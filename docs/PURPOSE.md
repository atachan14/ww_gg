# 目的と原則

## 何をするツールか

人狼ゲームの**配役・ルール・公開情報・全員で共有する戦略**から、各盤面(Board)での**陣営の期待勝率**を求めて確認するツール。

- 公開情報: 生死、CO(カミングアウト)、占い・霊能などの公開された結果。
- 共有する戦略: 「偽の役職者がCOしたら、真の役職者は対抗COする」「村陣営は役職を騙らない」のような、全員が従うと仮定する方針。盤面ごとに変えられる。
- 期待勝率: 各行動(吊り先・襲撃先など)を選んだ場合と、その盤面全体の、村と狼それぞれの勝率。

## 守る原則

ユーザーが確定した要件(`archive/20261029/requirements.md`)。

- **厳密な期待値を求める。** 確率の分岐をすべて評価した厳密な値でなければならない。乱数を使ったシミュレーション(モンテカルロ法)、信頼区間、探索の上限に達したときのシミュレーションへの切り替えは、代わりにならない。
- **使わないもの**: 乱数のシミュレーション、対戦データからの統計的な推定、発言や心理の分析。
- **厳密値と表示用の丸め値を分ける。** 内部は分数(Fraction)で持ち、%は表示だけ。設定で分数表示にもできる。
- **計算しきれなかった値を、計算済みのように見せない。** 上限に達したら「未計算(Pending)」と表示する。0% や途中の値で代用しない。分岐の打ち切りや近似で「完成」としない。
- **未決の仕様を実装側の推測で埋めない。** ゲームのルールや戦略の意味が決まっていないところは、ユーザーに確認する。
- **小さい例から確かめて広げる。** 素村・狼だけの3人 → 4人 → 5人 → 約9人 → 占い師などの能力、の順で、手計算と照らし合わせながら進めてきた。

## 計算の考え方(外から見た約束)

- 昼の吊り先、夜の襲撃先などの各候補は、**別々の行動の枝**として評価する。候補を等確率で混ぜて一つにしない(戦略で「ランダム」を選んだ場合を除く)。
- 戦略が「最大化(max)」なら、昼は村の勝率が最大の候補、夜は狼の勝率が最大の候補を選ぶと仮定する。同率の候補は全部保持する。
- 公開された情報から考えられる配役(役職の世界)を、すべて重み付きで保持する。実際の役職を一つに決めて計算しない。
- 処刑の直後・襲撃の直後に勝敗を判定する。狼が0人なら村の勝ち、生きている狼の数が村陣営以上なら狼の勝ち。
- 個人だけが知る情報(自分の占い結果など)と、全員が知る公開情報を混ぜない。個人の知識が、公開の戦略の選択に漏れないようにする。

具体的なルールと戦略の選択肢は [spec/game-model.md](spec/game-model.md)。

## 開発体制

AIが実装する。ユーザーは主に要件定義・動作確認・受け入れテストを担当する。
