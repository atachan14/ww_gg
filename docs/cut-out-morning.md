# 切り出し型：翌朝の正式な公開報告まで

`CutOutMorning` を独立追加した。正式Model Aの初期公開法則を継承し、処刑→初夜→Day2朝の現在実装済み公開報告まで進む。4〜5人・狼1・狩0・均等方針・固定CO・全公開の範囲。次の行動選択、完全勝率、max、狩人、7人、通常経路や公開設定には進めない。

## 死亡と結果の契約を再確認

既存 `acquire_uniform` と `true_reports` の契約、および既存死体占いテストに合わせた。

| 状況 | 保持する情報／新しい結果・公開 |
|---|---|
| 本人が取得前に処刑されている | 過去の取得・公開は保持。次の取得を生成せず、その新結果を要求しない |
| 本人が襲撃前に取得し、その襲撃で死亡 | 取得済みの新結果を秘密履歴に保持。朝に死亡しているため、その朝の新規公開はしない |
| 本人は生存、占い対象が死体 | 元のプレイヤー集合から既存の未訪問優先・均等規則で取得。生存CO者は取得済みの死体対象結果も公開する |
| 過去に既に公開した本人が後で死亡 | pastの既存prefixを消さない。今回の新規公開可否とは別 |
| 既に終局 | 朝の公開生成を呼ばない。終局後の新結果や報告を追加しない |

「襲撃された取得者の結果保持」は**秘密履歴の保持**であり、死亡者が新しく報告するという意味ではない。過去Boardへの訂正で既に公開済みの結果を扱う処理とも区別する。この試作から過去Board編集の新機能は追加しない。

## 使う正式な共通フロー

`InformationSetForecast.morning` → 既存の霊報告 `random_report_outcomes / report_flow` → 占いの `publications / future_publications / public_report_branches` をそのまま使用する。霊から占いへ進む既存順序を変更しない。COの追加や時機、未定義の同時報告規則を発明しない。

既存のfull-record検証設定 `retire_uninformative_scans=False` を使い、scalar用の取得履歴退役・既知騙り雑音省略を避ける。ゲームの開示ルールや報告方針の変更ではない。現在実装済みの均等／非矛盾候補の均等という偽報告規則のみ。未定義な複数騙り相関等がPendingなら理由付きUnsupportedにし、新しい独立コイン等で補わない。

生成には公開法則だけを渡す。さらに `push(source,source,branches)` で既存の観測重み移送を通し、同じ公開・物理measureなら確率と完全事後法則がそのまま一致することを確認する。本人の秘密条件を公開報告の生成へ渡さない。一般の本人Tableへの接続はまだない。

## 公開情報だけで切り出す

各公開枝で**実際に追加された**占い報告と霊報告の報告元・対象を固定する。色・取得日・公開日の値を持つ公開観測への支持条件は、この固定点部分群で保存される。既存の親群を保守的に切り出すだけで、交換監査・同型探索・再結合はしない。

同じ内容だから複数actorを新たな同時入力と読み替える処理は追加していない。入力の同時扱いは前段の明示初期snapshotに限り、生成された朝のベクトルは既存生成規則のまま保持する。群の保証には保守的な個別固定を使い、未公開のHypothesis内の取得対象・結果で群を分けない。

新stageは `after_morning_publication`。元のtracked、roster、observed_prefix、取得・狼自身の行動履歴、過去の報告prefixを保つ。新しく公開されたseer suffixのみ既存生成ベクトルと同じソート形式でラベル輸送し、元のpast順は変えない。逆順の初期報告を含む対照も通過した。

霊報告のラベル輸送は型が既知の最初のDay2ベクトルだけを追加対応し、報告機会・解決済み機会も同じラベルへ戻す。任意の未来報告schemaへ一般化しない。

## どこまで共通フローを往復したか

代表枝では、共通morningで記録された `PublicReportEvidence` を持つ `GeneratedBoard.roles()` から再構築し、公開Board・完全joint法則・past・同一observer measureが一致することを確認した。占い報告だけの例と、真/騙り霊報告を含む例を検証した。

この往復のoriginは、継承済みの完全な初夜子入力を持つ**KernelOrigin**。初期保存Gameから全処刑/夜/公開recipeを繋いだSavedOrigin経路の完成ではない。個人ラベルへ輸送した値は全対照で一致するが、その全枝を生成recipeへ登録する処理も未接続。輸送枝で新しいopaque originを作っただけなのにrecipe往復済みと数えないこともテストで明示している。本体の保存Board編集・取消・再計算やUIへの接続は残件。

## 独立小検証

再現：`python -B -m benchmarks.player_match_groups.cut_out_morning_fixture`。新規4テストと前段の4回帰テスト、計8件が各20秒上限で成功。新規約1秒、前段約0.9秒の小検証で、重bench・全suiteは行っていない。

参照は全個人ラベルの旧処刑/夜列挙から始め、霊の正式な全報告outcomeへ `project_private`、占いの `future_publications / public_report_branches` を独立に合成する。代表共有やラベル輸送を参照側へ使わず、枝質量、全Boardフィールド、完全秘密事後法則、past、役職率と群内交換妥当性を比較する。4人終局、単独真占、真/騙り占CO、逆順の初期past、真/騙り霊COを含め全個人ラベルで一致した。

P1真占・初日P3白の例では、P4処刑後、P1が襲撃されたら枠2の結果は保持するがpastへ新規追加しない。未公開の取得対象2/5が変わる秘密仮説を両方保持しながら、公開群 `{2,5}` は維持する。生存P1が死体P4白を新規公開する質量は、同じ死亡観測に条件付けて1/3。

| 小例 | 朝生成呼出 代表経路/全ラベル | 生成公開観測数 代表経路/全ラベル |
|---|---:|---:|
| 4人・同対象同白2CO（終局） |0 / 0|0 / 0|
| 5人・単独真占 |12 / 20|32 / 56|
| 5人・真/騙り占CO |11 / 18|78 / 126|
| 5人・真/騙り霊CO |15 / 18|76 / 90|

削減は前段の処刑/襲撃代表化の継承によるもので、朝の公開ベクトルそのものを勝手に間引いた結果ではない。各必要ベクトルは正式フローで全生成する。完全法則の列挙、公開生成、観測重み移送、群切り出し、ラベル輸送の費用は証拠に別記録し、総速度改善は主張しない。

証拠は `cut-out-morning-results.json` とローカルテストログ。通常経路・本体PlayerData・サーバー・既定OFF・公開設定は変更していない。
