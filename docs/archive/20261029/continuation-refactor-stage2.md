# 進行構造の整理・第2区切り（2026-10-13）

基準13d7f9a。ローカル限定。新能力・数値変更・公開モデルとAの統一は行わない。

## 共通の最小進行

action_flow.action_flowを旧公開占い評価のaction_valueとモデルAのactから呼ぶ。行動先は既に外側で選択済み。共通関数が次の順序を管理する。

1. 夜なら死亡前のBoardで能力を取得する（下記終局の差を維持）。
2. 方針が定義した対象行動の死亡/終局枝を受け取る。
3. 終局枝は勝敗値で停止し、公開報告を生成しない。
4. 継続枝の取得状態を死亡後の分布へ射影する。
5. 夜の継続なら朝の報告と後続評価へ進み、昼なら次評価へ直接進む。
6. 枝の確率で期待値を加算する。

死亡枝の列挙は配役に基づく純粋な分布計算であり、取得対象の名簿を変更しない。旧計算は終局枝しかない行動では取得生成を省く。モデルAは先に取得/閲覧者条件の成立を検証する。この既存の計算量・Pending契約差はacquire_terminalに明示し、勝敗値は同じ規則で返す。

## 方針として残したもの

| フック | 旧公開 PublicActionPolicy | モデルA InformationSetActionPolicy |
|---|---|---|
| acquire | 公開共同分布を取得、既存cache/trace | 公開と私的分布を別々に取得、閲覧者条件は私的側だけ |
| outcomes | 従来の指定行動action_outcomes | 私的物理枝＋整合性だけで更新した公開枝 |
| project | 従来の私的履歴周辺化 | 公開分布と私的重みを別々に射影 |
| morning_value | 従来霊能戦略、占い公開、従来solve | Aの霊能戦略、占い公開、私的枝重み、Aのsolve |
| day_value | 従来solve | Aのsolve |

昼max/random、狼仲間ごとの候補/max/random、同率均等化は外側の評価器が決める。共通flowには秘密を使って行動を選ぶ機能がない。霊能報告のmaxとrandomを無理に統合しない。

## 新能力の接続箇所が減った点と限界

以前は各評価器が夜判定、取得呼出し、終局判定、射影、朝/昼の分岐、確率加算を別々に実装していた。今はこれらの進行順序を一つのflowが所有する。例えば能力取得後・死亡前の共通処理を追加する場合、二つの再帰ループへ同じ処理を埋め込む必要がなくなった。専用テストは取得コールに状態を追加し、死亡後・朝の継続へ一度だけ渡ることを確認する。

ただし新しい役職の取得法・情報の所有者・行動選択・死亡/GJ・公開法は未定義であり、各分布方針への接続は必要。役職を登録すれば自動対応する構造が完成したとは扱わない。朝の霊能戦略と報告後の再帰はまだ各方針内にある。exact/reportsの圧縮経路、旧wolf_view_forecastの回帰基準も今回移行しない。

今回の能力取得は占いで、死亡の成立法には影響しない。旧計算の終局時の取得省略を保つため、死亡候補の純粋な列挙は取得前に行う場合がある。取得結果で死亡を防ぐ護衛などを追加する場合は、この列挙境界の契約を拡張する必要があり、現在のフックだけで対応済みとはしない。取得に使う名簿と、死亡後に公開できる生存者の名簿は分離済み。
