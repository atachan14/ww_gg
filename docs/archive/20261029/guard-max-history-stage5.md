# 公開の履歴分布と履歴条件付き最大化・段階5

今回の backend は、占い・霊能なし、自己襲撃不可、対称な5人以下の盤面と、
対応する最初の無死亡履歴からの最大化を扱う。初期狼2人で死んだ仲間がいる
場合も、所有者は初期狼全員の組合せのまま。狩人1人、自己護衛なし、
連続護衛あり、護衛均等化、個別成功通知なしを維持する。

`guard_history_prior` は公開の役職世界ごとに、無死亡と両立する秘密襲撃・
護衛履歴の候補を持つ。最初の4人生存の夜は、公開の役職分布の対称性により
各狼陣営の合法な3対象が最大化の同率になる。実際の方針はその同率を均等化
するので、役職世界ごとの無死亡履歴は真の市民2人への各1/2となる。
これは新しい襲撃戦略を仮定した均等分布ではなく、最大化の同率処理から
導かれる分布。各世界内で履歴を正規化し、model A の公開役職事前を保つ。

狼方針のキーは公開状態・初期狼全員・自分の実際の襲撃履歴。公開の候補分布
をその情報集合で条件付けて、未知の狩人位置を平均してから最大化する。
閲覧者の狩人や狼の実際の履歴は、公開の候補分布を作る入力にしない。
公開側が1本の実際の秘密履歴を知ることはなく、村の同率処理も変わらない。
最大化では私的履歴をキャッシュキーから消さず、過去の均等化向けの省略を
流用しない。次に終局の公開処刑しか残らない場合だけ、公開側の履歴を周辺化
する。本人のレコードは維持する。

過去の最大化が同率だったと現在の対称性だけから推測しない。
最初の無死亡を再生する際に、当時の公開分布と方針を確認して
`guard_prior_roster` に夜番号と当時の公開生存者だけを記録する。実際の襲撃先
は記録しない。この由来がない場合は、現在の役職分布が対称でも履歴分布を
作らない。最初の襲撃が均等化だった場合にも同じ履歴則が成立する。

非対称な最初の最適襲撃、より大きい履歴木、占い・霊能との混合、自己襲撃を
許す場合の非終局履歴はまだ未対応。公開 role 事前を維持したまま正の履歴を
割り当てられない世界にも適当な履歴を補完しない。対応部分では新たなルール・
戦略意味の決定は不要だが、一般の最適方針による履歴則は完成済みとは扱わない。
UI に説明項目や操作を追加していない。

手計算の回帰例:

- 狼1・狩人1・市民3の5人昼: 村最終勝率 `11/24`。
- 最初の無死亡後の4人昼: `13/48`。処刑で狼が1/4、過去の秘密襲撃先で
  あった市民が1/4。後者の次の3人夜だけは狩人がまだ不明で、村勝率1/12。
  他の非狼を処刑した場合は狼が狩人候補を狙って勝つ。`1/4+1/4×1/12=13/48`。
- その次の3人夜: 公開の平均は `1/36`。狼本人1は、過去の襲撃先2なら今夜3、
  過去3なら今夜2を選ぶ。過去の襲撃先4が昼に死亡していれば2・3は各1/2の同率。
- 最初の4人夜は、失敗5/6で次の公開処刑に勝つ1/3、成功1/6で13/48。
  よって31/96。初日の処刑を合わせ `1/5+4/5×31/96=11/24`。
- 初期狼2・狩人1・市民2の5人昼: 狼を処刑した2/5の継続では狩人が必ず生存。
  4人夜の成功2/9、失敗7/9なので `2/5×(2/9×13/48+7/9×1/3)=23/180`。
