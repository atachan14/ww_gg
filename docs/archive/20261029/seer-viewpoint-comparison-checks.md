# 占い視点の占い先比較・最小対応（2026-10-13）

基準: `060736f00026df89f3cf9ed7491f37aea01f902e`。ローカル作業コピーでのみ実装する。

これは `b12df1d` 時点の最小対応記録。生存狼1匹の制限を外した後続実装は [seer-multiple-wolves-checks.md](seer-multiple-wolves-checks.md) を参照する。

## 対応範囲

占いCO済み、結果開示「すべて」、公開側で生存狼1匹と確定、既存の公開取得履歴が揃うBoardの夜で、本人の次の占い先別の最終村／狼勝率を表示する。配役の初期狼数が2でも、公開側の残存狼数が1に確定していればこの条件を満たす。

現行の「未訪問先優先・均等」生成則の候補を比較する。既訪問先は、未訪問先が残る間は比較対象から除く。本人・死亡済み対象も除く。すべて訪問済みなら現行エンジンと同じ合法候補へのフォールバックを使う。対象を確定して実進行する機能には接続しない。

公開履歴と秘密履歴は別ストアのまま。公開結果は秘密欄作成の初回だけコピーし、その後の秘密編集で公開CO・ログ・Cookieを変更しない。秘密の完全な過去結果は真の取得記録として条件付ける。空欄／部分入力を白結果で補完しない。公開されている本人の真の取得記録と、同じ取得日の秘密記録が食い違う場合は不整合とする。結果騙りは対応範囲に含まない。

## 情報分離

公開joint priorを `seer_future_bridge.prepare_game` で作り、既存の取得／真・偽報告生成を使う。次の取得スロットは夜NからDay N+1であり、公開日とは別に保持する。

選択した本人・秘密結果・今回の占い先は視点側の枝重みにだけ適用する。公開側では本人の今回の占い先を含むすべての生成候補を保持し、公開行動の評価には私的Boardを渡さない。実際に結果が公開された枝で、その公開結果を受け取った後の公開判断を行う。同値の最適候補は均等に扱う。

今回の強制占い先は、本人の過去取得履歴が一意で、現行uniform生成の候補集合が本人に整合する仮説間で共通の場合だけ扱う。生成確率が共通の定数なので、その占い先の取得枝を条件付けて正規化しても配役priorに選択尤度を追加しない。本人が同夜に死亡しても、取得自体は死亡前に行うため視点の取得記録は保持する。死亡後にその記録を公開することはない。

継続計算の公開方針は狼比較と共用し、公開の同値候補を均等に集計する。seer用の枝条件付けでは、死亡した本人の記録も残して取得条件を失わない。

## 数値例

単体テストの全条件: 市民3・占い1・狼1の5人、初日占いなし。公開候補では占い師はPlayer1、狼はPlayer2（1/2）、Player3（1/4）、Player4（1/4）。Player5は市民でD1昼に処刑済み。Player1は占いCO、他は潜伏、公開過去結果・秘密過去結果なし。昼max、夜random、占い結果はすべて公開、自噛みなし。

| 次の占い先 | 最終村勝率 | 最終狼勝率 |
|---|---:|---:|
| Player2 | 3/4（75%） | 1/4（25%） |
| Player3 | 19/24（79.17%） | 5/24（20.83%） |
| Player4 | 19/24（79.17%） | 5/24（20.83%） |

生き残って公開した結果が翌昼の判断を変える。夜の襲撃で本人が死亡した場合の枝、占い対象が同夜に死亡して結果が追加情報にならない枝も計算している。値は仮の同一値ではなく、生成と公開判断を追った集計結果である。

## 未対応

- 「なし」: 未公開結果を本人の後続行動へ使う情報集合モデルは未対応。最終欄を理由付き未対応とし、公開計算や同じ仮値で代用しない。
- 潜伏本人: 固定COモデルでは将来の本人COと秘密の利用が定まらないため未対応。
- 複数の生存狼、公開狼数不確定: 指定襲撃のcount別正規化と観測者条件付けの組合せを追加検証する必要があるため、今回の最小範囲から除く。
- 過去の私的取得履歴が公開priorに含まれない／一意でない場合、複数偽占いの共同報告、生成候補の不足、予算超過: 未計算を返す。
- 占い先別の「次の朝まで」指標、狩人の護衛能力は未対応。護衛を含めない旨を配役に狩人がいる場合に表示する。
