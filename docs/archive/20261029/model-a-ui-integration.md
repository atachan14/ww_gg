# 公開画面のモデルA接続

`render_main`のOverview、対象固定Table、今日中、累積継続値は`evaluate_public_game`を使う。通常GET、公開編集プレビュー、戦略更新、夜画面の再描画も同じ経路。公開Boardと役職確率は元の分布から表示する。私的視点は別の条件付き分布でTableを比較し、Overviewは公開情報のまま。公開policy/cacheに閲覧者の秘密を渡さない。

開発用の占いfutureフラグで旧計算へ切り替える経路を除いた。主画面の能力戦略の利用可否・表示ラベルも現在のStrategyに合わせる。既存の公開結果入力、取得日/公開日、夜の未確定死体フラグ、戻る、公開cookieはこの接続で変更しない。初日占いあり・生存占いCOの初日公開結果未入力は、能力を省略した数値を出さずPendingとなる。

数値変更例：5人狼1から市民を処刑し、4人の夜で自噛み可能かつ最適襲撃の場合、Overviewの村勝率は旧1/2から1/3へ変更。狼は仲間を知り、村勝率が小さい非狼対象を選ぶ。対象固定行は公開事前分布に対する介入なので1/2、今日中村勝率は1/4。累積は処刑時の確定村勝率1/5と継続確率4/5により7/15。固定行を平均して夜Overviewにする意味ではない。

回帰：Windows全419テスト成功、107.846秒。追加UIテスト1件成功、0.194秒（全体実行開始後に追加）。DOM3種類成功。実Edge3種類成功：秘密再計算・独立編集・公開不変・古い応答排除・繰返し選択・戻る・死亡済み狼・占い分布の5/6/0/1/1/2/1/3を確認。主画面が旧build_treeを使わない検査も含む。

性能限界：7人・狼2/霊媒2/占い1・占いCO1人/霊媒CO2人の将来全公開は既定250000workでPendingになる。能力を考慮しなかった旧ローカル経路より対応範囲が狭まるケースとして記録する。潜伏役の圧縮は生存占いCO/allには安全性のため適用しない。この混合ケースの最適化は残り課題。隠れた旧モデルへのフォールバックなし。

呼出監査：主画面と私的視点はA。独立した初期配役比較の`comparison.compare_initial`、旧結果の移行fixture、参照用旧占い・狼評価器には旧計算が残る。観測priorの再構築は旧評価器ではなく共通の取得履歴を利用する。これらの参照・独立ツールを整理し終えるまで旧ソルバー全削除は行わない。能力追加時の情報所有者・取得時点・死亡への影響・キャッシュ条件は`information-ownership-cache-and-extension.md`参照。
