# 役職率先行配信：ローカル実装・検証

状態: 未公開。HELP履歴追加b90b34bとは独立した開発単位。

## 配信と計算

通常のブラウザ盤面遷移は、役職再構築を行わない軽いHTMLを返す。そこから1回のGET /main（Accept: application/x-ndjson）で、同じRoleStateを保持してroles→completeを返す。JavaScriptなしではcomplete=1の一括表示へ進める。一括APIの既存利用も維持する。

COプレビュー、戦略更新後の盤面取得、本人表も段階受信する。新しいバックグラウンドジョブ、外部保存、認証変更はない。公開の同一入力を役職用と勝率用の別要求で再構築しない。夜明けの観測準備も段階間で共有する。プレビューでは入力の合法性検査に必要な旧盤面と、変更後の盤面は異なる入力として再構築する。

本人準備は自身の役職・取得結果・自身の行動履歴で共同分布を条件付けた状態を保持し、役職率と後続評価が共用する。公開配役重みと物理分布、他者が政策選択に使う情報を変更しない。後続勝率がPendingでも、完成した本人役職率を失わない。秘密支持ゼロや共同準備未完で役職率を確定できない場合は、先行段階に数値を出さない。

## 期限・最新入力・保存

ストリームのiterator自身が従来と同じ270秒/400万workの親予算とプロセス内1計算枠を所有する。queue待機も期限に含め、終了・失敗・切断で解放する。送信開始後はHTTPステータスを変更できないため、後続の失敗はerrorイベントで通知する。途中EOFも失敗として扱う。

ブラウザは最初のヘッダーでストリームを読めるが、通信制御の実行枠は本文の終了まで保持する。Abortは表示を無効化するだけで、サーバー即時取消とは扱わない。COプレビューのrequest_id/Board/revision/下書き世代、本人表の選択世代、初期盤面の入力変更を各段階で確認し、古い応答を採用しない。保存要求のFIFO、最新下書きを待つ保存、入力保持を維持する。

## 検証

- 公開rolesはforecastを呼ぶ前に送信され、同一入力のRoleState再構築は1回。最終HTMLは一括応答と完全一致。
- 本人役職率・全勝率は従来応答と一致。秘密履歴付きで後続Pendingを強制しても、役職率は先行/最終で一致。
- 初期HTMLは役職計算なし。途中切断/後続失敗で排他を解放し、セッションを保持。
- headless Edgeで初期roles後の応答を保留し、CO変更後に届いた旧completeを除外。最新COプレビューの役職率は反映し、後続通信故障でも下書きと役職率を保持。
- 本人表もroles後の通信故障で本人役職率を保持し、公開勝率・公開役職率を汚染しない。
- 既存の連続編集・待機中の保存・中間要求の破棄・失敗した戦略の保存防止を再検証。

最終の関連13モジュール・105テストは19.712秒で成功。段階配信の専用テスト10件を含む。最終headless Edgeで段階配信と従来連続編集の2スクリプトが成功し、JavaScript例外はなし。全テストスイートの再実行ではない。
