# Wolf-information-group checkpoint refinement

This is a new, separately authorized finite window after 233cc35. It does not reset the old consumed meter, rerun the old 300/600-second calculations, or enable seven-player runtime grouping.

## Same computation, smaller saved unit

The numerical engine and checkpoint_audit.py worker source remain frozen at e8b8d42. primitive_checkpoint.py keeps that core content hash and records a separate selection-adapter hash. It calls the original base.worker unchanged. Its only numerical-loop adaptation is to return one original term from night_plan instead of the full term list, retaining the exact original private information group object, public/physical carriers, history, fixed bite and coefficient. The original worker's e.act call therefore runs unchanged.

Each primitive is the full conditional expectation for one existing wolf-information group. It is not one arbitrarily selected hidden world, and it is not a per-world maximum. Configured day/night/fake-medium strategies must remain random; max is still explicitly rejected. The original weights physical_mass * information_mass * policy_probability are preserved and never renormalized. Aggregation adds all exact primitive contributions and existing terminal contributions; an incomplete root keeps value=None, and an incomplete whole case keeps global value/Table=None.

## Importing confirmed results

For seven players the original input and evidence are read from committed 233cc35 snapshots. The core hash and original input hash must match. Every old complete-unit checksum is reconstructed against the newly rebuilt complete joint/conditioning/physical plan; every imported primitive signature and coefficient must match that plan. The three partial audit values are accepted only from the committed explicitly verified prefix and must equal their confirmed oracle counterparts. No generic incomplete value is promoted to complete.

Imported original seven-player work: 14 complete unit pairs, 86 complete oracle primitives, 83 complete audited primitives (including the three verified prefix values). The new namespace has its own adapter hash and a new 600-second cumulative meter. Old complete values are imported with their producer checksum/provenance, not relabelled as freshly computed results. A missing local original-input snapshot can be restored from the committed snapshot; an existing mismatched input is rejected, not overwritten.

## Small-case acceptance

5/1 reassembles 24 original information-group primitives per mode; 6/2 reassembles 120. Both oracle/audited complete Tables and final values (7/15, 1/12) exactly match the existing unpartitioned actual-input references. One original nonzero group per case was also freshly computed in each mode and compared with its original loop result; other confirmed work was reused. The checks completed in approximately 1.06s and 1.12s, without repeating the old full validation. Seven tests passed in 0.567s, covering whole-group identity/weight preservation, changed-signature rejection, committed-input/value restoration, max rejection, incomplete values, memory cancellation and stale-code rejection.

## New seven-player window

There are 240 original information-group primitives per mode. Only missing mode/group values will run. Each worker retains the existing 120-second/four-million-work and 1.5GB high-water cancellation limits, plus the parent watchdog. The new cumulative window is at most 600 seconds including planning/validation/aggregation. No failed/pending primitive is automatically retried and no limit is automatically extended. A completed full seven-player win/Table will be claimed only if every required primitive and both aggregates are complete and equal. Runtime remains default OFF with >6 dual-CO fallback throughout an incomplete audit.

## New window stopped; no repeated extension

The new window stopped at 600.063 seconds including final watchdog/record work. Each completed worker was below 120 seconds (largest measured chunk wall time 40.194s); the last pending primitive used only the remaining 1.865s before the global deadline. Worker peak was 203,571,200 bytes, below the 1.5GB cap. No memory threshold was hit, no automatic retry/extension followed, and no calculation process remained after the trial.

Twenty-four new exact values completed: 12 ungrouped oracle expectations and 12 matching-plus-independent-audit expectations. All 12 pairs matched. Including imports, 98/240 oracle values and 95/240 audited values are complete, so 95 original information-group expectations are independently checked (up from 83). Old 14 complete coarse unit pairs and the three verified prefix values were reused without recalculation. The coarse unit-pair count is still 14/42 and complete root interventions remain P1/P2 at 3/10 each. The global seven-player win and full Table remain None/pending; no complete seven-player equivalence is claimed.

The scheduler follows the original information-group order, not coarse-unit order. New values therefore advanced partial groups across several bite units rather than completing the old (3,4) coarse unit first. At the ceiling the pending item was (root=3,bite=4,index=3,audit); its oracle value had already been imported, but its new audit did not complete. It was not filled from the known oracle or by a guessed value.

This is limited progress toward a full Table; repeating the same 600-second extension is not the next automatic action. The established result is an exact, bounded, reusable expectation decomposition. A further performance step needs a distinct examination of common-flow branch generation/sharing and audit duplication, while preserving support, physical mass, actor information and configured policies. No such numerical shortcut, model or specification change was implemented in this task.
