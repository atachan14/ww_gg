# 物理分岐・情報集合の段階的整理

開始基準: HELP実装 `83de806`、構造監査 `97d0ed4`、計算実装 `eb8116d`。
ユーザー承認に基づく構造整理。model Aの公開更新、情報集合内の政策、未知の途中履歴の扱いは維持する。

## 第一段階: 物理Boardの明示的な継承

共通フローの位置引数payloadを `ActionInputs` / `ContinuationInputs` として名前付けした。
元のタプル入力を受ける共通処理との互換性は残し、公開状態と物理Boardを明示して運ぶ。
`InformationSetActionPolicy.project` は `outcome.board` を継続データへ保存し、
昼・朝の評価はそのBoardを `solve(..., physical=...)` へ渡す。

`physical_board` は入口でだけ公開Boardを土台に初期化できる。継続に物理Boardがあれば
その枝を土台にし、役職質量は本人の分岐測度から更新する。生存者・日・昼夜・死亡履歴が
公開観測と食い違う場合はエラーとし、公開盤面で置き換えて辻褄を合わせない。
公開されたCO・報告等の事実は枝へ反映する。既存のsolver用役職縮約はこの段階では維持。
狩人登録範囲は既存どおりその縮約を迂回する。

GJの物理成功Boardも、公開信念を土台にせず、入力された物理Boardと生成した本人記録から作る。
既存キャッシュは公開事実と本人の仮説測度をキーに持つ。新しい物理入力も同じ公開事実点で
あることを検証するため、この段階で別の不可視事実を同じキーへ紛れ込ませない。

検証: 公開の狩人候補が残るGJと物理成功世界を分離、複数夜の両本人記録、
次solverへの物理Boardの同一オブジェクト受渡し、キャッシュ有無の一致、
事実が食い違う入力の拒否。既存の候補採点はmodel Aの公開側から始める経路を維持している。
公開候補採点をすべて根からの物理分岐へ置き換えたという主張ではない。

## 続く段階

1. 狼の初期仲間と本人記録から情報集合を抽出し、集約・条件付けの重複を共通化する。
2. 最終評価と当日終了評価、各視点が同じ共通フローを使い、生成記録を捨てないようにする。
3. 役職縮約・キャッシュと、評価のための主観的な候補分岐／実際の継続を整理する。

途中Boardだけから未知の他者履歴を配分する新しい基準モデルは実装しない。
根から持つ物理情報と、公開方針の採点に使う主観分布を混同しない。

## 第二段階: 情報集合と枝の集約を共通化

`WolfInformation` は初期仲間マスクと本人の襲撃履歴を抽出する。真の他役職・護衛先・
秘密占い結果はキーに入れない。政策の入力は必ず公開Boardの役職事前分布と整合することを
検査し、観測者が条件付けした役職分布で公開の政策源を置き換える呼出しを拒否する。
同じ情報集合は実際の質量を足して一つの条件付き法へ集約し、その後一つの政策を適用する。

これを最終評価、当日終了値、狩人視点で共有する。公開側に保存された履歴が本人の既知履歴の
prefixにとどまる場合も、政策の候補評価用仮説に本人の完全な記録をマージして維持する。
確率を新たに配分する処理ではない。共有想定のStrategyは一つで、秘密戦略の階層は追加しない。

当日終了値も共通 `InformationSetActionPolicy.project` を通し、実際のoutcome Boardと取得済み
payloadから次段階を作る。公開childを土台に本人の物理Boardを作り直す重複を取り除いた。

「想定外」のUI相談はまだ実装しない。役職・観測条件の全候補ゼロ、本人条件だけの矛盾、
政策の全物理支持ゼロ、世界の一部の履歴混合不能、未対応・不明履歴・予算超過を区別する必要がある。
一部の混合不能だけで盤面全体を想定外と判定しない。

## 共有想定と視点の整理

ユーザー了承の整理方針は、配役・秘密情報・必要履歴の共同分布に、公開観測または公開観測と本人情報を条件付ける同じ計算構造である。
本人視点は本人情報を持つ場合の条件付き勝率であり、公開勝率の精度改善という意味ではない。
開始時分布・共有するStrategy・履歴生成なしには、公開観測だけで秘密履歴混合は一意に定まらない。
model Aの公開役職重み、世界内の想定秘密履歴混合、実際に生成された物理分岐質量は区別し、最適政策の選択尤度を公開重みに掛けない。
現在はHypothesisの秘密記録保持、物理Board継承、狼情報集合の抽出と共通集約まで実装済。
全役職の一般共同分布生成・任意途中盤面の秘密履歴復元・生履歴の十分な要約への圧縮は未対応。
連続護衛なしの前夜護衛と未公開占い結果など、合法手や情報集合に影響する事実は保持する。

## 第三段階: 本人条件付けの共通処理

`condition_actor_state` が既存共同分布を観測述語で絞り、明示された本人の護衛・襲撃記録をマージする。
狼政策、本人評価入口（既存占い師観測も通る）、狩人視点、狼視点の途中評価を接続。
公開sourceを変更せず、役職・未公開占い結果・他者記録・状態メタデータを保持する。
観測条件の意味と各役職の対応範囲は変更しない。霊能者/村人の条件にも共通処理を使えることを検証するが、新たな秘密行動モデルは追加しない。

保留例: 前夜に2を護衛した狩人と3を護衛した狩人は、連続護衛なしなら次の合法手が異なる。
同じ公開COでも、未公開の黒結果を持つ占い師と白結果だけを持つ占い師は本人の情報集合が異なる。
これらを同じ履歴要約へ潰すことはしない。途中盤面からそれぞれの秘密履歴の確率を新しく配分する処理も保留。

第3段階検証: 関連44テスト成功、修正後の全500テスト成功（137.653秒）。
