# GameRules：連続護衛なし

Base: 1bbbda8。デフォルト allow_repeat_guard=True を維持。False は単独狩人・処刑/襲撃の均等共同履歴フローに対応。max/相互max/複数狩人は今回の範囲外。

- 共通 guard_targets は同じ狩人の実際の前夜対象だけを次夜候補から除く。初夜は制約なし、前夜対象が死亡済みなら現在候補に元々存在しない。合法候補上の均等方針は変更しない。
- guard_choices は仮説の guards を受け取る。公開法と本人法を別々に生成・条件付けし、護衛成功/失敗、GJ、死亡後も過去記録を保持。
- 公開死亡観測は世界内の履歴で護衛失敗確率を平均する。GJは可能な世界の公開Qを保持し、世界内の護衛/襲撃履歴混合を共通能力フローから条件付ける。物理Pや襲撃方針の尤度を公開配役重みへ掛けない。
- 公開再生は既存 root replay から夜事前分布を収集し、既存 seer_manual/dawn へ渡す。公開serializerによるcacheに本人データは含めない。Progress.guard_state は公開専用の実行時carrierでありCookieへ保存しない。
- 本人Tableは同じ共同分布に本人の役職・既知護衛を条件付ける。前夜が未知で候補支持が一致しないときはPending。禁止候補はlegal/finalから除く。昼から次夜の固定介入、介入前死亡の扱いは従来共通フローを継承。
- 狩人死亡は既存の能力なし処理。現行非終局では生存3人以上なので、自護衛と前夜対象を除いても1候補以上残る。終局は能力評価前に停止。異常な非終局で0候補なら明示Pendingとし、新しいpass選択を作らない。
- UIはルールパネル＞村陣営＞狩人のあり/なしselectのみ有効化。詳細はHELP。既定maxはそのままPendingのBoardを開き、ユーザーがBoard戦略で各相を均等に変更できる。未対応のmax/自噛み除外の進行は拒否しGameを保持。複数狩人は新ルールの開始時に拒否。maxを均等化へ自動置換しない。
