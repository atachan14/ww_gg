# 護衛位置「均等化」の公開画面・評価接続

## 承認範囲と対応範囲

狩人1人、自己護衛なし、連続護衛あり、護衛成功通知なし。
連続護衛は Game の `Rules.allow_repeat_guard`、位置選択は Strategy の
順序付き `guard_position=('uniform',)` として管理する。UI も占い位置と
同じ Item エディターを使う。未実装の期待勝率最大化は無効な候補として
表示し、保存・計算には入れない。連続護衛なしは合法手制約の拡張点を
残しているが、現在は明示的に未対応として拒否する。

**今回の最終勝率・翌朝勝率・無死亡進行の対応範囲は、狩人の位置が
公開情報で確定している Board。** CO そのものを真と決めつけず、公開
役職分布で1人の生存者の狩人確率が1であることを確認する。狩人が
死亡した後の夜には護衛を発生させない。狩人が生存している役職世界
から、位置を省略する最適化や占い履歴退役経由の役職省略を停止した。

狩人の位置が公開情報で未確定の場合、村・狼・本人それぞれが持つ
無死亡後の情報が異なる。狼は自分の襲撃先を知るため、全体の役職分布
だけで次の狼方針を選ぶと情報を失う。逆にその襲撃先を公開 Board に
付けると村へ漏れる。その情報集合・私的襲撃履歴をまだ実装していない
ため `guard_hidden_attack_history_unimplemented` とする。初夜の前でも
未来にその分岐が発生するので最終勝率は表示しない。複数狩人は別の
未対応理由、計算予算超過や未確定の複数偽占い共同則も従来どおり区別する。
未対応の最終勝率を能力なし狩人の数値で代用しない。未対応理由だけで
実行可能な昼の処刑操作を無効にすることもない。

## 夜処理と情報の分離

`action_flow.resolve_action` の選択済み襲撃・生存中の能力取得・死亡解決
の順序を使う。護衛位置の候補は自分以外の全生存者で、役職を見て除外
しない。確定済みの襲撃先を見て護衛先を選ぶこともない。各候補を等確率
で周辺化し、stage1 と共通の一致判定で狼襲撃の死亡だけを防ぐ。
死亡による終局の事前判定は行わず、護衛後の結果から判定する。

護衛に成功した物理分岐は襲撃先を条件とした役職分布を保つ。一方、
その無死亡後の公開 Board は襲撃先や護衛先を持たない。昼の処刑方針は
公開の分布で、狼の方針は公開の分布を初期狼全員の組合せで条件付けて
選ぶ。閲覧者の秘密履歴や今回比較する固定護衛先をそのランキングへ
渡さない。同率の方針は既存どおり均等に扱う。

現在の公開観測更新は既存 Model A の「行動選択の尤度を掛けず、
ルールとの両立で絞る」方式を保つ。公開確定の狩人では、死体が狩人なら
護衛失敗確率1、その他なら一定の護衛失敗確率なので、同じ死体と
両立する世界内の公開事前比は変わらない。無死亡には私的な襲撃先を
入力せず、役職事前比を維持する。狼方針の選択尤度によるシグナリング
を追加した Bayes モデルには変更していない。この仮定を保つためにも、
狩人未確定の分岐を適当な公開観測則で埋めない。

狩人視点の Table は各行を「今夜その相手を護衛した場合」として比較する。
後続の夜の護衛は設定済みの均等化。本人の秘密欄は完了した過去の夜の
護衛先のみで、白黒結果・成功通知は作らない。夜番号と元の夜の生存者を
使うため、その後死亡した相手も当時生存していれば入力できる。空欄を
護衛先に補完しない。自分・当時不在の相手・護衛した相手の襲撃死などは
不整合。無死亡と本人の護衛先が揃うと、自己襲撃不可ルールではその相手が
狼でないことを本人の分布だけに反映する。

秘密欄は既存の Board ID・本人・役職で分離した sessionStorage に保存し、
視点往復・再読込で維持する。公開 CO 欄・Cookie・BoardLog・公開フォーム
へは追加しない。将来生成される護衛履歴は、現在の連続護衛あり・均等化
では次の選択に影響せず、公開確定の狩人なら狼に新たな隠れ役職情報も
生じないので周辺化する。連続護衛なしや優先条件を追加するときは、この
前提を外して将来の本人履歴を状態に保持する必要がある。

公開の無死亡は `deaths=[]`、欠測は `None` のまま区別する。進行履歴には
`target=None, deaths=[], observation='night-deaths-v1'` を保存し、死体イベント
を捏造せず翌昼へ進む。再読込・公開ログの所有 Board・戻る操作がこの
履歴を再現する。旧単一死体の履歴も維持する。

## 再現可能な確認例

`tests/test_guard_forecast.py` は手計算の独立した小例を含む。

- 3人夜、Player1 が公開確定の狩人、狼は2か3で各1/2。襲撃均等化では
  狩人への襲撃が1/2、他の村人への襲撃が1/2、その護衛成功が1/2。
  翌昼の公開処刑で狼を引く確率1/2なので村最終勝率は **1/8**。
  狩人襲撃の行は0、他の襲撃の行は1/4。
- 同じ Board で襲撃が期待狼勝率最大化なら、狩人への襲撃で勝てるため
  村最終勝率0。狩人視点でどの護衛先を比較しても、この公開由来の
  狼方針を秘密の固定護衛先で変えない。
- 4人昼、同じ公開確定狩人と狼1人、襲撃均等化。非狩人の処刑なら
  1/3で即勝利、2/3で上の夜になるので村最終勝率 **5/12**。

実画面は `http://127.0.0.1:8772`。起動は
`.venv\Scripts\python.exe app.py --port 8772 --dawn-board --hybrid-table-preview`。
既存8771には触れない。

画面確認手順は市民3・狩人1・狼1、昼最大化・夜均等化で開始し、初日昼に
Player1 の狩人 CO を公開、Player5 を処刑する。初日夜の狩人視点で各行の
護衛比較を確認し、全体へ戻って死体なしを報告して進む。翌昼に Player4
を処刑した次の夜、秘密欄にD1夜の護衛先2を入れると本人だけは2が非狼と
分かる。4は現在死亡していてもD1夜の候補に残る。全体へ戻れば元の公開
確率・勝率に戻る。この手順を `tests/dom/guard_browser.cjs` が実 Edge で
再現し、遅延応答の排除、繰返し選択、再読込、戻る、公開状態不変も確認する。

Python検証は `python -m unittest discover -s tests`。
このPCでは `TEMP` と `TMP` を task の `test-temp` に設定する。
ブラウザ検証は playwright と Edge を用いて
`node tests/dom/guard_browser.cjs`。既存の private/seer/wolf ブラウザテスト、
strategy_items/private_row/private_draft/viewpoint_modes の DOM テストも使う。

ローカルのみ。README・画像を変更せず、push・公開デプロイは行わない。
