## 最小段階の案

まず一人の確定狩人・確定配役・初回の単一夜を、襲撃先と非自護衛先を外から固定して検証する。過去護衛・複数狩・自護衛はこの段階の対象外で、禁止ルールとして確定する意味ではない。自然な護衛/襲撃方策や勝率UIは追加しない。「護衛一致で単一の襲撃死を取り消す」は承認が必要な効果案であり、今回は実装しない。

| 入力 | 内容/所有者 |
|---|---|
| role world | 実在する一つの完全配役、exact mass=1。サンプリングしない |
| predeath roster | 共通夜処理が供給する生存者。取得後死亡とは別 |
| chosen attack | 既存の選択済み襲撃先。護衛選択generatorへ渡さない |
| private guard intent | night/actor/target。占いcolor/resultとは別の秘密記録 |
| approved effect resolver | 将来の承認済みルールを外から供給。未指定なら未対応 |

| 出力 | 内容 |
|---|---|
| physical result | 死亡IDのtuple、同じrosterを保持する空tupleも表せる |
| public observation | 死亡のみ。護衛者・護衛先・死体なし時の実際の襲撃先を入れない |
| private ledgers | 狩本人の護衛記録と狼側の襲撃記録を別々に保持 |
| unresolved contract | 未承認ルールをFalse/0や死体なしへ補完しない |

型/入出力の上記整理はルールに依存しない準備。実Boardへの空夜進行は、現行`dawn.py`が未対応としているので有効にしない。

## テスト骨格

効果resolverをテストダブルとして注入し、取得前/後payload、選択済み襲撃先、公開出力の秘密非含有を検証する。護衛そのものの成功規則はテストダブルで決めた契約にすぎず、既定ルールにしない。

| ケース | 検証点 |
|---|---|
| 与えた死亡なし結果 | rosterを削らず、夜後の時点へ渡す。公開情報に護衛先なし |
| 与えた単一死亡結果 | 一人だけ削る。取得済み秘密記録を公開ログへ流さない |
| 狩本人が死亡する結果 | 死亡前取得は残る。公開は生存者条件に従う |
| 未承認の自護衛/履歴制限 | 未対応のまま、勝率0を作らない |
| viewerを変更 | 公開攻撃方針は同じ、私的payoffだけを別にする |

これらは次段階の骨格で、今回新しいスキップテストや護衛ルールの実装は追加しない。

## 最小段階で新たに判断が必要なこと

1. 「一人・初回夜・非自護衛・過去履歴なし」の確定世界から始め、一致した単一襲撃を取り消す効果案を採るか。
2. 死体なしを実際のBoard進行へ載せる段階で、公開観測の更新・累積値への反映・本人/狼が知る成功情報をどう扱うか。

自己/連続/複数狩や自然な護衛方策は、最小段階では対象外なので今すべて決める必要はない。ただしUI能力先比較へ進む前には、合法対象と公開/本人方策を決める。GJ後は狼が自分の失敗襲撃先を知るため、将来の狼情報集合は初期仲間maskだけでは足りない。護衛先をpublic policyへ渡す代用をしない。

護衛を有効にする際は`evaluation_projection`（能力なし狩人位置の圧縮）、`joint_value_key`、`exchangeable_value`、terminal preflight条件を再審査する。共通夜/朝flowを再利用し、狩人用の別勝率solverを作らない。
