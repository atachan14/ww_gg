# ④ 同時行動・相互最大化の設計確定

状態: 設計完了。実装⑥は未着手・未対応のまま。本書は既存の均等規則とPendingを維持する契約であり、新しい均衡選択、相関乱択、off-path信念、CO/報告戦略を導入しない。既存 expected-win-policy-common-design.md の節6・9にある設計候補は、本書の確定範囲と将来拡張を区別して読む。

## 1. 入力と情報境界

同時段階の入力を次に分ける。

- 入力事実: 公開Board、GameRules、既存の公開報告、完全共同秘密履歴。
- 観測: 各主体がその段階開始までに知る公開事実と本人秘密。本人秘密は既存ルールで認める役職・取得結果・自身の行動履歴。狼陣営の共有roster/既存共有情報は一つの主体の情報として扱い、狼人数分の独立主体にはしない。
- 合法手: ルールと本人情報から既存フローで生成する。観測条件と設定済みの方針を混ぜない。
- 方針: 設定済みの固定方針、均等方針、または相互最大化を要求する方針。未設定のCO・報告・護衛・占い戦略を生成しない。
- 物理遷移: 同時intentとchance結果から、能力効果、死亡、勝敗、取得履歴を既存の共有フローで解決する。

共有想定は全体/本人で同じで、観測条件だけが異なる。行動選択用の条件付き分布は既存の共通公開入力と当人の情報から作る。他人の秘密や画面の閲覧者による制約を別主体の選択へ渡さない。Model A の公開配役重みQ、世界内秘密履歴混合、枝の物理質量Pは別々に維持する。

## 2. 同時段階の順序と非先読み

1. 段階開始の公開状態・共同履歴・各主体の情報集合を固定する。
2. 全主体の合法手と、その情報集合だけに依存するintent方針を用意する。
3. 明示された共同選択則から全intentを揃える。他主体の今回のintent・成否・取得結果を見てから選び直さない。
4. 全intentと設定済みchanceを既存の物理遷移へ渡す。自護衛なし・連続護衛条件・同時死亡等はGameRulesと既存ルールに従う。
5. 既存の終局境界で停止し、続行枝だけに必要な公開観測・本人観測・履歴更新を行う。取得/公開報告の結果slotとタイミングは night_acquisition / morning_flow 等の現行規則を保つ。内部計算順序は、同じ段階の新結果を行動選択者へ見せる許可ではない。
6. 設定済みの継続戦略で次段階を評価する。

逐次処理で最初の行動結果を次主体へ渡したものを同時行動とは呼ばない。意図の列挙順・評価順を替えても、同じ共同則の物理枝と質量が一致することを⑥の受入条件とする。

## 3. 共同選択則の契約

現在の均等護衛×狼襲撃は、完全共同秘密状態に条件付けた現行の積 qa×qg と合法性を維持する。全体の周辺分布が独立という意味ではない。共有された役職・秘密履歴により無条件の行動は相関し得る。

追加の同時主体に、この積を根拠なく適用しない。共同選択則は、各主体の情報集合、完全な方針profile、段階入力に対して、合法なintent組の正確な分布と、一主体の合法な逸脱を評価する規則を明示する契約とする。既存の独立な局所乱択は既存の適用範囲で継承できる。相関装置・共有乱数・協調・共同偽報告を求める設定には、その共同則と逸脱の意味が必要で、なければ UndefinedJointLaw としてPendingを返す。

周辺の行動確率だけから新しい共同分布を推定しない。未実装の新主体を均等や独立に置き換えない。相関型の一般戦略や共同報告方式は本設計の追加仕様として採用しない。

## 4. 相互最大化と均等同率の契約

profile K は段階・主体・情報集合から合法手の分布への完全な対応である。最大化を要求する各情報集合で、全合法手aについて、同じKと同じ設定済み継続戦略を使い、当該情報集合の今回の行動だけをaへ介入した正確な期待勝率 V(a | I,K) を既存の共通フローで求める。他主体、当人の他の情報集合、継続方針、chance則を同時に変更しない。

利得は既存の所属陣営の勝率に従う。本人の閲覧用Pや他人の秘密を、行動選択の信念へ流用しない。最大化しない固定主体は設定済みの分布を保つ。

最大化主体の条件は K(I) = Uniform(argmax_a V(a | I,K))。同率最適の全手を均等にする現行規則を保つ。全主体・全情報集合でこの条件を同時に検証して初めて整合profileとする。二つのmaxを順番に計算すること、最初の整合候補だけを採用すること、継続方針まで自由最適化することは代用にならない。

一般の非均等な混合Nashを自動採用しない。現行の均等同率規則の範囲で整合profileが存在しないことも結果として許容し、その場合はPendingとする。この明示的な拒否までを確定仕様とし、常に数値を返す新しい解概念は⑥にも黙って追加しない。

## 5. 結果と証明の契約

| 結果 | 必要な根拠 | 通常の数値・方針選択 |
|---|---|---|
| UniqueCertified | 完全な合法逸脱評価と、候補領域の網羅または同等の証明による一意性 | 証明済みの方針のみ採用できる |
| MultipleCertified | 二つ以上の整合profileの証明。一覧が完結したかも別に記録 | 一つを選ばずPending。解集合の恣意的平均もしない |
| NoAdmissibleProfile | 現行規則下の候補を全て排除した証明 | Pending。別の均衡・乱択則へ置換しない |
| UndefinedObservation | 必要な続行観測の支持がゼロ等の具体的実例 | Pending。必要候補一件のwitnessで数値を拒否できるが、全候補の分類完了・解不存在とは呼ばない |
| UndefinedJointLaw / Unsupported | 必要な共同則・逸脱則・対応機能が未定義/未実装 | Pending。根拠のない独立化・均等化をしない |
| DependencyUnfinished | 未解決の後続profileや循環依存 | Pending。未評価得点を0にしない |
| BudgetUnfinished | 時間・仕事量・候補数の上限到達 | Pending。未定義や解不存在の証明とは区別する |

証拠には、入力/完全profileの識別、対象の主体と情報集合、合法手、公開/物理支持、依存先、候補総数と調査数、網羅/独立性/終局依存クラス/拒否witness等の証明範囲を残す。複数種類の問題がある場合、確認できた事実と未調査部分を併記し、一種類の完全証明と偽らない。

既存の物理終局は不要な後続信念を要求しない。続行するゼロ支持観測には一律補完・epsilon・任意の信念を入れない。公開重み正なのに必要な秘密支持がゼロの場合も最小例を保持してPendingとする。

## 6. ①・②と⑥への依存

①の完全共同履歴、公開/本人条件付け、合法手、設定済み方針、共有物理遷移、Model AのQ/秘密混合/Pの分離を基盤にする。②の既存戦略・未対応表示の契約も維持する。①の一部に予算未完や未定義観測が残っていても、④の本契約は確定できる。その枝の値が計算済みになるわけではなく、結果をそのまま伝播する。

934e35a の5/6人C/H/Wには未定義候補の実例があり、占霊の無制限6人には予算未完が残る。相互最大化の設計はoff-path信念を追加する理由にも、計算量不足を解不存在とする理由にもならない。①全面完了は未宣言のままである。

⑥が将来実装すべきものは、本契約に従う同時intentの接続、明示的共同則と逸脱、完全profileの証明器、結果/依存/証拠の伝播、cache整合と回帰である。探索順、SCC分解、証明された対称性・独立性・終局依存の再利用は実装上の選択であり、新ルールのユーザー判断を要求しない。完全profileや必要履歴を落とす再利用、未証明候補の採用、予算増加だけでの完了扱いは不可。

## 8. 既存の「想定外」合意との対応

2026-10-14 02:57 UTCの合意は、想定と整合する候補がゼロになる盤面情報を「想定外の盤面です」とし、機能未対応・計算エラーとは分けるもの。今回のゼロ支持も概念として同じ分類であり、新しい信念ルールを必須とはしない。

発生場所を分ける。入力/実観測に条件付けた候補が全て消えれば、その入力盤面が想定外。最大化の比較中の仮想続行枝だけで候補が消えた場合、想定外なのは比較枝で、元盤面そのものの候補ゼロとは限らない。元画面では「比較先に想定外となる枝があるため、この戦略の勝率を確定できない」という範囲の理由を示す。枝の値を補わず比較を未確定とする。現コードのundefined_witness/Pendingはこの伝播を表し、想定外の実例が一つあることから元盤面全体の矛盾や解不存在を主張しない。

例: 真狩人P1・生存P1/P2/P3、狼が必ずP1を襲撃する想定なら、実際にGJを入力すると観測盤面が想定外。一方、GJ未入力の夜に「狼P2が市民P3を襲撃する」合法な逸脱を比較すると、P1のP3護衛による仮想GJだけが同じ想定と整合しなくなる。前者と後者の場所を区別する。元の夜盤面まで不整合と断定しない。

①の完了条件を、新しいoff-path信念・均衡・数値補完の策定へ拡大しない。この想定外の拒否と伝播は既存合意で扱える。追加モデル判断が必要なのは、将来この枝にも通常の数値を割り当てたいと依頼された場合だけである。
