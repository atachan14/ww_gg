# B案：Board更新の階層フロー（検討中）

検討中・未実装のB案です。合意済みの責任境界と、まだ選んでいない処理順・規則を分けて示します。B案の採用、Step5の移行計画、製品の計算処理を決定・実装した説明ではありません。

## フロー全体の前提

- 各処理は必要な時点で、同じ版の共通GameDataの配役・ルール等を参照します。冒頭で一式をBoardへコピー保存する工程は置きません。GameLayoutの具体的な内容と版管理方式は[未決]です。
- Boardは地点固有の確定事実・有効入力と根拠を持ち、共同候補・必要履歴・条件別の結果は再構成できる派生状態として扱います。「保持先」と「更新する処理の責任」は別です。
- 1・2は事実と入力を整え、古い結果を失効扱いにします。役職率の算出・更新は3aの統一入口へ集約します。勝率と枝確率は3bの責任です。内部の共通helper分解は許容しますが、別の入口で役職率を独自更新しません。
- 3a内部は責任の内訳です。記載順すべてを確定した実行順にするものではありません。[未決]は有力候補を含む未選定事項で、それ以外は合意済みの責任・保持条件です。

## 入口の違い

- **新規Board：** 1→2→3a→3b。根なら初期生成、子なら親の有効な共同状態と遷移根拠を3aの出発点にします。
- **Currentの通常入力更新：** 2→3a→3b。地点の確定情報が変わらない場合です。
- **親訂正・Phase変更：** 必要な1から再構成。影響する共同状態・子の根拠・結果を失効扱いにし、旧子の局所入力を自動移植しません。
- **過去再評価の要求：** 対象過去地点の1・2と、Current条件を別に指定して3a→3b。通常評価では常に必要な処理ではありません。

## 1. 確定情報反映

1. **地点と確定した進行を反映**
   - 日時・Phase・生存者・確定した処刑や死亡等を反映します。推測した役職や秘密行動を確定事実に入れません。
   - 親・選択経路・依存する入力根拠の版を識別します。UIの収納上の親子と、進行・計算の依存関係は区別します。
2. **生成・再構成の入口を識別**
   - 根の作成、子の生成、親訂正後の再構成、過去地点の再評価を区別します。
   - 過去再評価で正規Boardの当時情報を書き換えません。親やPhase等が変われば、依存する計算を失効扱いにします。ここでは確率を再計算しません。

## 2. 入力情報反映

1. **有効な入力と根拠を整える**
   - CO・公開能力報告・SystemLog・観測入力と、その所属・取得時点・公開時点・出所を反映します。
   - 訂正、発言撤回、仮入力、確定入力を区別します。公開報告を真の取得結果として全世界へ強制しません。
   - 当時の設定と、当該地点以降の設定済み方針を区別します。
2. **視点と評価要求を整える**
   - 公開か、誰の本人視点かを指定します。本人の役職・取得結果・自身の行動履歴は公開入力へ混ぜません。
   - 正規評価かCurrentからの過去再評価か、固定行動比較か設定済み方針込みかを区別します。
3. **入力を検査し、旧計算を失効扱いにする**
   - 形式・所属・時点等を検査します。共同候補との確率的整合の検査は3aで扱います。
   - 変更に依存する役職率・勝率・関連結果を旧条件の結果として扱います。仮入力で確定入力を置き換えません。
   - 失効は再利用不可、退役は旧枝を現行経路から外す意味です。復元用記録の削除とは別です。ここでも確率を再計算しません。

## 3. 計算情報反映

### a. 役職率情報反映

1. **共同状態の出発点を選ぶ**
   - 初期生成：配役・ルールから全体候補と必要秘密履歴を生成し、選んだ初期モデルの重みを設定します。
   - 継承更新：有効な親の共同候補・重み・必要履歴を出発点に、子の遷移・取得・観測を反映します。役職率だけから再出発しません。
   - 通常更新：変更した入力を正しく再評価できる状態を使います。親が既に適用した証拠をもう一度掛けません。
   - 訂正再構成：既にゼロにした候補を新しいSystemLogや基準変更で復活させる必要がある場合、単純filterでは戻せないため保持した根拠から再構成します。
   - 過去再評価：対象過去地点とCurrent条件を区別します。[未決]証拠の適用範囲、当時方針への作用と評価式。
   - [未決]再利用・継承・根からの再構成を切り替える具体的な判定規則。
2. **COgroup方式・真偽基準を反映**
   - COと配役人数・騙り条件等の整合を扱います。COgroupは全体共同候補に対応する集計・条件付き内訳とし、独立した小ゲームにしません。
   - 初期priorの配分と、進行後の条件付けを区別します。子ごとに無条件で初期配分し直しません。
   - [未決]真偽基準の優先item・適用順、COgroup処理の位置。
   - [未決]追加CO時に再配分する条件と方法、定員未充足の保護・skip条件、遅いCCO、過去の未入力の詳細。将来仕様まで一律に「再配分しない」とは決めません。
3. **遷移・観測・必要秘密履歴を反映**
   - 処刑・死亡・GJ等の観測、占い結果の取得、護衛・襲撃等の必要履歴、公開時点に達したCO・能力報告を扱います。
   - 未知履歴は初期分布・ルール・設定済み方針から生成します。履歴生成に必要な共通計算部品を使っても、役職率更新の入口は3aに揃えます。
   - 公開配役重み、世界内の秘密履歴混合、物理枝質量を分けます。すべての行動選択尤度を公開配役重みに一律に掛けません。
   - 手入力報告の整合判定と、自動生成する報告の選択確率を区別します。観測済み証拠と新しい遷移を二重適用しません。
   - [未決]新しい真偽規則と観測・履歴更新の適用順。
4. **支持と重みを確認し、必要な正規化を行う**
   - 各分布の意味・分母を保ち、必要な条件付けの箇所で正規化します。「最後に一度だけ」とは決めません。
   - 公開重みが正の世界と秘密履歴支持の対応を確認します。支持ゼロを一律の仮履歴で補いません。
   - 候補ゼロの場合は入力不整合・未対応・情報不足・予算超過等を区別して返します。未計算を全員0%や勝率0として扱いません。一部候補の正当な0%とは別です。
5. **公開・本人の条件別状態を構成**
   - 公開共同状態を保持し、本人の役職・結果・行動履歴で別の派生状態を条件付け・正規化します。
   - 本人状態で公開状態を上書きしません。閲覧者の秘密を他者の行動選択に渡しません。
6. **役職率を集計し、対応するBoardの計算結果に反映**
   - 対応する共同分布を各人・各役職へ周辺化します。各人の役職率の独立な積で共同分布を作り直しません。
   - 共同候補・必要履歴と結果を、地点・入力根拠の版・視点・評価条件に対応付けます。保持欄そのものが処理主体なのではありません。

### b. 勝率情報反映

1. **終局を判定**
   - 終局なら対応する勝敗値を返して止めます。終局後の不要な未来枝を作りません。
2. **候補と評価条件を整える**
   - ルールから合法手を求め、固定行動の比較と設定済み方針込みの評価を区別します。
   - 各行動者が知る情報だけで方針を選びます。候補評価に必要な再帰は以下で行い、maxの選択はその値に基づきます。
3. **各行動の取得・公開・観測の枝を生成**
   - 設定済み方針と物理ルールから結果を生成し、枝確率とその条件・分母を計算します。役職率の周辺値だけから物理枝確率を決めません。
   - [未決]「黒を見つけたらCO」等の将来CO方針。定義された場合は子の有効入力へ反映し、子3aで共同状態を更新します。
   - 遷移で既に反映した取得・観測・重みの根拠を子へ渡し、子3aとの二重適用を防ぎます。
4. **必要な子Boardを同じ入口で評価**
   - 子も1→2→3a→3bを通します。継承は3aを省く意味ではなく、その出発点です。
   - 未来Boardは必要時に生成する一時状態として扱えます。全未来木の永続保存は前提にしません。
5. **枝の値から行動値・盤面値を求める**
   - 枝確率×子の勝率を加重合計して固定行動値を求め、設定済み方針で行動値を集約します。maxは設定済み継続戦略の下で最良候補を選ぶ意味です。
   - 未定義の最適CO・報告規則を追加せず、未対応maxを黙って均等へ変えません。同時複数maxの一般の相互期待勝率最大化は未実装で、その実現方法は[未決]です。
   - 盤面値・候補別値・次の朝まで・累積等を区別します。未完成の計算を完成値として保存・表示しません。
6. **要求された関連・過去再評価を取得**
   - 正史の親子、未来、現行内訳、Currentからの過去内訳を別種の関連として辿ります。UIの収納関係を物理遷移とみなしません。
   - 過去再評価は要求された時だけ行い、通常計算で常に過去Boardを作るものではありません。正規Boardの当時評価を上書きしません。
   - [未決]過去再評価の対象選択、内訳の分母・固定条件・方針への作用。

## 表示・保存・cacheとの境界

- 百分率への変換・丸め・画面配置は、計算結果を使う表示処理です。
- 保存は正本と復元根拠、cacheは再計算可能な結果の再利用として区別します。具体的な保存範囲・cache容量は[未決]です。使う場合は地点・入力根拠の版・GameData版・視点・評価条件が一致する結果だけを再利用します。
- 現行実装では保存Game、保存Boardノード、計算Boardは別です。計算用Boardが一部の人数等を持ち、復元用退避が設定をコピーすることもあります。この事実をB案の「各Boardへ共通設定一式を保存する工程」と読み替えません。

## 校正した点と理由

- **共通前提と手順：** GameData参照を独立Stepから外し、各処理の必要時参照へ。コピー保存との誤読を避けるため。
- **役職率の責任：** 共同状態構成・条件付け・集計を3aに集約。保持欄と処理担当、helper分解と独立更新を区別するため。
- **継承と再構成：** 子も全入口を通し、候補復活時は根拠再構成。親分布の単純filterで常に十分という誤読を避けるため。
- **順序と未決：** 真偽優先・COgroup位置・追加CO・過去条件に[未決]を明示。列挙順を確定アルゴリズムにしないため。
- **異なる確率と履歴：** 公開配役重み・秘密混合・物理枝質量、初期priorと後続観測、入力訂正と撤回を区別。二重カウントを避けるため。
- **失効と表示：** 失効／退役／削除、候補0／勝率0／Pending、保存／cacheを区別。計算状態やUI収納を確率の意味に混ぜないため。
