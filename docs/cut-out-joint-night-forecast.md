# Opt-in joint-night Forecast and SavedOrigin experiment

Parent 386413c. Normal engine/factory/UI routes remain unchanged. The new cut_out_joint_night_forecast entry is an explicit opt-in experiment. It uses a bound fixed source and one generated night, then complete common continuation to terminal results. Multiple generated nights are explicitly rejected by both compared engines.

## Admitted cases and guarantee

* Original 4/5-player W1/S1/M0/H0, P1 true-seer CO with initial white P3, then fixed P3 execution. Current source is a three-/four-live first-night Board.
* Original actual 7-player W2/S1/M1/H0 uniform saved input, with the previously documented synthetic first-night observations, then fixed known-wolf P5 execution. Current source has four alive at night2. Night1 is already saved history, not a second generated night in this comparison.

Sources come from SavedOrigin and the existing issued root/group proof, followed by the existing fixed action-evidence recipe. A new identity ledger binds data object, origin/root, immutable input text, revision, settings and complete current source. Q and private/physical P remain separate. OwnView is admitted only by the exact existing own-evidence condition recipe; its owner/acquisition endpoints split groups before orbit generation. Root private/public substitutions are rejected before generation.

The joint producer reads roster block-occupancy signatures once from the carried joint law and constructs representative rosters, legal target-block choices and combinatorial multiplicity. It does not expand each literal information set x action and then deduplicate. Root solve backs up only those joint representatives; later branches use the existing common uniform continuation. A separate fully labelled old recursion is the oracle. No new CO/report policy, max choice, hunter approximation or latent-information shortcut is introduced.

Terminal comparison keys include the full parent source, action and child: identical normalized terminal states can have different conditional branch probabilities and must not be collapsed.

## SavedOrigin reconstruction and ownership

TransportEvidence is identity-issued and checks the exact reconstructed input before applying a previously proved label mapping. Mappings must be bijections inside inherited blocks and fix the own-view endpoints. Every read must retain the original SavedOrigin and fixed evidence prefix. The transport changes full correlated carriers and event labels, not only marginal probabilities or scalar values.

For each engine/case one full recipe path is replayed with reconstruction-kernel reuse disabled. Every unique complete terminal transition is then read through its SavedOrigin recipe with the existing exact completed-step cache enabled. Those entries are keyed/checked by complete immutable source inputs. No KernelOrigin or computed parent posterior is installed as an authoritative origin.

An initial attempt to cold-rebuild every path separately in the seven-player case exhausted the ten-second restoration budget and was unverified. It is not counted as a passing all-cold test. All six final comparisons use the stated one-cold-plus-exact-reuse policy and succeed within the same limits. This distinction remains material for future performance work.

Seventeen negative cases preserve rejection of copied receipts/transports, changed Q/P, skew that leaves the representative's mass unchanged, view-only/private-only changes, wrong owner/origin, stale revision at Forecast/read time, out-of-block or owner-changing transport, max, unsupported larger source and a second generated night. Arbitrary within-information-set unequal-likelihood measures remain outside admission; arbitrary biased distributions are not newly supported.
