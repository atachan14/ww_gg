Scope is the same actual seven-player input and fixed prefix: execute P1, bite P4, surviving true medium P3 reports P1 black or white. No initial-root search, ordinary UI/HELP/MAX/hunter change, deployment or external publication. The two earlier black-only checkpoints remain historical records.

## One structure with distinct primitive input laws

The medium observation is applied by the existing common morning flow before declarations. Black fixes true seer P2, one live wolf and medium-branch mass Q=1/2, P=4/9. White fixes dead true seer P1, fake reporter P2, two live wolves and mass Q=1/2, P=5/9. Only P2 is a living seer CO in either case. Multiple-reporter generalization is therefore unnecessary for this extension.

Truth acquisition patterns and the existing exposed-fake public-history options feed one single_report_orbits reducer, one label restoration function, one publication receipt, one Forecast adapter and the same SavedOrigin/cold replay path. The adapters differ because a truthful acquisition constrains the secret joint state while an exposed fake declaration does not. Black has four representative vectors/eight named outputs; white has six representatives/ten named outputs. No complete named vectors are expanded before grouping. Both adapters preserve every original role mask, acquisition, roster and attack history.

For the white branch, existing fake_uniform_options uses the original target roster, excludes self2 and previously reported target4, permits the dead target1, and keeps both colors for targets1,3,5,6,7. Each named option has conditional probability1/10. Noncontradictory filtering cannot make P2 true again after medium white has proved true owner1; the established exposed-fake noise law applies. Thus black1 and black3, or white5 even when physical wolves are2/5, remain legal fake declarations. This is existing configured behavior, not a newly optimized CO/report rule. Fake reports create public history, never fake private acquisitions.
