以後の要件確認はこの文書を基準にし、追加のユーザー説明に応じて更新する。

## 確定：目的と計算

- 人狼ゲームの盤面・公開情報と指定した条件に基づき、各行動・各Phaseの陣営の期待勝率を求め、確認する。
- 乱数試行によるシミュレーションではなく、確率分岐をアルゴリズムで評価した厳密な期待値が必須。
- MC推定、信頼区間、探索上限に達した際のMCへの切替は、厳密期待値の代替にならない。
- 厳密値と表示用の丸め値を区別する。具体的な内部表現や計算方法はまだ選定しない。
- 素村・狼だけの小さい例から、要件と期待する結果を照合して進める。

## 確定：最初の素村・狼の基準例

### 初期人数と進行

| 例 | 素村 | 狼 | 合計 |
| --- | ---: | ---: | ---: |
| 3人 | 2 | 1 | 3 |
| 4人 | 3 | 1 | 4 |
| 5人 | 4 | 1 | 5 |

- 昼開始。
- 昼は全生存者を処刑候補とし、各対象を指定した場合を別の行動枝として評価する。候補同士を等確率で混合しない。
- 未決着なら夜へ進み、狼が生存する村人を一人襲撃する。
- 狼0人なら村勝ち。生存狼数が生存村人数以上なら狼勝ち。
- 処刑直後・襲撃直後に決着を判定し、決着した枝では次の行動を行わない。処刑直後に終了したら夜の襲撃へ進めない。
- この基準例ではCO・能力・追加公開情報による対象の立場差を使わない。これはMAINの公開情報変更機能を不要とする意味ではない。
- 夜は狼が村人を襲撃する。対象の人物が違えば次の昼の顔ぶれ・公開履歴も変わるため、候補の扱いと確率・進行先は確認中。人数が同じことを理由に枝を混合しない。

### 手計算による照合値

各処刑対象を固定した場合の処刑直後の厳密値を照合する。旧版の一様処刑を前提とした5人の最終値 `7/15` を、訂正後の正解基準として自動採用しない。

| 例 | 処刑直後の村勝ち | 処刑直後の狼勝ち | 未決着 |
| --- | ---: | ---: | ---: |
| 3人 | `1/3` | `2/3` | `0` |
| 4人 | `1/4` | `0` | `3/4` |
| 5人 | `1/5` | `0` | `4/5` |

4人の村処刑後は村2・狼1の夜で、合法な襲撃後は村1・狼1となり狼勝ち。5人の村処刑後は村3・狼1の夜で、合法な襲撃後は村2・狼1の昼へ進む。夜の候補・重み・表示履歴と、次の昼の行動選択は確認中。

### 次に具体化する3人例

最初の確認例は「村2・狼1、昼開始」とする。

| 昼の結果 | 確率 | 処刑直後の人数 | 決着と後続 |
| --- | ---: | --- | --- |
| 狼を処刑 | `1/3` | 村2・狼0 | 村勝ち。その場で終了 |
| 村を処刑 | `2/3` | 村1・狼1 | 狼勝ち。その場で終了 |

この例では夜の襲撃は一度も起きない。
TOPで何を確定し、MAINで何が表示され、どの変更操作に対して何を再計算するかを、この例の画面操作として確認する。
この3人例の最小実装は承認済み。初期の公開情報は全員生存・役職未確定に固定し、公開情報の編集欄は今回後回しとする。追加の確定役職情報・CO・能力入力を推測で設けない。外部公開・pushは、この版の確認後に別途区切る。

## 確定：TOPの役割

- 大きくTOPとMAINの二画面を想定する。名称は仮。
- TOPは、ゲーム中に変更できないゲームルールの設定を主とする。
- 配役と、役職ごとのローカルルールをここで設定・確定する。
- 戦略の初期値も設定し、初日の行動に反映する。
- MAINはTOPで確定したゲームルールを前提とする。MAINの戦略・公開情報の編集と、固定ゲームルールの変更を同一に扱わない。
- 基準例で承認された昼夜・処刑・襲撃・勝敗条件を、最初の照合条件とする。他の選択肢を自動で追加しない。

## 確定：MAINの役割

- MAINはPhaseごとにPage送りし、TOPで確定したゲームルールを元に各Phaseの状況を確認する。
- TOP直後に表示するMAINは初日昼（Day1昼）。
- Phaseごとに戦略と公開情報を変更でき、吊り先を指定できる。
- 戦略・公開情報・吊り先の変更に応じて、その条件に基づく期待勝率を再計算して表示する。
- 各Phaseでの表示項目は、ひとまず旧ww_ggを参考にする。旧実装の未完成部分まで、そのまま完成仕様としない。
- 情報差がない同等の候補は、対象を変えても同じ期待勝率になる場合がある。「変更するたびに必ず違う数値を出す」という要件ではない。

旧UIの参考項目は、配役、Day・Phase、陣営勝率・決着、各人の番号・名前・生死・CO・陣営／役職確率、対象別の勝率欄、対象選択、戦略操作、進む／戻る。
具体的な列、入力範囲、配置、更新の確定方法は未確定。能力結果入力や専用能力Phaseは、旧資料の案と仮表示を区別して確認する。

### 確定：初日昼から夜への操作

1. TOPでゲームルールと戦略初期値を設定し、初日昼のMAINへ進む。
2. 必要に応じて公開情報・戦略を更新し、その条件の期待勝率を確認する。
3. 吊り先を指定する。
4. **「夜に進む」** を操作する。処刑後が終局条件に達する場合はその場で停止し、未決着の場合だけ初日夜（Day1夜）へ進む。

「夜に進む」は終局条件より優先する操作ではない。村2・狼1の3人例では、処刑後の両分岐が終局のため、初日夜へ進む枝はない。
画面上のPage送りと、確率分岐の各結果をどの状態として閲覧するかの詳細は分けて確認する。初期のPhase送りにTree可視化を必須としない。Treeの形式や枝の閲覧操作は後回しで、ここでは確定しない。

### 確定：進行先と全枝終局時の決着画面

- 決着しない分岐があるなら、未決着の分岐へ進む。すべての分岐で決着する場合は、決着画面として村の勝率と狼の勝率をそれぞれ表示する。
- 今回の3人例では処刑後の全枝が終局する。どの対象を指定しても、決着画面の情報欄に村 `1/3`・狼 `2/3` を表示し、夜の行動は行わない。単一の実役職・結果を乱数で決めない。
- 決着画面の勝率は、指定対象が村人か狼かという不確実性を保った勝敗の確率。村か狼のどちらかを必ず1つの勝者表示に置き換えない。
- MAINは情報欄→プレイヤーテーブル｜戦略→将来のTreeという順を想定する。Tree可視化の実装は引き続き後回し。
- 情報欄は旧版の配役、Day・Phase、陣営勝率・決着表示を参考にする。開始配役と処刑後の生存者数を区別し、未確定の真の役職を表示情報に混ぜない。

未決着枝への進行は今後の人数拡張で具体化する。複数の未決着の可能性を恣意的に1つ選ばず、重みを保持すること、既に終局した確率質量を含む全体勝率と条件付きの勝率を混同しない表示・状態管理は、今後の検討事項。今回の3人実装に不要な一般化を先回りして加えない。

## 将来要件：プレイヤー申告とシステム情報の集約

CO・能力結果に加え、ユーザー入力のシステム情報を同じ情報パネルへまとめたいという構想を記録する。既存プレイヤー表の親パネル内にシステム情報欄を置き、独立したトップレベルパネルを増やさない構成案。親パネル名 **BoardInformation** は提案段階だったが、後述の追加確定で不採用。システムログ表はBoardPlayerTable内のプレイヤー表の上に置く補足情報という将来案へ更新する。

例：システムログの意味として、当該時点に生存中のパン屋がいないと確定できる場合、生存中のパン屋CO者は全員そのCOが偽と判断できる。この例は一般的な将来要件であり、特定プラットフォームのログ仕様やパン屋の挙動を検証済み仕様として採用しない。新役職・システム情報の入力や計算接続は今回実装しない。

時点、未入力と不在確認、確定情報とプレイヤー申告を区別する。パネルの区分案と後続設計の注意は [バックログ](backlog.md) に記録する。


## Game / Board領域の表示名追加確定（2026-10-09）

ユーザー承認（Slack message `1791520934.114619`）により、画面でも影響範囲を伝える次の5名称へ統一する。

| 表示名 | 対象 |
| --- | --- |
| GameCast | ゲーム全体の初期配役 |
| GameRule | ゲーム全体のルール |
| BoardOverview | 当該盤面・Phaseと勝率の要約 |
| BoardStrategy | プレイヤー全体で共有する戦略に基づく期待値計算の設定 |
| BoardPlayerTable | 当該盤面のプレイヤー表、CO・能力結果と役職確率の確認 |

見出し・参照導線・アクセシブル名へ反映する。通常文中の一般名詞や個々の役職ルール・戦略項目は英語へ機械置換しない。既存DOM IDと保存形式・URL・計算ロジックは保全。BoardInformationは不採用で、将来のシステムログ表はBoardPlayerTable内のプレイヤー表の上に補足する。システムログ機能の実装承認を意味しない。
