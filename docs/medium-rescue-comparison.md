## Local selector safety and adoption decision

`OverCapReuseForecast` is ONLY a benchmark/test class. It first returns an existing current key unchanged. On a missing key, it considers only original6 IDs, target=None, configured120 bound, bounded law sizes, supported observer and a single identical colour block (hence720 candidates). It then invokes the same bounded COMPLETE snapshot proof. Unsupported observer, unproved correlation or plan exhaustion returns no key, so the original fallback remains. Selection changes memo construction only, never actor policy, posterior, legal targets or probability mass. The correlation negative and retained existing-key path have unit controls.

The selector preserves numerical equality here and avoids77 unnecessary plan calls (78->1). It is not proven universally faster; the small observed total differences are noisy and original remains fastest. Even a genuine canonical-key rescue need not be necessary for the numerical value because an existing reducer already covers it. A stronger selector would also check whether the EXISTING complete reduced-key path already suffices before adding proof; that remains a design idea, not a new enabled rule.

Decision: no production/default/factory adoption, no7 expansion, no all-seer future. Keep the comparison classes isolated.11 focused key/selector/integration tests pass in1.722s; no new full suite was run. Last production full-suite evidence remains860/860 at c97f630. Standard UI process/settings are unchanged. Comparison/test worker absence is checked before returning the quiet window.
