# v0.5以降の要件候補：朝の選択用

2026-10-07。基準はv0.4本体 `0c679e6`・検証記録 `21c84c2`。この文書は提案だけで、v0.5以降の機能採用・実装承認を意味しない。版番号と日程も未確定。

根拠は [要件基準](requirements.md)、[backlog](backlog.md)、[v0.4](v0.4.md)。[旧vision](../../gg_ww2/docs/vision.md)は目的・私的情報・初期占いの検討記録として参照し、当時の暫定ルールや実装を現版の確定仕様へ読み替えない。

## 既に確定している土台

- 公開Boardと全候補共同分布からFractionの厳密期待値を求める。実配役を1つ選ばず、MCへ置き換えない。
- 真報告は同じ配置に由来する。偽報告は方策のAction。隠れ配置ごとに最適化してから平均しない。randomの内部選択を次の公開Boardへ漏らさず、同じ公開結果へ到達する質量を合算する。
- 計算条件はBoardごとに保存する。例として「1日目は市民騙り可、2日目から不可」に対応する方向は確定。現在は騙り許可編集UIが未実装。
- CO必須は条件集合で保持し、条件のいずれか成立で必須。能力結果条件の具体的意味・Xの指定は未確定。
- ギドラの合法性はAND：全宣言が候補の真役職自身、またはその真役職の騙れる役職に含まれる必要がある。1つでも許可外なら候補を除外する。グループ化・CCO人数カウント・解除履歴は未確定。
- 現行全配役一様／COグループ比較候補／2段階残差試作を保全する。正式なモデル一本化は未確定。
- 占い師・狩人は現在、能力なし。能力・初日白・ギドラは未実装。Tree表示は延期中。「戦略オプション」への改名、random方針の画面初期対象も未確定。

## 候補ごとの最小範囲と確認点

### 1. 履歴／戦略の見せ方：候補

- 価値：現在勝率・累積勝率と、過去Boardの設定を読み違えにくくする。
- 最小scope：行動ごとの日／Phase、対象、当時の計算・CO必須条件、CO／入力済み申告を読み取り一覧にする。既存の戻る操作を案内する。
- 依存：既存のBoardスナップショット。新しい計算規則は不要。
- 要判断：常設か折りたたみか、現在Boardとの違いを何項目見せるか。改名は別判断。任意履歴ジャンプ・比較ケース分岐・永続保存は含めない。
- 小ケース：1日目max→2日目randomへ変更し、過去欄はmaxのまま。戻ると当時の対象・設定が復元される。未入力を申告済みとして表示しない。

### 2. 役職ごとの騙り許可編集：対応する方向は確定、UI／詳細は要判断

- 価値：市民騙りや役職間の騙り許可をBoard単位で比較する。
- 最小scope：真役職別の許可先集合を編集し、行動時の履歴へ保存。自役職COは許可設定と別に常に適合。現在既定の村役職なし／狼は配役内全役職を保つ。
- 依存：CO互換判定、初期COグループ分布、過去設定再生。進行後に新設定で初期配役を配り直さない。
- 要判断：後続Boardで禁止に変えた際の既存COへの扱い。村役職が霊を騙る場合の申告・将来報告方策（現在の真霊／狼偽霊だけの規則から自動拡張しない）。UIで初版に許可する変更範囲。
- 小ケース：初日市民の占COを許可→翌日禁止、過去Boardの制約を保持。設定項目の表示順を変えても同じ共同分布。狼以外の複数騙り役職も順序不変。

### 3. 占い能力：候補、情報と時点は要判断

- 価値：占い先・公開白黒が対象別勝率へ与える差を見る。
- 最小scope案：占い対象の明示指定、占CO者の結果申告、真占の白黒と指定した偽報告方策による将来分岐を一組ずつ追加。手入力だけを能力込み期待値の完成とは扱わない。
- 依存：占の位置と結果の共同分布、対象のAction、公開時点、本人の私的結果を含む利用情報。現在の未来キャッシュで占の位置を周辺化する最適化は再設計する。
- 要判断：私的結果を誰がどの行動で使うか、対象の合法範囲・再占い、夜の選択／同時解決、翌朝死亡時の報告、真占の結果騙り・狼以外の騙り報告。旧visionの初日ランダム白の記録を現版へ適用する対象集合・公開状況を再確認し、都合で別の既定を作らない。
- 小ケース：5人・占1狼1、明示対象の白／黒を共同分布と照合。同じ公開情報の世界で私的な占結果を狼方策へ漏らさない。占2人の同一対象は独立結果として扱わない。

### 4. 狩人護衛：候補、夜の観測は要判断

- 価値：護衛先が襲撃・生存確率と最終勝率をどう変えるか比較する。
- 最小scope案：護衛対象の明示指定と襲撃の一夜同時解決、成功／失敗後の公開Boardと継続勝率。最初の占い版と同時に広げない。
- 依存：狩の位置、狼の襲撃Action、護衛対象の利用情報、死者なしの夜を保存できる履歴。現在の「各行動で対象が死亡する」状態管理と人数だけの進行上限をそのまま使わない。
- 要判断：自己護衛・連続護衛・対象制限、複数狩、護衛／襲撃の公開範囲、成功が誰にどう分かるか。ページ入力順を理由に他役職の未公開行動を漏らさない。
- 小ケース：確定狩が明示された襲撃先を守る夜、死者なしで翌日へ進む。狩死亡／対象不一致との比較。公開されない護衛先から真狩を勝手に確定しない。

### 5. ギドラ：AND合法性は確定、機能範囲は要判断

- 価値：複数役職宣言を、重複人数や独立確率の誤計算なく扱う。
- 最小scope案：Player行の「COを追加」で宣言集合を入力し、AND互換と完全配置の整合性を確認。採用するなら、将来報告を含む勝率への接続範囲も先に明示する。
- 依存：騙り許可、複数結果欄、CO必須条件、CO時点と申告機会の履歴。
- 要判断：CO集合による排他的グループ化は検討案。CCOで集合に含まれる役職をどう数えるか、宣言削除が編集撤回かゲーム内解除か、過去制約をどう保持するか。未定の解除規則を作らない。
- 小ケース：真占の占・霊COは霊騙り許可がないと除外、あれば適合。重複宣言や追加順で人数・分布が変わらない。占だけ／霊だけ／占・霊を使う案でも1人を二重計上しない。

### 6. CO必須の能力結果条件：条件集合は確定、発動意味は要判断

- 価値：「定員到達CCO＋黒結果でCO」等の方針を比較できる。
- 最小scope案：霊能の黒条件を1種類だけ既存の条件集合へ追加。可変Xや全役職への一般化は同時に入れない。
- 依存：潜伏者の結果入手時点、条件成立による将来COのAction／観測、Board別条件保存。現版が自動生成しない将来COを新たに扱う必要がある。
- 要判断：本人だけが知る真結果が基準か、公開された他人の申告が基準か。黒の人数X・回数・対象、偽結果の扱い、同時CCOの時点。既存条件とのORは維持する。
- 小ケース：未公開の黒結果を他人のCO条件に漏らさない。複数条件が同時成立しても同じCOを二重生成しない。条件が未成立でも現在の手入力COを勝手に消さない。

### 7. Tree表示：延期中の候補

- 価値：対象Action、結果Chance、到達質量、条件付き勝率の理由を確認できる。
- 最小scope：現在Boardから1行動だけ展開し、要求時に次の枝を開く。終局枝と未決着枝、random報告の公開結果合算を区別して表示する。
- 依存：既存の厳密全候補評価。描画の表示深さを計算範囲やゲーム時間にしない。
- 要判断：MAIN内か別画面か、枝の絞り込みと戻るの意味。最大同率Actionを消さず、表示上の折りたたみによって計算質量を変えない。保存・共有は別件。
- 小ケース：3人処刑の両終局を1/2ずつ表示。真霊2人の白白／黒黒だけの相関枝を表示。random内部指示を公開情報の枝として見せない。

### 8. 性能改善：継続候補、数値仕様の変更なし

- 価値：9人の再計算や能力追加後の待ち時間を抑える。
- 最小scope：cold／warmの初期評価・全候補・終局までの履歴を分けて測定し、実際の重い箇所1つだけ改善する。
- 依存：同じ公開情報に対して十分な共同状態であることの証明と回帰fixture。v0.4の [実測](v0.4-benchmark.json)を比較基準にする。
- 要判断：許容待ち時間と測定対象端末、長い計算の進捗・取消・明示停止。固定の探索上限値やMCフォールバックを新要件にしない。
- 小ケース：キャッシュ有無でFractionが一致。死者の処刑色と生存CO者の真偽相関を残す。初夜だけ速くても完成と判定しない。

## 推薦する順序（未採用）

独立QAの修正 → 履歴／Board設定の見える化 → 騙り許可編集の意味確定と実装 → 占い能力 → 狩人護衛 → 能力結果によるCO必須 → ギドラ → Tree表示。性能測定と必要な厳密最適化は各段階で行う。

推薦する次版の小範囲は **A：既存履歴・当時設定の読み取り表示だけ**。意味が確定したBoard別設定を確認しやすくし、能力やギドラの判断を一緒に増やさずに区切れる。能力を先に優先する場合はCへ替え、その情報・時点の判断を先に済ませる。朝の選択前にどれも実装しない。
