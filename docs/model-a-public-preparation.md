# 全体側モデルAの準備区切り

2026-10-13、基準59c9482。6項目の統合と、その後の共通化再点検/次要件選定は承認済み。今回は公開用計算の準備を保存する区切りであり、6項目の完了や全体UI切替はまだ行っていない。G作業と公開版は変更しない。

## 実装と検証済み

- model_a_public.evaluate_public_game/public_forecast：秘密を受け取らない公開用A入口。公開の共同取得priorを作り、Boardの現在値、昼の対象別最終値、朝までの勝利質量を返す。夜のOverview値も評価できる。
- horizon_for_action：最終期待勝率で仲間ごとの夜方針を選び、期限内の終局質量だけを数える。最終評価と期限内評価は、同じaction_flow.resolve_action/NightFrameで取得・物理死亡を処理する。将来の能力を期限内評価専用の別夜solverに追加しない。
- forecast_result.Forecast：旧新の出力型を共有。夜の対象比較が未確定の間はnight_actions/night_horizonをpending_metricsに明記し、その列の数字を作らない。画面にはまだ接続していない。
- exchangeable_public：公開の狼位置が交換可能で将来開示がない範囲に限定したAの人数圧縮。既存exchangeable_valueを使い、旧指定行動法へfallbackしない。COを含む有効未来霊能/占い開示がある場合は使用しない。狩人は現行の能力なしモデルであり、護衛を実装する際はこの高速化の適用条件も必ず狭める。
- public_history_key：取得prior生成が読む公開入力だけを抽出する。秘密下書き・閲覧者・無関係なUI状態をcache keyへ入れない。Board、Rules、Strategy、公開取得/公開日履歴、計算上限で完成数値のcacheを分ける。16件のimmutable結果だけを保持し、FuturePendingを保存しない。未定義の夜列には数字がなく、明示的pending_metricsが残る。

5人・各役職1人・開示なしで、圧縮を無効にしたAと4種類の夜戦略/自己噛み設定の全対象最終値・期限内値が一致。単に旧compressed solverの結果をそのまま新側へ流用したのではない。

3/4/5人・狼1の最終値1/3、1/4、7/15を維持。4人の昼から朝まで村1/4・狼3/4、5人では村1/5・狼0で、最終値と期限内値を区別する。実際の公開CO/取得履歴と私的API要求で公開snapshot/cacheが変わらない回帰も追加。

9人・狼2/霊能2/占い1/能力なし狩人1・全て非開示の計算で、Aの9行最終値と期限内値が約0.002417秒、最終値94/315。旧のOverview値だけ約0.001292秒で同値。出力範囲が異なるため、この2つの時間から速度優劣は結論しない。霊能/占いの大きな非対称盤面の同等性能はまだ未保証。

## 未完了と必要な仕様回答

全体視点の夜にPlayer Xを比較する際、Xが仲間になる配役も混ざる。役視点は仲間確定なので単純に仲間を除外できるが、全体では条件付けを決める必要がある。次のどちらかを質問済みで、回答を待っている。

1. Xを襲撃できる配役だけに条件付けた、対象指定の比較（推奨）。
2. 設定済み狼戦略が自然にXを選ぶ場合の条件付き勝率。

これは同じ数値ではない。2は各仲間構成の行動選択確率を比較の重みに使う。どちらでも、後続公開推論に襲撃選択尤度を加えないA契約は維持する。回答前に既定値として片方を採用せず、空列を既存公開計算で埋めない。

その回答後に夜列を実装し、Overview/Tableの最終値・期限内値・累積、preview/確定/戻る後の再描画を同じfacadeへ接続する。続いて霊能/占い/9人の性能不足を補い、公開policy cacheと私的payoff cacheの契約を整理、旧評価ループを参照移管後に削除する。既存旧計算は今も画面から使われているので削除していない。

6項目終了後は偶発的な重複を再点検し、同値保証された高速経路と情報所有者による分離は理由を示して残す。その完了区切りを報告してから、潜伏/非開示の本人利用や狩人など次要件を選ぶ。新仕様は勝手に確定しない。
