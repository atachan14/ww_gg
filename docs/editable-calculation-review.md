# 計算中の編集・通信の整理（ローカル修正）

公開8010bf1の全main.inert/全POST拒否を撤去し、プレビュー中のCO/結果/戦略編集を可能にした。追加修正の公開は未承認のためpush/deployしない。

旧dbcba096以前は、Tableの180ms debounce/AbortController/要求番号、本人視点のAbortController/世代番号、戦略のrunning+pending loopがあった。通信Abortや古い応答を無視することと、サーバー計算の停止は異なる。旧版に確実なサーバー計算取消はない。8010bf1のprocess semaphoreも中断ではなく、別要求を待たせる排他である。

修正は同一ページのfetch POSTを1件ずつ実送信し、古いプレビューがclient Abortされても応答bodyが終わるまで通信枠を保持する。待機中の同種プレビューは最後の1件だけ、保存等の書込みは順序を守って全件保持する。古い応答の反映は既存の世代/Board/revision照合で防ぐ。サーバーを即時取消せず、現在の計算1件＋最新入力1件にまとめるので、最後の編集からの総待ち時間は1回の最大約5分を超える可能性がある。

戦略も180msの静止待ちで連続変更をまとめる。戦略反映中もCO/結果を保持し、最新戦略反映でDOMを作り直す際に下書きを引き継ぐ。COプレビューは未反映戦略では送らず、最新戦略の反映後に再開する。保存を押した意図は戦略反映後の最新下書きへ引き継ぐ。戦略失敗時は下書きを保持して保存を止める。プレビュー失敗/期限到達でも下書きをsessionStorageから復元する。

公開保存の原子的確定中と明示的なページ送信/盤面遷移だけは、その入力を保護する（先行計算待ちで長くなる場合もある）。単なるプレビュー待ちでは編集を止めず、ページ全体を無効化しない。サーバーの270秒/400万work、数学、認証は変更していない。実装はブラウザのfetch調停と既存入力管理のみであり、複数タブ/複数Vercelインスタンス横断のキャンセル機構ではない。
