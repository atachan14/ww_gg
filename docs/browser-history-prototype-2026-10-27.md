## Shared implementation

werewolf/browser_history.py adapts the existing navigation handlers through one bounded same-origin transport. BrowserStore keeps a NavigationDocument only in the request; save means returning the next recipe, never writing a journal. Existing NavigationDocument.restore / NavigationGame.restore replay and validate all occurrences, name bijections, edge weights and settled outcomes using the same exact evaluator. No second simulator, approximate distribution, client-provided payoff cache or trusted arbitrary client posterior was added.

Recipes use an application-key-signed versioned envelope as an early integrity check, then full exact replay. A validly signed fixture with edited selection_weight is still rejected by replay. The browser holds the envelope in IndexedDB, not a4KBcookie. Unchanged signed cookie identity still scopes the normal anonymous session; no account/backend login is introduced. No local121saved journal is uploaded or imported into this prototype.

The common Tree's process-local numeric node IDs are represented on the wire by stable semantic-route hashes plus signed reconstruction recipes. A fresh worker replays only the requested evaluator routes and maps the resulting real nodes back to the same presentation IDs. Route signatures include revision; old route references cannot cross a Current change. No child/probability is invented for a missing ID. Board display numbers are presentation metadata retained in IndexedDB, not solver state.

The optional static/browser_history.js transport saves through an IndexedDB transaction before ordinary BoardNavigation.install. Compare-and-swap rejects late old replies and conflicting tab writes; identical duplicate results remain idempotent. Save failure rejects adoption and keeps the old stored recipe/draft. Initial old-cookie Current is hidden until local history restores. The existing panels, exact-role/value rendering, Tree UI, zero manual branches and Current handlers remain in use. A cold summary may not erase already received same-immutable-node night/ability detail; the shared Tree keep() now preserves those records just as it already preserved actions.

## Cancellation and lifecycle

The outer request uses the existing bounded position_stream worker and heartbeat while replay, JSON Tree requests and streamed role/value evaluation run. The original HTTP status/headers/body are framed and preserved; the UI still receives real roles/complete/error events. Closing the TCP stream sets the request-owned cooperative Event and reaches tick(), including during synchronous JSON handlers. This is not merely ignoring an obsolete result. No detached durable job registry, background-after-tab-close task, thread kill or unrelated-process operation is used.

Tests with an8second-bounded synthetic CPU loop make a real local TCP request, close it, assert CalculationCancelled plus worker-finally exit, and measure exit latency. Final run0.984s; other successful final-code boundary runs0.906/0.921/0.922/1.000s. This demonstrates the local WSGI transport, not Vercel proxy disconnect behavior. Existing work/time limits remain; unsupported replay is422, exhausted budget remainsPending/error with no complete value. Partial forecasts are never committed or cached as complete.

The transport rejects cross-origin requests, unknown routes/fields and payloads above131072bytes; existing operation bodies remain limited4096bytes. No oversized history is truncated or dropped: the caller retains its preceding valid IndexedDB state and gets an error. This finite safety limit is not proof that every future long history fits. A new deployment/version must retain a compatible signing key/recipe version; no new production key was created. The isolated runner has a clearly public fixture key for restart testing only and must not be used as a production credential.

## Scope / remaining release gates

This bounded prototype covers public Current, Table publication/preview, semantic Tree reads/selection and calculation/retry. Direct mutation routes not connected to recipe transport (including personal views and strategy/native forms) fail explicitly422 in this opt-in mode; they do not silently use an unrelated cookie/root. Personal feature expansion remains deferred. Existing nonprototype routes are unchanged. Full supported-public-form coverage needs a separate finite adapter pass before replacing the ordinary public site.

Full repository/large independent hunter oracle and prior unrelated old assertion groups were not rerun. No numerical expectations outside the resolved2contracts were edited here.
