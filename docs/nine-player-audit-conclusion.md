固定条件は[nine-player-audit-set.md](nine-player-audit-set.md)。8件を現行250000 work・20秒で計測し、近似・予算拡張・旧モデルへの切替はしていない。結果は`nine-all-benchmark.json`、圧縮前は`nine-all-baseline.json`。getter計数のオーバーヘッドを含み一般性能保証ではない。

## 偽占い2人の仕様問題

`multi-law`では偽2人のworldが可能。D1に9番を処刑、N1に8番の死体を観測すると、D2に偽1/2番が生存する非終局枝が到達可能。共通publisherへ渡すと`multiple_fake_report_correlation_unselected`となることを別に確認した。全体評価はその前にwork上限に達しており、単なる性能改善で法則を補えるわけではない。

各偽のuniform周辺分布を、独立な積として勝手に採用しない。共同法則が必要な枝のみ未対応とし、5人の終局枝など法則を必要としない既存ケースを一律に拒否しない。

## 6項目の構造面

| 項目 | 現状 |
|---|---|
| 夜の取得/死亡/遷移 | `NightFrame.after`と明示policyで共通化済み |
| 朝の報告/継続 | 共通flowと同一公開ベクトル統合、確率相関を維持 |
| 公開/本人/狼の情報所有 | 公開priorと私的payoffを分離、observer識別子とstale応答検査を維持 |
| 公開A/今日中facade | 支持範囲で完成、夜行は承認済み狼数別事前比率を維持 |
| UI/preview/API/cumulative接続 | 同一A入口へ接続済み、未対応はPending。今回画面コードの変更なし |
| 呼出/拡張/性能監査 | 本番の旧評価呼出なし。旧loop/exportは使用中の移行参照テスト用として保持。拡張点・代表限界を記録 |

**現行モデルの構造整理として残る必須の共通化作業は見つからなかった。ここを完了の区切りとする。** 全設定を予算内にすることは構造完了の条件にしない。旧solverを参照テストから分離する移動は可能だが、現在の計算を改善せず移行証拠を壊すリスクがあるため追加しない。

role marginalの再構築は重複するが、計測全体で0.027〜0.333秒に過ぎず主因ではなかった。cache化は見送り。medium専用キーとscan履歴付きjointキーは保持する情報と適用条件が違い、一本化は有益な共通化とは確認できない。同役COの名前置換は将来の性能候補だが、報告者/保留機会/私的条件の対称性検証が必要で今回は広げない。

## 次の既存要件

第一候補は狩人の段階実装。既存文書と試作の確認、未合意事項、確定世界・単一夜の入力出力とテスト骨格を[guard-single-night-contract.md](guard-single-night-contract.md)へ整理した。夜/朝flowの新設は不要。護衛の効果・死体なし進行・私的襲撃履歴/護衛履歴は**新機能の具体的な作業**であり、今回の共通化漏れとは区別する。

最初は襲撃/護衛先を外から固定し、承認済み効果resolverを注入する範囲に限定する案。自護衛/連続/複数狩や自然な方策を決め打ちしない。GJ後に狼が知る襲撃先を保持せず、初期仲間maskだけで将来の方針を選ぶ代用は不可。現行の死体なし観測は記録のみで進行不可を維持し、護衛勝率を表示しない。

第二候補は潜伏/none占い本人の未来比較。公開行動へ本人の秘密を渡さず、本人の取得/公開の扱いを定める必要がある。9人の追加性能監査は独立した候補に留め、これら既存開発を無期限に止めない。
