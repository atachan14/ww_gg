## Priority clarification: the auxiliary ledger is not algorithmically required

The user's clarification supersedes treating repeated ownership/frame checks as a permanent runtime requirement. Same-group semantics and Q/P updates are necessary; a registry repeatedly proving that an internal result still belongs to its engine is not. This increment only consolidates that registry and cleans its lifetime; it does **not** yet implement a closed calculation API or eliminate the ledger. Its runtime acceleration remains unadopted.

The code already has the right foundation: GameData and BoardData in board_flow.py are frozen, and GameRuntime owns immutable common settings and creates a new runtime for a new setup. SavedCutOutGraph.data/engine and InformationSetForecast.rules/strategy plus public cache dictionaries remain replaceable in the experimental interface. The ledger's _owner_current, _groups_record, frame comparisons and issued-generation/cache-ticket maps largely compensate for that experimental openness, rather than being prerequisites of the probability algorithm.

Next structural priority is to reuse those immutable snapshots and calculation-local cache ownership. Open one calculation from a saved BoardData plus fixed strategy/view inputs; keep its engine/caches internal; create child frames only through the existing common acquisition/filter/death/report constructors. A Board edit/recalculation opens a new calculation instead of replacing the data behind an existing internal frame. The API should not separately accept arbitrary laws/groups or foreign raw cache entries and then try to certify them. Unsupported/general legacy inputs keep the ordinary entry. Once that boundary is real, owner/configuration checks belong at the external entry, and independent group invariance/full-history/cold assertions belong in development tests, not after every internally generated child.

Removable auxiliary work then includes receipt issuance/weak registries, repeated owner/frame identity checks, generation and policy stamps, cache-proof tickets, and duplicated proof-only copies of branch weights. Preserve the actual algorithms: initial lawful joint-history generation, legal-target policy, owner-only observation filtering, normalization and event/branch/choice masses, separate public Q and actual P propagation, named group splitting/transport needed by orbit evaluation, and SavedOrigin recipes for required cold readback. Root user-input validation, zero-support errors and numerical memoization remain at their actual semantic boundaries. Do not simply switch off checks on the current mutable experimental API, nor invent a second solver or a new layer of certification objects. First close ownership by construction, then measure the same bounded tasks before claiming a benefit or extending cases.

### Mathematical construction rather than runtime certification

At an initial group-model snapshot, permutations inside equal claim classes preserve the generated initial assignment/history law. Fix every named endpoint in public ability reports. These classes are constructed from saved inputs, never supplied separately by a caller or inferred from role marginals. Let G be this partition's permutation group. Common unobserved uniform acquisition commutes with permutations. A named action/observation E refines to the subgroup fixing its endpoints; own-role/scan conditions additionally fix the owner, known result targets and selected intervention target. Wolf information fixes its roster members and attack targets conservatively. Full histories and physical weights are still carried, rather than replaced by marginals.

Q and P remain separate. Own observation conditions P while leaving public Q unchanged. Public compatibility/role-weight projection remains the existing Model-A updater; it is not replaced with a new Bayes rule. Reporting uses the existing complete-history public generation and private likelihood transfer. For wolf information cells I, actual mass is w_I=sum(P over I), and the configured target policy q_I(t) is calculated from public Q conditioned on wolf-owned I, never the viewer's secrets. Actual choice coefficient is w_I*q_I(t); physical outcome probability is applied afterward. Thus the scalar continuation is sum_I w_I sum_t q_I(t) sum_o p(o|I,t) V(Q'_{t,o},P'_{I,t,o}). Public role weights, world-internal history mixtures and physical branch/choice coefficients are not merged.

These construction reasons replace the old runtime group/owner comparisons in this route. Tests enumerate complete named output laws and each nontrivial group generator, including private observations. The live engine does not execute those comparisons.
