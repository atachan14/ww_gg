# 切り出し型：正式Model Aの初期公開priorへの小adapter

初期公開スナップショットと処刑一手に限定し、正式なCOグループ重みを参照する `ModelAInitialGroups` / `ModelAOneStepExecution` を独立追加した。単純支持条件付けの試作を実仕様へ置き換えず、別の入口・法則タグにする。通常factory・既定OFF・公開設定は変更しない。

## 正式な法則をそのまま参照する

入力は `InitialModelASpec` のみ。4/5人、狼1・狩0・霊0/1・占1/2、明示した同時初期スナップショット、既存の固定ClaimPolicy、均等方針・全公開設定、Day1の取得/公開枠1だけを受ける。任意のBoard、共同分布、game dict、入力関数、履歴や不明なCCO時機は受けない。一手評価もadapterが発行したcontextそのものだけを受け付け、任意の法則に差し替えたcontextを拒否する。占2は不足COを比較する小例に必要な初期役職数として扱い、未来の複数占い師戦略を追加するものではない。

この明示specから新しい初期入力を作り、既存の `board_roles.reconstruct_saved` と `public_prior.prepare_public_prior` を呼ぶ。前者は既存の `group_initial_board`、手入力報告の互換条件、全公開の欠落条件を適用する。後者の正式な取得priorとpastを、そのまま不変contextの参照として保持する。adapter側で再条件付け・均等化・再グループ加重・秘密履歴の追加をしない。

正式priorの役職射影とBoardの重みが一致しなければUnsupported。正式側が零支持/Pendingなら履歴を補完せずUnsupported。adapterの `update/rebuild` は旧単純支持フィルタへ進まず拒否し、変更時は新しい明示specから正式経路を再構築する。

P5だけ占CO・ClaimPolicy全条件none・市2霊1占1狼1では、正式入口のP5狼率は**1/5**。前段の単純支持試作は**1/2のまま**で、両者を混ぜない。結果の法則タグは `model_a_initial_public`。単純試作タグをModel A評価器へ、Model Aタグを単純試作へ渡しても自動変換しない。

## 構築規則から保証する範囲

1. 既存初期配役列挙は、人数制約を保つ全ラベル配置を作る。CO写像を保存する番号交換は合法な配置を全単射で移す。
2. デフォルトの騙り設定は狼だけが騙り可能。既存COグループ規則は合法な狼位置の各群へ均等質量、その群内の合法な役職補完へ均等質量を置く。上記交換は狼位置群も群内の補完も全単射で移すので、群数・補完数・各配役の質量を保存する。
3. 同じ固定対象・色・取得/公開枠の報告元集合を保持する交換は、真占にだけ適用する手入力互換条件と、全公開の欠落位置集合を保存する。騙りを真占へ固定しない。条件後の総質量も同じなので正規化重みを保存する。
4. 正式公開priorは、COした真占の観測済み取得記録を構築する。CO集合と報告条件を保存する交換は、追跡者集合・取得記録・役職・その質量も保存する。

これを根拠に、CO役職で区分し、報告対象を固定し、同じ対象/色/取得枠の報告元だけを元群内で保持する。証明用の区分構築は法則の再更新ではない。全置換・生成元交換・旧canonical keyによる上流照合へは戻らない。未知の騙り設定・番号依存方針・一般履歴へこの論証を流用しない。

## 情報保持と保証の限界

正式priorはCOした占い師を追跡する構造で、潜伏真占の未知の初期取得履歴を全展開した法則ではない。`tracked` と `observed_prefix` を正式値のまま保持し、前段試作の全真占取得生成へ置き換えない。本人の秘密法則や複数夜のadapterは未実装。

pastのオブジェクトと元の報告列順も保持する。保証は**正式な初期共同分布・明示スナップショット関係・一手枝**についてであり、旧future cacheが持つordered-past tupleのバイト単位の交換不変性や、未来報告方針まで保証したものではない。逆順で入力した報告のpastが逆順のままであることも検査する。一般のログ順を同時扱いする変換・CCOタイミングの新定義・未来cacheへの群共有は行わない。

contextの支持質量1は、参照した正規化済み正式法則全体に対する値で、COや報告が生成される確率1を意味しない。公開配役重み、世界内で正式priorが保持する秘密記録、処刑一手の物理枝質量は別に扱う。

## 独立対照と小例

再現：`python -B -m benchmarks.player_match_groups.cut_out_model_a_fixture`。新規6テスト0.204秒、共通一手コードの前段4テスト3.857秒、計10件成功（各20秒上限）。以前の全suiteとは別の検証。

独立oracleは全合法配役を列挙し、狼位置別に均等群質量→群内補完質量を明示計算する。報告/欠落条件で絞った後に**再グループ化せず**正規化し、真CO占の取得記録を付ける。正式Boardとpriorの共同質量・全役職率に一致し、群内全置換はテスト側の旧board/state serializerで確認する。adapter内で置換監査を行うコードはない。

4/5人それぞれで、単独CO、占2にCO1の不足CO、同じ対象同じ白の2CO、背景位置の片側だけが結果対象になる例、全公開結果の片側欠落を比較した。一手は全対象の既存 `action_outcomes` と比較し、質量・勝敗観測・処刑記録・生存者・完全秘密事後法則が一致した。代表による集計も全対象と一致した。

## 上流の費用も残す

各ケースで正式prior cacheをローカル測定プロセス内だけで空にし、初期入力作成/Board再構築、正式prior作成、証明による群構築、一手評価、任意のラベル変換を別記録した。群構築は法則照合0・交換監査0だが、正式な初期配役列挙とjoint作成は残る。既存の計算済み任意Boardを受ける入口はなく、上流の構築証明を伴う参照受け渡しの一般化はまだ行っていない。

P5例では名目上の初期配役60→正式支持24、保持仮説24。各処理の単発計時を証拠JSONへ別記した。極小盤面の費用内訳であり速度改善の主張ではない。証拠は `cut-out-model-a-results.json` とローカルテストログ。

通常経路・本体PlayerData・サーバー・既定OFFは変更なし。初期公開法則と一手の重み不一致を解消した区切りであり、Model A全ゲーム評価・本人秘密・一般ログ・未来公開戦略への接続完了ではない。公開・push・7人重測定も行っていない。
