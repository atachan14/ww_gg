# 探索位置のWeb接続：ローカル完成・未公開

基準: 公開版7d1999a。探索位置表示の公開・pushは行っていない。先の計測試作から、毎呼出しラップを使わず自己スタックを低頻度に採取する方式を通常の/main・COプレビュー・戦略変更後の取得・本人表へ接続した。

## 表示と入力

公開/狼本人/占い本人/狩人本人を表示し、評価中のDay・昼夜と「呼出し深さ」を示す。経路はツールチップで最大12フレーム。完了率、残時間、保存されたBoardの枝番号、全Treeではない。短時間で終わる場合と採取対象外の処理では表示しない。通常UIに大きな木は追加していない。

Board/revision/本人か公開か/runを段階応答へ結合し、CO下書きのrequest_idとブラウザの編集世代も確認する。新しい編集・視点変更・確定送信で消し、旧位置を再表示しない。roles/complete/勝率データとは分けて扱い、診断の値を勝率計算へ使わない。本人の役職・結果・護衛/襲撃先・候補配役・内部関数名は送信しない。照合用には小さいメタデータだけを保持する。

位置表示は非blockingで、CO・結果・戦略を編集できる。ブラウザのポーリング/周期タイマーを増やしていない。非表示時はDOM更新を止める。計算と通信を維持する間、サーバーの採取/heartbeatは最大1Hzで継続する。非表示を理由に計算を取消して再計算する方式ではない。

## 要求内の実行と終了

同じHTTP要求の専用workerが、同じ準備済み状態の評価を一度だけ行う。Flaskのコピーした要求コンテキスト内でgeneratorを完全に消費する。consumerはそのworker自身の実行スタックだけを最大1Hzで採取する。フレーム/locals/Board参照を保持せず、Day/昼夜だけにして破棄する。全探索木、外部サービス、永続的なjob登録、別の計算要求はない。

採取機能が利用できない場合は再試行せず位置表示だけを停止し、数値計算を継続する。内部の例外内容は送らない。

出力キューは2件に限定。元の270秒/400万workの親予算とプロセス内計算枠はworker自身が所有し、queue待ちも期限へ含める。枠を先に解放して重複計算を許さない。終わったworkerがsentinelで停止しないよう終了通知は非blocking。完了/例外/切断で採取を止め、workerのfinallyで枠を解放する。切断は次のtickで協調終了する方式で、任意のC処理を強制停止する機能ではない。2秒以内に戻らないworkerは診断へ記録し、早期に枠を明けない。通常のブラウザAbortは従来通り表示無効化と本文drainであり、実接続切断とは区別する。

現実のlocalhost HTTPを役職率受信後に切断したところ、次の要求は1.022680秒で進んだ。元の約13秒のforecast完了まで待たず枠が解放され、診断stop=cancelledを確認。pending_worker/500/Tracebackはなかった。

## 検証

- 関連129テストが31.631秒で成功。公開/本人、複数夜/GJ、cache、公開ログ・親Board編集/子孫枝退役・保存、配布、予算に加え、長時間worker、期限、例外、切断、同一要求への結合、秘密非出力を含む。
- 追加の重点34テストが5.282秒で成功。worker内の期限超過後も役職率を残し、次の要求が通ること、採取不可時は一度だけ停止すること、任意時間設定でもqueue待機が有限であることを確認。
- 遅延/故障/偽revision・runを挟むheadless Edge試験で、入力継続、再編集で旧表示を隠す、完了/失敗で消す、本人→公開で旧位置を拒否、非表示中の描画停止と位置用setIntervalゼロを確認。
- 既存の保存待ち・最新CO/結果の保存・古い要求破棄・失敗戦略の保存防止も再成功。
- 実計算でも1366px/light・390px/darkで位置が見え、入力可能なまま113/504へ更新。横はみ出し/JS例外なし。renderer TaskDurationは約0.305〜0.331秒、ScriptDurationは約0.0070〜0.0075秒、最終JS heapは約4.28〜4.40MB（peakではない）。位置の初回はページ開始から約1.15〜1.71秒。

## 再現と公開境界

python -B benchmarks/exploration_position_web_benchmark.py <baseline-or-current-tree> <result.json> [private]

通常設定で位置表示を有効にする。CALCULATION_POSITION_ENABLED=Falseなら従来の同一要求・同期iteratorへ戻せる。Vercel本番でworker/streamの寿命を検証した意味ではなく、今回のWeb接続はローカル完成まで。公開には別承認と、本番の先行/最終値・位置・切断の確認が必要。
