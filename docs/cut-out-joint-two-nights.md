# Two generated nights: opt-in source/group induction checkpoint

Parent fbaf1fa. Normal engine/factory/UI, MAX and public version are unchanged. No initial seven-player search was run.

## Reachability: why six players

Under the current H0 rules, each day executes one player, each night kills one non-wolf, and play stops when wolves are zero or reach parity. Four/five original players cannot execute a second night: the upper bounds are 4/W1=1, 5/W1=1 and 5/W2=1 night. This is checked by an exhaustive count-state reachability test, independent of role inference. No skipped execution, GJ or changed victory rule is introduced to fabricate a small example. The minimum W1 source that can reach night2 is six players.

The two-night issuer therefore admits only explicit six-player W1/S1/M0/H0 uniform test sources: P1 true seer with initial white P3, then fixed P3 execution. One case publicly names P2 wolf; another leaves its position unknown among P2/P4/P5/P6. These are new test fixtures, not new user observations. The current root is five alive at night1. Existing four/five and seven endgame one-night experiments keep their original scope.

## Structural inheritance before generation

The first NightNode uses the issued initial groups and fixed-death receipt. A second NightNode must have a trusted request actually produced by the common action policy, the original SavedOrigin/evidence prefix, and complete source equality on replay. Both Q/public and private/physical P, secret scans/results, attacks, past reports, alive roster and settings remain bound. The current public group receipt comes from prior completed acquisition/action/publication events; observer endpoints and known wolf rosters refine its private subgroup.

The producer then reads block occupancy signatures from the carried joint distribution and creates representative information/action choices with exact combinatorial multiplicities and policy sums. It never enumerates every literal information-state/action combination and then searches duplicates or player exchanges. Existing uniform/unvisited seer generation still uses its own complete history on the original target roster, including corpses. No missing history is filled or role/secret independence imposed.

For unknown-wolf public play, the first live group sizes are (1,4). At night2 they are (1,1,1), (1,2), or (3), depending on prior deaths and public reports. The (3) case retains a joint unknown-wolf occupancy and permits information/action aggregation again; a named public target or known own role fixes the relevant endpoints. Unknown public groups are never reused as an unconditional guarantee for an asymmetric P.

Label reconstruction composes transports for every ancestor action, not only the root night. It includes intermediate grouped day executions, each night's information/action choice, and labelled forced-action Table queries. Later groups fix earlier observed endpoints; chronological transport composition preserves the complete path. Terminal keys retain parent source and action as well as child state, because equal normalized terminal states can have unequal conditional probabilities.

## Independent cold restoration

Each case selects a night2 representative branch with a live true seer. It constructs a NEW plain InformationSetForecast engine with initially empty value/acquisition/publication caches and a NEW SavedOrigin using the same immutable input data. Every action/publication operation is rebound to the new engine, condition operations are cloned, and completed-step reuse is disabled for the entire replay. The cold result equals the original warm result in all public/private/physical/history fields, has two attack records, and includes three third-slot scan records, with one or two directed at players dead in the resulting Board. For the unknown-wolf cases the selected cold witness retains Q != P both before and after the terminal observation. No Forecast value is used by that cold engine.

All labelled paths are separately restored and compared using the previous helper (one generic cold sample per engine, then the exact completed-step cache); the additional cold witness is specifically second-night and independent-engine, not the previous arbitrary first-terminal sample. This is not a claim that every path is cold-rebuilt or that pure immutable validator caches were evicted.

## Remaining scope and reasons

Four/five-player two-night examples are unreachable under the unchanged rules. The six-player issuer is W1/M0/S1/H0 with fixed public CO and initial white report; W2, multiple/latent/fake seer configurations and medium/guard extensions are not inferred from it. The existing six-player Model A adapter itself is W1, and the actual W2 seven-player initial exploration is still deferred for coordination. Third generated nights, arbitrary source/likelihood edits and unproved private evidence remain unsupported. Constructor's two history-validation passes are unchanged as a separate per-node cost. No heavy seven-player, ordinary UI, MAX or external publication change was made.
