## 2. 目的と不変条件

期待勝率最大化は「設定済み継続戦略を使い、合法な各候補を本人の情報で期待値評価して最大候補/分布を選ぶ」こと。世界ごとに真役職を見てmaxした後に平均してはならない。

- 完全秘密履歴L: 全配役、占い取得、護衛、狼本人の襲撃記録、取得時生存者、公開報告の取得日/公開日を保持する。
- 公開Q: Model Aの公開配役重みと世界内秘密履歴混合。物理枝質量Pで置換しない。
- 本人B_i: 同じ公開Qを本人の役職/結果/自身行動履歴だけで条件付けする。他人の秘密や現在の他人の同時行動は渡さない。
- 物理P: 固定した実行候補と既存の能力/ルール/設定方針による実際のchance枝質量。本人の候補介入はPに作用し、公開方針Kを候補別に差し替えない。
- 全体と本人で共有する想定・方針は同じ。違うのは観測条件と介入だけ。
- 公開観測後は現行の生成支持フィルターを使う。正支持のModel A重みに生成尤度の大きさを追加乗算しない。真の物理Pの条件付けとは別処理。
- 既存GameRules（自護衛なし、連続護衛は設定値）、既存の均等取得/護衛/報告、旧maxの契約を保持する。

方針決定の利得は U_i(a;K) = Σ_h B_i(h) Σ_z P(z | h, a, K) u_i(z)。一方、全体/本人Tableの表示利得は、保持した実際の条件付き物理法則P_viewを使って固定Kを評価する。DecisionValueとDisplayValueを型/呼出しで区別し、表示用の本人介入や物理重みを方針順位へ渡さない。狼の村利得最小化と陣営勝率最大化の補数関係は、同じ測度・同じ候補値の中でだけ使う。

数値は既存のFractionを基準とする。正規化前後の質量、合法分布の総和1、全同率候補の個数、terminal/by-dawn質量を厳密に検査する。将来の非一様混合を採用する場合も、近似ソルバーの結果をそのまま厳密証明として使わず、合理的係数の小問題なら有理数で偏差条件を再検証する。一般に正確な混合が有理数で表現できるとは仮定せず、表現できない場合の数値契約は別途明示する。
## 3. 共通処理の境界

| 部品 | 入力/出力 | 再利用する既存部品 |
|---|---|---|
| 情報集合 | L/Q + 本人の許された記録 -> B_i | actor_information / private_adapter |
| 合法手生成 | 物理盤面、ルール、本人履歴 -> 候補集合 | legal_targets / guard_choices / candidates |
| 候補評価 | Q/P/L、完全方針K、候補介入 -> 厳密利得・枝・必要依存 | action_flow / night_acquisition / guard_model / morning_flow |
| 観測条件付け | 完全Kの全公開infosetから生成した支持 + 観測 -> Q'、別にP' | public_observation_support / observe_root_public |
| 方針選択 | 全候補の完成した厳密値 -> best responses と設定済み同率処理 | optimal_targets / uniform_policy |
| 方針の閉包 | 候補評価から要求された方針依存 -> 証明付き全体Kまたは理由付き未解決 | 新規の共通調停層。物理モデルは増やさない |
| 同型再利用 | 全公開/本人/物理入力、設定、候補、観測者、K識別子、証明モード -> scalar/cache key | exact_renaming |

「計算が重いから」「狩人例だけだから」という理由で別の勝敗モデルを作らない。能力処理の中で最適化したり、方針選択の中で秘密履歴を補完したりしない。

## 4. ③: 候補評価と方針依存を分ける

候補評価器は常に指定された完全PolicyProfileを使う。未知のmax方針が必要なら依存を返し、その場で再帰的に同じ方針を作り直さない。候補ごとの一時的なkernelの差替えも禁止する。

PolicyProfileのキーは actor + 情報集合 + 決定時点。同じ狼陣営の共有初期roster/本人襲撃記録は現行どおり一つの狼行動主体であり、狼人数だけ独立した別主体にしない。

評価結果は ExactActionValue と Dependencies を分離する。完成前の値、未評価候補を0とした部分ベクトル、暫定kernelを通常cacheへ入れない。全候補の値と合法性が完成して初めて既存best-response集計へ渡す。

依存グラフは、方針選択、候補期待値、公開観測支持、後続方針をノードとして明示する。非循環部分は従来の後ろ向き評価。循環成分（SCC）は共通閉包器へ渡す。同じ公開入力を再要求した事実を検出し、再帰上限到達を仕様未定義と混同しない。

## 5. 昼max / 狼max / GJ支持の実例

市民2・狩人1・狼1、P1狩人CO（真偽未確定、ClaimPolicy none）、P4処刑後のNight1、護衛均等、連続護衛あり。狼の3情報集合にそれぞれ合法2択があり、現行の「最大候補全てを同率均等」に従う方針候補は3^3=27個。

既存共通評価で、全合法候補を同じ完全公開kernelの下で評価した。完全評価できた中で整合したkernelは、各infosetが合法2択を各1/2で選ぶもの。W1本人の両候補の村利得は1/6、W2/W3本人の候補は全て0。6個のkernel候補は public_generated_observation_zero_support で停止した。

この結果は「全ての盤面で解が存在する/一意」の証明ではない。証拠は task-6/day-max-four-kernel-probe.py/.json。

依存は K_wolf -> GJ生成公開支持 -> 公開Q'における昼max -> 狼候補利得 -> K_wolf。同時に現場で行動するという意味の循環とは別で、戦略から推論することによる評価依存である。先にどちらかを均等に固定して結果を返すことはしない。

小さいSCCでは現行同率規則に許される完全kernel候補を列挙し、同じKの下で全候補/全infosetを共通評価してbest-response一致を検証する案が成立する。大きいSCCでは依存分割、完全入力同型、支持クラスの厳密共有で探索を削減する。最初に見つけた解を黙って採用したり、未検証の反復収束を厳密解としたりしない。候補数・作業量には明示的な上限を設け、打切りはUnprovenで返す。反復は候補を作る補助としては使えても、最善応答・全支持・解選択の証明を代替しない。完全方針の指紋はcacheへ含め、同型再利用時は方針内の主体/候補IDも同じ全単射で写す。

## 6. ④: 同時行動の共通設計

同時段階では各主体の情報を段階開始時点で固定し、全intentを揃えてから既存物理遷移を適用する。相手の今夜の護衛/襲撃/取得結果を見て自分の行動を選べない。死亡前取得と公開報告の時点は既存night_acquisition / morning_flowの順序をそのまま使う。

既存の均等護衛×狼襲撃は既存の共同生成則を維持する。将来の複数max主体では、単独maxを順番に呼んだ結果を「相互最大化」と呼ばない。各主体の情報集合と効用で、同じjoint profileに対する偏差利得を全て検証する必要がある。

共同ランダム化の法則は明示する。周辺の方針分布だけでは共同分布は定まらない。既存の複数偽報告相関未選択を、勝手な独立積で埋めない。狼陣営の一体行動、既存の独立真占い取得、将来の別主体の戦略的混合は区別する。

### 同率均等と一般の混合均衡は同じ契約ではない

将来の相互最大化を一般の混合Nashに置き換えると、現行「同率最善手は全て均等」と衝突する場合がある。数理部品の例（実在ww盤面としては未確認）で、村利得行列 [[1,0],[0,1/2]] のゼロ和ゲームは純粋均衡がなく、混合均衡は両主体とも第1手1/3・第2手2/3となる。各主体の全同率手を1/2ずつにする制約ではこの均衡を表現できない。

したがって、将来の相互maxについて「現行同率均等を制約として守る」か「均衡を支える非一様混合を別戦略として許す」かはユーザー判断事項。今回はどちらも新規採用しない。実際のww盤面から該当利得表を抽出できた時点で、候補値/情報集合/共同法則を添えて判断を求める。単なる数理例を実盤面の再現結果と取り違えない。

## 7. ゼロ支持・複数解・未解決を区別する

| 結果 | 意味 | 現時点の扱い |
|---|---|---|
| CertifiedProfile | 完全Kに全合法偏差を評価し、現行選択規則との一致を証明 | 証明範囲と一意性の有無を別に保持 |
| MultipleCertifiedProfiles | 異なる整合Kがある | 任意の解を選ばない。解集合/値域を診断へ、通常の単一値はPending |
| NoAdmissibleProfile | 選択済み規則の下で許される完全解がないと証明 | Pending。均等化/新均衡規則へ置換しない |
| UndefinedObservation | 必要な観測の公開生成支持がゼロ | 最小盤面・kernel・介入・Q/P支持を診断。任意beliefを作らない |
| UndefinedJointLaw | 初日偽報告/複数偽報告相関など生成則自体が未選択 | 既存Pendingを保持。仕様選択が必要 |
| BudgetExceeded / Unproven | 探索や証明が未完了 | 不存在・複数解・仕様矛盾の証明とは呼ばない |

公開Qが正なのに必要秘密支持ゼロ、または公開観測の支持が全てゼロの場合、一律補完はしない。物理終局枝は既存の終局処理、続行には必要な公開条件が定義されていることを要求する。off-pathをepsilon確率で救うことは新しい観測/精緻化規則なので未採用。
