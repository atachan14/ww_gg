# Seven-player branch growth: code and small-counter audit

No heavy initial search or numerical strategy changes. Probe: the actual public uniform root, two literal deaths (execute P3, attack P4), then one report-generation stage. solve/act throw if invoked. A three-second calculation budget covers the probe. Exchange enumeration is a test oracle only, not a production matching route.

## What already aggregates

CutOutUniformEngine.solve selects group representatives BEFORE action_flow: day weights are group size / live count; night weights sum configured target probabilities inside the legal part of each private group. act caches by representative, and the final labelled action table requests individual values through that cache. There is no general expansion back to every individual immediately after grouping.

Initial groups are {1,2}/{3}/{4}/{5,6,7}, so the seven live day targets already become four representative continuations. Executing singleton P3 and attacking singleton P4 do not split the two remaining live blocks. Acquisition is symmetric and does not publicly fix every secret target. Each of six wolf information sets has four legal targets, already reduced to three private target representatives with policy masses 1/4,1/4,1/2.

The 60-second attempt's 132,695 requests/evaluations versus 132,691 completed scalar cache entries indicate many distinct unfinished context/action combinations, not merely final-table requests redoing scalar actions. The count alone cannot identify the global dominant cause; the observations below identify specific duplication opportunities.

## Measured local opportunities, not speed claims

1. **Joint wolf-information/action orbit**: six information sets x three current representatives = 18 continuation calls. The full 24 literal (initial wolf roster, legal target) pairs occupy three orbits under {1,2} and {5,6,7}, with total masses 1/4,1/4,1/2. This suggests evaluating three joint representatives before creating continuation branches rather than independently entering all six private loops. Current test establishes the finite descriptor/mass count only; full physical/readback/Table equivalence still needs a prototype.
2. **Joint simultaneous report-vector orbit**: 64 named vectors occupy 13 inherited-label orbits. The test checks 768 transports for both exact vector probability and the complete public actor-history law, not only role marginals. Orbit masses are saved and must not be replaced with uniform weights. Child Board construction currently occurs once per named vector, so constructing representatives from an event-pattern generator before Boards/descendants is the larger reporting opportunity.
3. **Preserve symmetric reporter block**: seven of the 64 vectors retain P1/P2 symmetry but the generic endpoint fixer splits them. Fixing only that issue changes the sum of live target representatives across outputs from 276 to 269, so it is useful groundwork but not the large improvement by itself. Other outputs' named target/equality patterns justify finer blocks. No production change is made in this audit.

## Implementable next stage and required guarantees

Start with an explicit public-uniform joint wolf-information/action prototype on this tiny prefix, then <=5-live endgames. Construct orbit descriptors from inherited blocks, initial-roster membership counts and fixed attack-history endpoints BEFORE action_flow. Carry one representative plus total exact selection mass and explicit label transports. Do not run canonical matching or enumerate all world permutations in the runtime. Unsupported partial evidence or unknown correlation must retain the existing conservative path.

Admission requires a bound source/owner/revision and an induction certificate that BOTH public Q and physical/private P (including role rosters, acquisitions, attacks and relevant observer evidence) commute with the proposed transports. A public block alone is insufficient when P is already conditional on one wolf roster. Legal self-exclusion and configured uniform strategy must commute; compare mass sums for complete info/action pairs, not independent marginals. Any observed/viewer endpoint restricts the admissible group first. The event/resolution projection and terminal/continuing observations must commute as well.

Then derive simultaneous report patterns from per-reporter histories and equality relations between targets inside inherited blocks, before concrete labelled vector/Board enumeration. Keep true/fake correlations within each world/secret history and use the unchanged policy weights. A batch/provenance receipt must distinguish simultaneous same-meaning rows from sequential/single or asymmetric edits. Carry conditional observation likelihoods and label transports so P weights and labelled Table/action/joint rows can be restored. Public branch mass times orbit cardinality alone is unsafe for a viewer-conditioned P. Never merge histories merely because their role marginals or scalar values agree.
