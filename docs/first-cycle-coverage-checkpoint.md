# 初期7人UNIFORM：初昼・初夜の対応表と観測遷移の共通化

対象は既存の実入力を day/night/fake_reports のみ明示的にUNIFORM化したもの。市3/霊1/占1/狼2/狩0、P1/P2占CO・初日P4白、P3霊CO。初期の公開6配役・秘密6状態と設定済みルールは変更していない。勝率探索、通常UI/HELP/MAX、外部公開、初期入口の高速経路設定は変更していない。

## 対応率は層を分ける

- 最初の昼の処刑7択、続く夜の異なる生存者6択で、公開ラベル付き合法履歴は42。初期群で見ると14構造類。
- 6世界 ×7処刑 ×6襲撃候補 =252世界内枝のうち、180が合法。狼本人への襲撃72枝は設定済み「自噛みなし」により正当な対象外。既に処刑された人を襲撃する7ラベル履歴も対象外。
- 観測された夜襲撃の混合Q/Pを、所有元・実際の昼イベントと結んで保証した既存の検証入口は3履歴。今回の共通入口で42/42に拡張した。物理到達質量は従来検証入口1/10から1へ。
- **報告の生成前構造集約は2/42履歴（4.76%、物理質量19/280 ≈6.79%）のまま。** 今回のイベント証明を報告集約の新規対応として数えない。38履歴は構造保証不足。残る2履歴はP1/P2双方が死亡し、占い報告集約そのものが不要な正当な対象外（物理質量1/35）。適用対象40履歴だけを分母にすれば2/40=5%。
- 初期7人全探索への自動高速ディスパッチは引き続きOFF。新入口はローカル試作の第一周期イベント用であり、通常の初期ソルバーへ自動接続したという意味ではない。

## 最大の不足群を一つ一般化

公開上まだ非狼と確定していない人（SまたはL）が襲撃される履歴は30/42、物理到達質量3/5で最大。単なる「その対象を強制的に襲撃する介入」と、実際にその人が死亡したという観測を混同できない。

新しいobserved_choiceは、昼の所有済みイベントから得た全P仮説について、対象が狼なら0、非狼なら設定済み均等チーム方針1/(生存数−生存狼数)を掛けて混合する。正規化後のPを既存ActionEvidenceへ渡し、公開Qは既存public_children/condition_night_corpseの「適合性のみ」の更新を使う。新しい役職モデル・一律補完・未定義最適行動は追加しない。狼2人が各自独立に襲撃する確率を掛ける処理でもない。

最小例：P1処刑→P2襲撃では、P2が狼となる生存狼2のクラス全体が観測で消える。Q/Pとも残存狼1、襲撃の物理確率1/10。死ぬ直前の真占P2の取得結果は秘密履歴に残る。別例のP5処刑→P1襲撃では、残存狼1の公開Q重み1/3に対し物理P重み2/7となり、昼夜の枝質量は1/60。数クラスを介入前の比率のまま保つ更新ではこの結果にならない。

対応区分は手動リストだけで決めず、42履歴すべてで既存のsingle/joint producerの実guardを試し、受理された2履歴では集約出力と完全なQ/Pを再比較している。処刑・襲撃端点から細分した群も、全42履歴で宣言済み群の生成交換に対する完全Q/P・Board不変性を検証した。群は事後分布から探索して作り直していない。

全42履歴の新しい共同sourceを、独立した旧チーム情報群の列挙＋通常カーネル＋fresh SavedOriginでcold復元し、全Q/P・取得・攻撃・死亡・過去報告が一致した。さらに別カーネル間で翌朝の全1,452公開枝と完全な私有分布を比較して一致。solve/actは明示的に禁止し、全初期勝率探索は行っていない。

## 証拠・次の境界

実行：python -m benchmarks.player_match_groups.cut_out_first_cycle_coverage

全列挙5.150221秒、ピーク34,656,256 bytes。比較30秒・worker120秒・1.5GBの上限内。関連18テストが成功。反復死亡・不正所有元・コピー・古いrevision・別方針は拒否する。既存single/two-reporter helperは共通の第一周期source発行を再利用するが、未保証の報告を既存報告モデルへ無理に渡すことはない。

次の大きな報告側の不足は、生存霊と両占COが残る12履歴である。霊の黒/白により狼数・真偽支持・偽報告候補を先に更新し、端点で細分した群から共同報告パターンを作る証明が必要。他の38履歴を「正当な対象外」として切り捨てたり、今回の42 source一致を報告最適化の100%対応と読み替えたりしない。
