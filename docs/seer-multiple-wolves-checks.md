# 占い比較の複数狼・公開狼数不確定への拡張（2026-10-13）

基準: `b12df1dbe529f06f927545e5e27f684e4e98fbc2`。ローカル開発のみ。

## 変更

生存狼数が1匹であることを要求する一律の条件を外した。CO済み・すべて開示・現在の取得履歴が揃う範囲で、複数生存狼と公開狼数不確定も比較できる。

公開側と観測者側のjoint取得分布を別々に持ち、同じ公開方針の固定行動を両方へ適用する。公開の候補評価、同値の均等化、未来の偽占い・霊能報告指示には公開分布だけを使う。観測者の配役分布を公開forecastへ渡さない。

夜の指定襲撃は、既存 `action_outcomes` をそれぞれの分布に適用し、それぞれの狼数別priorと合法襲撃正規化を維持する。公開側の襲撃後分布を条件付けるだけでは、観測者が既に知る真の役職により狼数priorが変わってしまうケースがある。回帰では観測者の1匹／2匹priorが1/2ずつで、公開側の襲撃後が1/3／2/3でも、観測者側は1/2／1/2を保つことを確認した。

昼の処刑と終局も、それぞれの分布で既存の勝敗判定を使う。観測者側の終局枝はその確率で勝敗に加算し、継続枝だけを次へ送る。公開側の枝を観測者の秘密で削って公開方針を変えない。

未来の報告は公開側の既存生成器で作る。同じ役職・取得記録の仮説ごとに、その公開報告の生成尤度を観測者の分布へ適用し直す。したがって公開の偽占い方針を、真占い師の秘密で変更しない。報告後の観測者枝の確率合計が1であることも確認する。

## 指定された5人例

市民2・占い師1・狼2、初日占いnormal、自噛みなし。Player1とPlayer2が占いCOし、両方ともDay1にPlayer3白を公開。昼max・夜random・すべて開示。

- D1昼にPlayer1を処刑して未決着のD1夜へ進んだ場合、占い視点Player2・秘密Day1 Player3白で、占い先Player4とPlayer5はそれぞれ村7/8（87.5%）、狼1/8（12.5%）。この継続Boardは生存狼1匹である。初期狼2匹の設定を生存狼2匹と混同しない。
- D1昼にPlayer3を処刑すると、両COの真結果によりPlayer3は非狼であり、4人生存・狼2匹で全枝が狼勝利となる。D1夜の占い比較画面を作らず結果画面へ進む。

公開Cookie・ログ・配役状態は占い視点の計算前後で不変。実Edgeで上の数値と結果画面への分岐を確認した。

## 複数生存狼と狼数不確定の検証

7人・初期狼2・占い1、占いCO Player1、初日占いなし、Player7処刑後のD1夜を使用した。

- 公開候補を狼Player2・3、真占いPlayer1にした場合、実際に生存狼2匹のBoardで占い先別の数値を返す。
- 狼Player2・3が1/4、狼Player2・4が1/4、狼Player2・7が1/2の公開候補では、生存狼数は1匹／2匹が半々のBoardであり、数値を返す。仮の固定値を返す専用処理は入れていない。
- 別の真／偽COが混じる公開候補で、観測者の狼数priorと公開priorが違う場合の襲撃正規化を検証した。

実UIからも、市民4・占い1・狼2の7人でPlayer1占いCO（Day1 Player3白）、Player2狼CO、昼夜maxを設定した。Player7処刑後は公開生存狼1匹が25%、2匹が75%で、占い先Player2・4・5・6は村50%／狼50%。同じ公開設定で白のPlayer3を処刑すると生存狼2匹が確定し、占い先Player2・4・5・6・7は村1/3／狼2/3となる。両方を実Edgeで確認した。

## 残る具体的な論点

公開方針の襲撃指示が、本人の条件付き分布のある狼数仮説では必ず仲間を狙う場合、同じ指示を合法に実施できない。既存の指定襲撃モデルの前提がその観測者条件で成立しないため、この場合だけ未計算にする。

例えば、公開側では真占いPlayer1なら狼Player3、偽占いPlayer1なら狼Player1という候補が残り、公開方針がPlayer3を襲撃候補に含める場合、真占い師の条件下ではPlayer3を噛めない。これを回帰にした。実際の狼がどの秘密情報を使って代替対象を選ぶか、またその行動選択を公開の尤度として扱うかは、新しい戦略仕様である。今回、秘密に基づく候補の差し替えや公開方針の変更は導入しない。

なし開示での本人の秘密活用、潜伏からの将来CO、複数偽占いの共同報告モデル、公開取得履歴不足、予算超過も従来どおり未対応／未計算。公開勝率や0で代用しない。狩人能力は対象外のまま。
