# 用語集(案)

2026-10-30 に、要件・仕様の詰め直しの最初として作り始めた**案**。用語の意味だけを書く。仕様の中身は [rules.md](rules.md)(ゲームのルール)と [calculation.md](calculation.md)(計算の定義)に書く。ユーザーと確かめながら直していく。確定した用語には「確定」と書く。

- 「今の使われ方」は、今のコード・画面・旧 docs での使われ方。参考であり、定義ではない。
- 画面の名前(GameCast、BoardStrategy など)は、2026-10-09 にユーザーが確定したもの(`archive/20261029/backlog.md`)。

## 1. ゲーム

| 用語 | 意味(案) | 今の使われ方・メモ |
|---|---|---|
| **Game** | 1回のゲーム全体。配役とルールで決まり、ゲームの途中では変わらない | 確定済みの名前(Session への改名は不採用) |
| **配役**(GameCast) | 役職ごとの人数 | 確定済みの名前 |
| **ルール**(GameRule) | ゲーム中に変わらない決まり。自噛み、初日の占い、連続護衛、同票のときの処理、投票結果の公開など | 確定済みの名前。投票結果(誰が誰に入れたか)は「公開/非公開」を切り替えられるようにする。既定は公開(2026-10-31 に非公開から変更) |
| **プレイヤー** | ゲームの参加者。番号(1, 2, …)で区別する | 名前も付けられる |
| **役職** | 市民、占い師、霊能、狩人、人狼、狂人(v1) | 狂人は今のコードにない。v2 以降の予定は [rules.md](rules.md) の「役職の構造」 |
| **陣営** | 勝ったときに一緒に勝つ役職の集まり。v1 は村陣営(市民・占い師・霊能・狩人)と狼陣営(人狼・狂人) | 「数え方」「グループ」と分けた(2026-10-30、[rules.md](rules.md)) |
| **数え方** | 勝敗の判定で、何として数えるか。狼 / 人間 / 数えない(狐) | 案(2026-10-30) |
| **グループ** | 互いを知り、行動を一緒に決める集まり。v1 は狼グループ(人狼)。襲撃は狼グループの能力 | 案(2026-10-30)。「人狼」は役職名、「狼」は数え方とグループの名前 |
| **人間** | 数え方が人間のプレイヤー。v1 では人狼以外(狂人も人間) | 勝敗の判定に使う |
| **人外** | 村陣営でないプレイヤー | |
| **白人外** | 占い・霊能の結果が白の人外。v1 では狂人 | |
| **狂人** | 狼陣営だが人間。占い・霊能の結果は白。狂人は人狼が誰かを知らず、人狼も狂人が誰かを知らない | 確定(2026-10-30) |
| **日・Phase** | 「1日目の昼」「1日目の夜」のような時点。Phase は昼と夜の2つ。夜の結果(死体、報告)は、次の日の昼の始まりに含める | 確定(2026-10-30)。必要になれば「朝」を足す可能性はあるが、見込みはほぼない |
| **決着** | 勝つ陣営が決まること。v1 では、狼が0人なら村陣営の勝ち、狼の数が人間の数以上なら狼陣営の勝ち | 処刑の直後・襲撃の直後に判定する。v2 の狐は上書きする([rules.md](rules.md)) |

## 2. 行動と情報

| 用語 | 意味(案) | 今の使われ方・メモ |
|---|---|---|
| **行動** | 処刑、投票、襲撃、占い、護衛、CO、能力結果の報告 | |
| **CO** | 役職を名乗ること。名乗っていない状態は「潜伏」 | |
| **騙り** | 本当の役職と違う役職を名乗ること | |
| **騙れる役職** | 役職ごとに、騙ってよい役職を決める戦略。どの役職でも設定できる。「すべて」は文字どおりすべてで、人狼CO・狂人COも含む。例: 市民が「すべて」なら、市民も人狼と同じように騙っている可能性を含めて計算する。人狼が「なし」なら、人狼は騙らないとして計算する | 確定(2026-10-30)。v1 の既定は、人狼と狂人が「すべて」、村陣営は「なし」 |
| **投票** | 処刑先を決めるための、各プレイヤーの票。票は Board の枝にせず、処刑先の確率(分数)として計算する | 方針 2026-10-31([rules.md](rules.md) の「投票」) |
| **指定** | 候補の中から、全員が同じ人に投票すること(同率なら共有のくじ)。v1 は公開の視点で決まるので、指定する人も指定先という項目も要らない | 2026-10-31 |
| **グレラン** | 候補の中から、各自が独立に投票すること(同率なら各自のくじ) | v2 以降の予定(2026-10-31) |
| **PP**(パワープレイ) | 人外の票で、処刑先を押し切ること | 専用の仕組みは作らず、投票の結果として起こるものとして扱う。その確率も処刑先の分数に入る(2026-10-31)。v1 では狂人の票が要る |
| **RPP**(ランダムパワープレイ) | ルールが「同票のときは、最多得票者からランダムに処刑する」の場合に、同票に持ち込んで処刑先を確率で決めること | |
| **能力結果** | 占い・霊能で得た白黒。本人だけが知る | |
| **報告** | 能力結果を公開すること。偽の報告もある | |
| **公開情報** | 全員が知っていること。生死、CO、報告、処刑先、夜の死体 | |
| **秘密の情報** | 一部の人だけが知っていること。本当の役職、狼の仲間、自分の能力結果、護衛先、襲撃先 | |

## 3. 盤面と Tree

## 4. 計算

| 用語 | 意味(案) | 今の使われ方・メモ |
|---|---|---|
| **世界**(配役の候補) | 誰がどの役職かの割り当ての1つ。公開情報と矛盾しないものをすべて、重み付きで持つ | 今のコードでは worlds |
| **役職率** | 各プレイヤーが各役職である確率。世界の重みを足したもの。世界の重みには、公開情報と矛盾しないことに加えて、**戦略から読める情報**も入れる | 画面の BoardPlayerTable に出ている。戦略から読める情報を入れることは確定(2026-10-30)。起こりやすさまで読む(暫定 2026-10-30)。[calculation.md](calculation.md) の「役職率」 |
| **戦略**(BoardStrategy) | 全員が従うと仮定する方針。Board ごとに持つ。戦略はすべて共有されていて、全員が知っている | 確定済みの名前。個人の行動を予測するものではない。「個人戦略」という概念はなくした(2026-10-30) |
| **順序付きの絞り込み** | 戦略の項目を順序付きで持ち、候補が1人になるまで順に絞り込む。最後は等確率(または最大化)で選ぶ。例(仮): 「占い位置: 未占い > 未確定の位置 > 潜伏 > 等確率」。条件に合う候補がいなければ、その段は飛ばす | 仕様として残す(2026-10-30)。今の UI にもある(占い位置「未占い → 均等化」、偽占い方針「破綻しない報告 → 均等化」など、`static/strategy.js` の `ordered`)。重さを抑えるため、多くの項目の既定値をこの形にして、最大化は確かめたいときに切り替える方向 |
| **一致グループ** | 立場が同じで、名前を入れ替えても確率が変わらない候補やプレイヤーをまとめて、一度だけ計算すること | 今の実装では試作で通常は OFF([../PERFORMANCE.md](../PERFORMANCE.md))。グレランの票の数え方にも使える見込み(2026-10-31) |
| **既定開示・既定行動・盤面評価** | 戦略の項目の種類。既定開示は自動更新で公開情報を生む(CO、報告など)。既定行動は秘密の行動の枝を生む(襲撃、護衛、占い)。盤面評価は役職率の読み方を決める。1つの項目は1つの種類だけを持つ | 確定(2026-10-30)。[calculation.md](calculation.md) の「戦略」 |
| **偽の判定** | 盤面評価の項目。「既定開示に従わなかったら偽」なら、その役職なら従ったはずの行動をしていない候補を、その役職である候補から除く | 確定(2026-10-30)。「真偽の判定」とは呼ばない |
| **騙るタイミング** | 騙る役職ごとの既定開示の項目。人狼のように情報を共有する役職は人数も指定する(例: 初日に1人) | 案(2026-10-30) |
| **最大化** | 行動の候補から、勝率が最大のものを選ぶ戦略。同率の候補は等確率で選ぶ | 確定(2026-10-30)。旧名 max、期待勝率最大化。UI 上の表記は後で調整するかもしれない |
| **等確率** | 行動の候補から、等確率で選ぶ戦略 | 確定(2026-10-30)。旧名 random、均等化。random は乱数のシミュレーションと紛らわしいので使わない |
| **勝率** | 各陣営が勝つ確率。分岐をすべて評価した厳密な値 | 「期待勝率」とも |
| **行動ごとの勝率** | 処刑先・襲撃先などを1つに決めた場合の勝率 | |
| **視点** | 誰の立場で確率・勝率を見るか。全体(公開情報だけ)か、特定のプレイヤー(その人の秘密の情報も使う) | v1 では対応外でもよい(2026-10-30) |
| **重み付けの考え方** | 今の計算は、戦略が決める「起こり得る/起こり得ない」(1 と 0)と、理由のない候補を等確率にすることだけで確率を作る。人の感覚による重み付け(「この人は狂人っぽい」など)は入れない | 2026-10-30 ユーザーと整理。確率論では、等確率にする考え方は「理由不十分の原則」(無差別の原理)、場合の数で確率を出すのは「古典的確率」(ラプラスの定義)と呼ばれる。人の感覚の重みを入れるのは「主観確率」。将来は、人の感覚による重み付けもできる厳密計算に広げたい |
| **等確率にする単位** | 理由不十分の原則は、何を等確率とみなすかで答えが変わる。初期値は「COグループ方式」: 騙れる別役職を持つ役職の位置の組み合わせ(誰が真か)を先に等確率にし、その中で残る配役を等確率にする(`archive/20261029/co-group-model.md`) | 確定(2026-10-30)。余裕ができたら、ほかの単位(配役の1つ1つを等確率にする、など)での計算もおまけで実装したい |
| **未計算** | 計算の上限に達して、値が出ていないこと。0% や途中の値で代わりにしない | |
