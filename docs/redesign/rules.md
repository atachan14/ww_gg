# ゲームのルール(案)

作り直しに向けて、ユーザーと詰めているゲームのルールの下書き(2026-10-30 開始)。用語は [glossary.md](glossary.md)、計算の定義は [calculation.md](calculation.md)。今のコードのルールは [../spec/game-model.md](../spec/game-model.md)。

## 役職の構造

v1 は最低限の目標で、v2 以降への拡張に備えた構造を v1 の時点で想定しておく(2026-10-30 ユーザー)。

- **方針(確定 2026-10-30)**: 役職を名前で決め打ちしない。性質の組み合わせとして表す。今のコードはそうなっていない(配役の候補を「人狼・霊能・占い師・狩人の位置」で持ち、役職名が計算の芯に埋め込まれている)。
- 性質の案:
  - どの陣営と一緒に勝つか
  - 勝敗の判定での数え方(人狼として/人間として/数えない)
  - 占い・霊能の結果(白/黒/そのほか)
  - 誰を知っているか(仲間の人狼、狂信者が知る人狼など)
  - 能力(襲撃、占い、護衛など)
  - 特殊な性質(占われると死ぬ、襲撃されても死なない、道連れ、など)
- v1 の配役: 市民3・占い師1・霊能1・狩人1・人狼2・狂人1(9人)まで。
- v2 以降の予定: まず狐と猫又。その後、パン屋、黒猫、そのほかの特殊役職、最大20人。さらに、いろいろな種類の狼と白人外(人狼ジャッジメントのローカルの特殊役職: 強欲な人狼、賢狼、狂信者、サイコなど)。
- 検討中: 狼と白人外で陣営を分けたほうが扱いやすい気もする。同じ狼陣営として扱う場面もある一方で、勝敗の判定では白人外を狼の数に入れない。

### 陣営・数え方・グループ(案 2026-10-30)

役職の「仲間」を、意味の違う3つに分ける。

| 概念 | 意味 | v1 | v2 の例 |
|---|---|---|---|
| **陣営** | 誰と一緒に勝つか | 村(市民・占い師・霊能・狩人)、狼(人狼・狂人) | 狐(狐) |
| **数え方** | 勝敗の判定で、何として数えるか | 狼(人狼)、人間(それ以外) | 狐は数えない |
| **グループ** | 互いを知り、行動を一緒に決める集まり。グループの能力を持つ | 狼(人狼) | 賢狼・強欲な人狼も狼グループ。狂信者は狼グループを知るが、狼グループからは知られない |

- 「人狼」は役職名、「狼」は数え方とグループの名前にする(ユーザー 2026-10-30)。
- 狂人は、陣営は狼、数え方は人間、グループはなし。白人外と狼の違い(勝敗の判定で狼に数えない、仲間を知らない)は、陣営ではなく数え方とグループで表す。
  - 狂人陣営を別に作り、勝利条件を「狼陣営の勝利」とする案もある(ユーザー 2026-10-30)。その場合、陣営の勝率が狐なしでも3つになる(狂人陣営の勝率は狼陣営と常に同じ)。上の3つの分け方なら、陣営を増やさずに同じ区別ができる。
- 襲撃は、役職個人の能力ではなく、**狼グループの能力**にする(ユーザー 2026-10-30)。厳密には、狼だけで噛み投票を行い、その結果で襲撃先が決まる。v1 では、グループで1人を選ぶだけにする(噛み投票は含めない)。
- 人外・白人外は呼び名: 人外 = 陣営が村でない。白人外 = 人外で、占いの結果が白。

### 勝利条件

陣営ごとに持つ。処刑の直後・襲撃の直後に判定する。

| 陣営 | 条件 |
|---|---|
| 村 | 狼(数え方)が0人 |
| 狼 | 狼の数 ≥ 人間の数(狐は数えない) |
| 狐(v2) | 村か狼の勝利が決まったときに、狐が生きている。村・狼の勝利を上書きする |

例(ユーザー 2026-10-30): 人間2・狼2・狐1 の盤面では、人間2・狼2 で狼の勝利が決まり、狐が生きているので狐の勝利に上書きされる。

### 性質の一覧

| 性質 | 値 |
|---|---|
| 陣営 | 村 / 狼 / (v2)狐 |
| 数え方 | 狼 / 人間 / 数えない |
| グループ | なし / 狼 |
| 知っているグループ | なし / 狼(狂信者。相手からは知られない) |
| 占いの結果・霊能の結果 | 白 / 黒 |
| 個人の夜の能力 | なし / 占い / 護衛 |
| 処刑先の結果を得る | する / しない(霊能) |
| グループの能力 | 狼: 毎晩1人を襲撃 |
| 能力の修正 | (v2)賢狼: 襲撃に成功した相手の役職を知る。強欲な人狼: ゲーム中に一度だけ、追加でもう1人襲撃できる |
| 特殊な性質 | (v2)占われると死ぬ、襲撃で死なない、死んだときに道連れ、能力の対象になると無効にして相手を襲撃死させる、など |

- 騙れる役職・騙るタイミングなどは、役職の性質ではなく戦略(既定値は役職ごとに持つ)。

### v2 の役職

| 役職 | 内容(ユーザー 2026-10-30、狐・猫又・パン屋・狂信者は一般的なルールでの想定) | 足す性質 |
|---|---|---|
| 狐 | 狐陣営、数えない。占われると死ぬ(呪殺)。襲撃で死なない | 陣営と勝利条件、特殊な性質2つ |
| 猫又 | 村陣営。処刑されるとランダムに1人、襲撃されるとランダムに狼1人を道連れ | 死んだときの効果(死に方ごと) |
| パン屋 | 村陣営。生きている間、朝にパンが届く(公開情報) | 生きている間に毎日起こる公開情報 |
| 狂信者 | 狼陣営、人間、占いは白。狼グループを知る(狼グループからは知られない) | 知っているグループ |
| 黒猫 | 狼陣営、人間(狂人の一種)。処刑されたときに、狼以外からランダムに1人を道連れ | 死んだときの効果 |
| 賢狼 | 狼グループ。襲撃に成功した相手の本当の役職が分かる | 能力の修正(秘密の情報が増える) |
| 強欲な人狼 | 狼グループ。ゲーム中に一度だけ、追加でもう1人襲撃できる | 能力の修正(グループの能力の回数) |
| サイコ | 狼陣営、人間(狂人の一種)。占い・護衛・襲撃などの能力の対象になると、その能力を無効にして、相手を襲撃死させる | 特殊な性質 |

- 確認したいこと:
  - サイコを狼グループが襲撃したとき、狼のうち誰が死ぬか(襲撃を実行した狼をどう決めるか)。
  - 黒猫の「狼以外」に狂人などの白人外は含まれるか(数え方が人間なら含まれる、で合っているか)。

## ルール(GameRule)の項目

今のコードの項目(自噛み、初日の占い、連続護衛)に加えて:

- 同票のときの処理(例: 最多得票者からランダムに処刑する → RPP が起こり得る)
- 投票結果(誰が誰に入れたか)の公開: 公開/非公開。既定は非公開(確定 2026-10-30)

## 投票(検討中)

- 以前の経緯: 狂人を含めた PP・RPP を表すために、個人の視点での投票を計算に含める案があった。v1 では投票を実装せずに簡略化したルールで表すか、判断を先送りにしていた。採用する可能性があるなら、早めに組み込むべきかもしれない。
- 狂人を表すには、「全員が同じ処刑先に投票する」では足りない(2026-10-30 ユーザー)。狂人は村に投票し、さらに狼と票を合わせる必要がある。
  - CO して投票先を宣言する必要がある場合や、狼が CO する場合がある。CO しなくても票を合わせられる状況もある。
  - そもそも PP が可能かどうかの判断が必要。
  - 村も、狂人を含む PP を防ぐために人外を騙ることがある(内訳上は PP が可能でも、狂人の視点では狼が 1/2 になる、など)。
- 進め方(ユーザー 2026-10-30): 最大化の前に、決め打ちの戦略から始める。例: 「投票位置: 村陣営率最大」「CO のタイミング: 狼陣営 > 村陣営」。最大化には後で対応する。
- 宣言と指示: 投票先を事前に宣言することも、盤面の情報に含める。自分の「宣言」とは別に、仲間に促す「指示」の欄が要るかは検討が必要。
- UI の案: 能力結果の欄と同じように、投票結果の欄で公開できるようにする。未来の日を指定すると、事前の宣言を表す(能力の対象の宣言も同じ)。
- 狂人の判断(ユーザー 2026-10-30): 狂人は、公開情報に加えて「自分が狂人である」ことを使って判断する。公開情報だけでも狼の生存数は絞れ、確定することもある。狂人の視点ではさらに絞れる。
  - 例: 9人の配役で、狂人が潜伏し、初日に占い2・霊能2・潜伏5になる。戦略で村の騙りがない前提だと、狂人の視点では、占いと霊能に狼が1人ずついる。その後、潜伏から4人が死に、狂人が生き残ると、PP が成り立つ。霊能や占いが潜伏に黒を出していれば、狂人の視点で真偽がつき、投票先も合わせられる。狼の視点では狂人の生死が分からないことも、狂人には分かる。そこで、狂人が生存を報告して PP を行う。
  - 視点の表を v1 で表示しなくても、狂人の行動は「狂人が知っていることが同じ状況」ごとに決める必要がある(今の人狼の襲撃と同じ考え方)。CO のタイミングの戦略と同じ仕組みで、狂人の視点の状況ごとに枝が分かれる。
- PP のタイミングの最大化(ユーザー 2026-10-30): 「PP を行う」の勝率(成功する確率と、失敗したときの勝率を含む)と、「行わない」の勝率を比べて選ぶ。
- 投票の最大化と均衡: 多人数の投票では、1人が票を変えても結果が変わらない投票は、どれもナッシュ均衡になる(全員が同じ人に入れる、など)。ナッシュ均衡だけでは投票先が決まらない。陣営どうしの対戦として扱う必要があるが、狂人は人狼を知らないなど、同じ陣営の中でも知っていることが違うので、計算は難しい。
- 発展した案:
  - 指定による投票(例: 確定した霊能者を指定者とし、その視点で全員の投票先を指定する)
  - グレラン(主に潜伏者を範囲として、各自が自由に投票する)
  - v2 以降: 複雑な投票の指示(市長、ギャンブラーなど、複数票を持つ役職を交えて投票させ、真偽によって吊り先を分岐させる)
