# ゲームのルール(案)

作り直しに向けて、ユーザーと詰めているゲームのルールの下書き(2026-10-30 開始)。用語は [glossary.md](glossary.md)、計算の定義は [calculation.md](calculation.md)。今のコードのルールは [../spec/game-model.md](../spec/game-model.md)。

## 役職の構造

v1 は最低限の目標で、v2 以降への拡張に備えた構造を v1 の時点で想定しておく(2026-10-30 ユーザー)。

- **方針(確定 2026-10-30)**: 役職を名前で決め打ちしない。性質の組み合わせとして表す。今のコードはそうなっていない(配役の候補を「人狼・霊能・占い師・狩人の位置」で持ち、役職名が計算の芯に埋め込まれている)。
- 性質の案:
  - どの陣営と一緒に勝つか
  - 勝敗の判定での数え方(人狼として/人間として/数えない)
  - 占い・霊能の結果(白/黒/そのほか)
  - 誰を知っているか(仲間の人狼、狂信者が知る人狼など)
  - 能力(襲撃、占い、護衛など)
  - 特殊な性質(占われると死ぬ、襲撃されても死なない、道連れ、など)
- v1 の配役: 市民3・占い師1・霊能1・狩人1・人狼2・狂人1(9人)まで。
- v2 以降の予定: まず狐と猫又。その後、パン屋、黒猫、そのほかの特殊役職、最大20人。さらに、いろいろな種類の狼と白人外(人狼ジャッジメントのローカルの特殊役職: 強欲な人狼、賢狼、狂信者、サイコなど)。
- 検討中: 狼と白人外で陣営を分けたほうが扱いやすい気もする。同じ狼陣営として扱う場面もある一方で、勝敗の判定では白人外を狼の数に入れない。

### 陣営・数え方・グループ(確定 2026-10-30)

役職の「仲間」を、意味の違う3つに分ける。

| 概念 | 意味 | v1 | v2 の例 |
|---|---|---|---|
| **陣営** | 誰と一緒に勝つか | 村(市民・占い師・霊能・狩人)、狼(人狼・狂人) | 狐(狐) |
| **数え方** | 勝敗の判定で、何として数えるか | 狼(人狼)、人間(それ以外) | 狐は数えない |
| **グループ** | 互いを知り、行動を一緒に決める集まり。グループの能力を持つ | 狼(人狼) | 賢狼・強欲な人狼も狼グループ。狂信者は狼グループを知るが、狼グループからは知られない |

- 「人狼」は役職名、「狼」は数え方とグループの名前にする(ユーザー 2026-10-30)。
- 狂人は、陣営は狼、数え方は人間、グループはなし。白人外と狼の違い(勝敗の判定で狼に数えない、仲間を知らない)は、陣営ではなく数え方とグループで表す。
  - 狂人陣営は作らない(確定 2026-10-30)。狂人陣営を作って勝利条件を「狼陣営の勝利」にする案もあったが、狐なしでも勝率が3つになり、狂人陣営の勝率は狼陣営と常に同じになる。3つの分け方なら、陣営を増やさずに同じ区別ができる。
- 襲撃は、役職個人の能力ではなく、**狼グループの能力**にする(ユーザー 2026-10-30)。厳密には、狼だけで噛み投票を行い、その結果で襲撃先が決まる。v1 では、グループで1人を選ぶだけにする(噛み投票は含めない)。
- 人外・白人外は呼び名: 人外 = 陣営が村でない。白人外 = 人外で、占いの結果が白。

### 勝利条件

陣営ごとに持つ。処刑の直後・襲撃の直後に判定する。

| 陣営 | 条件 |
|---|---|
| 村 | 狼(数え方)が0人 |
| 狼 | 狼の数 ≥ 人間の数(狐は数えない) |
| 狐(v2) | 村か狼の勝利が決まったときに、狐が生きている。村・狼の勝利を上書きする |

例(ユーザー 2026-10-30): 人間2・狼2・狐1 の盤面では、人間2・狼2 で狼の勝利が決まり、狐が生きているので狐の勝利に上書きされる。

### 性質の一覧

| 性質 | 値 |
|---|---|
| 陣営 | 村 / 狼 / (v2)狐 |
| 数え方 | 狼 / 人間 / 数えない |
| グループ | なし / 狼 |
| 知っているグループ | なし / 狼(狂信者。相手からは知られない) |
| 占いの結果・霊能の結果 | 白 / 黒 |
| 個人の夜の能力 | なし / 占い / 護衛 |
| 処刑先の結果を得る | する / しない(霊能) |
| グループの能力 | 狼: 毎晩1人を襲撃 |
| 能力の修正 | (v2)賢狼: 襲撃に成功した相手の役職を知る。強欲な人狼: ゲーム中に一度だけ、追加でもう1人襲撃できる |
| 特殊な性質 | (v2)占われると死ぬ、襲撃で死なない、死んだときに道連れ、能力の対象になると無効にして相手を襲撃死させる、など |

- 騙れる役職・騙るタイミングなどは、役職の性質ではなく戦略(既定値は役職ごとに持つ)。

### v2 の役職

| 役職 | 内容(ユーザー 2026-10-30、狐・猫又・パン屋・狂信者は一般的なルールでの想定) | 足す性質 |
|---|---|---|
| 狐 | 狐陣営、数えない。占われると死ぬ(呪殺)。襲撃で死なない | 陣営と勝利条件、特殊な性質2つ |
| 猫又 | 村陣営。処刑されるとランダムに1人、襲撃されるとランダムに狼1人を道連れ | 死んだときの効果(死に方ごと) |

| 狂信者 | 狼陣営、人間、占いは白。狼グループを知る(狼グループからは知られない) | 知っているグループ |
| 黒猫 | 狼陣営、人間(狂人の一種)。処刑されたときに、数え方が狼でない人(白人外・狐も含む)からランダムに1人を道連れ | 死んだときの効果 |
| 賢狼 | 狼グループ。襲撃に成功した相手の本当の役職が分かる | 能力の修正(秘密の情報が増える) |
| 強欲な人狼 | 狼グループ。ゲーム中に一度だけ、追加でもう1人襲撃できる | 能力の修正(グループの能力の回数) |
| サイコ | 狼陣営、人間(狂人の一種)。占い・護衛・襲撃などの能力の対象になると、その能力を無効にして、相手を襲撃死させる。狼グループに襲撃されたときは、ランダムな狼が死ぬ | 特殊な性質 |

- この表し方で、ほかに想定している役職も表せそう(ユーザー 2026-10-30)。

## ルール(GameRule)の項目

ゲーム中に変わらない決まり。TOP で決め、Game ごとに持つ。

### v1 で選べる項目(案 2026-10-30)

| 項目 | 選択肢 | 既定 | 出どころ |
|---|---|---|---|
| 自噛み(狼が狼を襲撃) | 許可 / 不許可 | 不許可 | 今のコード |
| 初日の占い | あり / ランダム白 / なし | ランダム白 | 今のコード |

### 決まっていて選べない項目(v1)

今のコードの前提を、v1 では固定にする(2026-10-30。投票以外はユーザーの異論なし)。

| 1日目の夜の襲撃 | あり |
| 狩人の自分の護衛 | できない |

## 投票(検討中)

### 拡張に備えた形(案 2026-10-30)

v1 は「全員1票、自投票なし」だが、v2 以降の拡張ができる形だけ v1 で用意しておく(ユーザー 2026-10-30)。

- 投票は、各プレイヤーの行動として持つ: 「誰に、何票入れるか」。
- 票数は、役職の性質とそのプレイヤーの状態から決まる。v1 は全員1。
  - 市長(v2): 票数が2という性質。
  - ギャンブラー(v2): 投票ごとに「溜める/投票する」を選ぶ。溜めた票数を状態として持ち、投票するときにまとめて入れる。
- 投票できる相手は、ルールで決まる。v1 は「生きている自分以外」。自投票の許可はルールの項目として足せる。
- 処刑先は、票を集計して決める。最多得票者が複数なら、同票のときの処理(v1 はランダム)。

### 投票の考え方(方針 2026-10-31)

- **PP という専用の仕組みは作らない。** 投票は、各プレイヤーの既定行動(秘密の行動の枝)として持つ。処刑先は、全員の票の集計と同票のときの処理で決まる。
- PP・RPP は、人外の票が村の票以上で、しかも投票先が重なったときに、結果として起こるもの。勝敗は今の決着判定のまま(処刑の後、夜と勝利判定に進む)。
- v1 では狼だけでは PP できない(狼の数が人間の数以上になった時点で狼の勝ちが決まるため)。PP・RPP には狂人の票が要る。
- **狂人と人狼は対称に扱う**(ユーザー 2026-10-31)。人狼も狂人を知らない。どちらが相手を見つけやすいかは盤面次第(狂人が占いを騙って人狼に白を出せば、人狼の視点で狂人が確定する。逆も同じ)。なので、どちらかが宣言する形にはせず、どちらも自分の視点の絞り込みで投票位置を決める。
- 投票結果が非公開なら、村と違う人に入れても、過半数に足りなければ処刑先は変わらず、損がない。なので、人外が黙って確定村に票を合わせる暗黙の PP が、宣言もタイミングの判断もなしにそのまま表せる。
- 投票先の宣言(未来の日の投票結果の開示)は、後から既定開示として足す。そのときは、投票位置の絞り込みに「宣言先 >」の段を足す。仕組みは増えない。
- 決着判定に「生存している人外が過半数なら PP」を足す案(ユーザー 2026-10-31): 内訳ごとに票を合わせられるかまで計算すれば、共通のロジックにはできる。ただ、「票を合わせられるか」を決めるには、誰が誰に入れるかの決まりが要り、それは投票の戦略そのもの。投票を後から入れるとこの判定は置き換わるので、投票の形で始める。

### 指定とグレラン

- 指定: 候補の中から、全員が同じ人に入れる(同率なら共有のくじで1人に決める)。グレラン: 各自が独立に選ぶ(同率なら各自のくじ)。違いは同率の割り方。
- **v1 の指定先は、公開の視点で決める**(今の昼の処刑の最大化)。公開情報と戦略は全員が知っているので、全員が同じ指定先を計算でき、指定する人(指定者)は要らない。
- 指定者を決めるのは難しい(ユーザー 2026-10-31)。確定村がいない、複数いる、確定した占い師が結果を伏せている(伏せた結果に応じて占い師が指定するべき)、確定していない人どうしの指定が競合する(A・B の視点では C・D の偽が確定し、C・D の視点では A・B の偽が確定していて、E の視点ではどちらも 1/2)、など。ユーザーの叩き台:

  ```
  村陣営 > 指定可能者: 確定村 > 公開の視点の確定村
  村陣営 > 指定者: 秘密の情報を持つ人 > 役職者 > グループ化
  村陣営 > 指定先: 処刑時の村の勝率が最大 > 等確率
  村陣営 > 投票位置(既定行動): 指定先 > 処刑時の村の勝率が最大 > 等確率
  狼陣営 > 指定可能者: PP が可能なときの確定した狼陣営 > 村陣営に合わせる
  狼陣営 > 指定者: 秘密の情報を持つ人 > 役職者 > グループ化
  狼陣営 > 指定先: 処刑時の狼の勝率が最大 > 等確率(指定者に選ばれなかったら公開されない)
  狼陣営 > 投票位置(既定行動): 指定先 > 村に合わせる
  ```

  - 指定可能者の範囲や価値がプレイヤーごとに違うと、決め方が分からなくなる。v2 以降で、指定を「宣言」(既定開示)として扱う方向で考え直す。秘密の情報を持つ人の指定は、その人の宣言(公開情報)になり、ほかの人は投票位置の「宣言先 >」で従う。

### v1 の投票の戦略(案 2026-10-31)

| 項目 | 種類 | 選択肢(案) | 既定(案) |
|---|---|---|---|
| 村陣営 > 投票位置 | 既定行動 | 順序付きの絞り込み | 指定先 > 処刑時の村の勝率が最大 > 等確率 |
| 人狼・狂人 > 投票位置 | 既定行動 | 順序付きの絞り込み(自分の視点) / 指定先に合わせる | 自分の視点の絞り込み(例: 確定村 > 村陣営の率が最大 > 等確率) |

- 指定先: 公開の視点で、処刑したときの村の勝率が最大の人(同率なら共有のくじ)。
- 順序付きの絞り込み(確認 2026-10-31): 段ごとに、対象が0人ならその段は使わずに次へ、1人なら確定、2人以上ならそこまで絞って次へ。最後は等確率。
  - 自投票はできないので、指定された本人は「指定先」の段が0人になり、次の段に進む。
- 人外の既定値は、既定のルール(投票結果は非公開)に合わせて自分の視点の絞り込みにする(ユーザー 2026-10-31)。投票結果を公開にすると、村と違う投票が見えるので、そのままでは不自然になる。ルールに応じて戦略の既定値を変えるか、ルールと戦略を組にしたテンプレートにするかは、使ってみて再検討。
- 重さ: v1 は村が全員で指定先に入れるので、票が分かれるのは人外の3人だけ。
- v1 では扱わない: グレラン(v2 で「村陣営 > 投票位置」の選択肢として足す)、投票先の宣言、指定者、投票結果が公開のときの読み方、村が人外を騙って PP を防ぐ、ライン切り(人外の絞り込みの選択肢として足せる)。

### グレランの計算(v2 以降の見込み)

- 例(ユーザー 2026-10-31): 9人が全員潜伏でグレラン、自投票なし。狼以外の7人は、自分以外の8人から等確率で選ぶ。狼の2人は相方を避けて、残りの7人から選ぶ。
  - 狼のどちらかが吊られる確率は、全員が等確率に選ぶなら 2/9(約 22.2%)。狼が相方を避けると 7459171/44040192(約 16.9%)に下がる(1人ずつの票の組み合わせを数えて、厳密に計算した)。
  - 狼に入る票の数の平均(2/8×7 + 0/7×2 = 7/4 票)は、吊られる確率そのものではない。吊られる確率は、最多得票と同票の処理まで数える必要がある。
- **一致グループで軽くできる。** 立場が同じで、入れ替えても確率が変わらないプレイヤーは、票の状態をまとめて数えられる。この例では、立場を「村か狼か」と「もう投票したか」で分けると、票の状態の数が、1人ずつ区別した 24,230 通りから最大 156 通りに減り、同じ値になった。
- 例2(ユーザー 2026-10-31): 霊能が確定し、残り8人が全員潜伏で、投票が見えないとき、人外が常に霊能に入れると、グレランの票が割れれば確定した霊能を吊れることがある。ただし、霊能を狙うより潜伏を狙うほうが勝率が高い場合もある。こうした人外の選び方は、投票位置の絞り込みの選択肢で表す。

### これまでの検討メモ(2026-10-30)

2026-10-31 の方針で置き換えた案を含む(狂人が宣言して狼が合わせる案、PP の宣言のタイミングなどの項目)。

- 以前の経緯: 狂人を含めた PP・RPP を表すために、個人の視点での投票を計算に含める案があった。v1 では投票を実装せずに簡略化したルールで表すか、判断を先送りにしていた。採用する可能性があるなら、早めに組み込むべきかもしれない。
- 狂人を表すには、「全員が同じ処刑先に投票する」では足りない(2026-10-30 ユーザー)。狂人は村に投票し、さらに狼と票を合わせる必要がある。
  - CO して投票先を宣言する必要がある場合や、狼が CO する場合がある。CO しなくても票を合わせられる状況もある。
  - そもそも PP が可能かどうかの判断が必要。
  - 村も、狂人を含む PP を防ぐために人外を騙ることがある(内訳上は PP が可能でも、狂人の視点では狼が 1/2 になる、など)。
- 進め方(ユーザー 2026-10-30): 最大化の前に、決め打ちの戦略から始める。例: 「投票位置: 村陣営率最大」「CO のタイミング: 狼陣営 > 村陣営」。最大化には後で対応する。
- 宣言と指示: 投票先を事前に宣言することも、盤面の情報に含める。自分の「宣言」とは別に、仲間に促す「指示」の欄が要るかは検討が必要。
- UI の案: 能力結果の欄と同じように、投票結果の欄で公開できるようにする。未来の日を指定すると、事前の宣言を表す(能力の対象の宣言も同じ)。
- 狂人の判断(ユーザー 2026-10-30): 狂人は、公開情報に加えて「自分が狂人である」ことを使って判断する。公開情報だけでも狼の生存数は絞れ、確定することもある。狂人の視点ではさらに絞れる。
  - 例: 9人の配役で、狂人が潜伏し、初日に占い2・霊能2・潜伏5になる。戦略で村の騙りがない前提だと、狂人の視点では、占いと霊能に狼が1人ずついる。その後、潜伏から4人が死に、狂人が生き残ると、PP が成り立つ。霊能や占いが潜伏に黒を出していれば、狂人の視点で真偽がつき、投票先も合わせられる。狼の視点では狂人の生死が分からないことも、狂人には分かる。そこで、狂人が生存を報告して PP を行う。
  - 視点の表を v1 で表示しなくても、狂人の行動は「狂人が知っていることが同じ状況」ごとに決める必要がある(今の人狼の襲撃と同じ考え方)。CO のタイミングの戦略と同じ仕組みで、狂人の視点の状況ごとに枝が分かれる。
- PP のタイミングの最大化(ユーザー 2026-10-30): 「PP を行う」の勝率(成功する確率と、失敗したときの勝率を含む)と、「行わない」の勝率を比べて選ぶ。
- 投票の最大化と均衡: 多人数の投票では、1人が票を変えても結果が変わらない投票は、どれもナッシュ均衡になる(全員が同じ人に入れる、など)。ナッシュ均衡だけでは投票先が決まらない。陣営どうしの対戦として扱う必要があるが、狂人は人狼を知らないなど、同じ陣営の中でも知っていることが違うので、計算は難しい。
- 発展した案:
  - 指定による投票(例: 確定した霊能者を指定者とし、その視点で全員の投票先を指定する)
  - グレラン(主に潜伏者を範囲として、各自が自由に投票する)
  - v2 以降: 複雑な投票の指示(市長、ギャンブラーなど、複数票を持つ役職を交えて投票させ、真偽によって吊り先を分岐させる)
