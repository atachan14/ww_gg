# v0.7 の計算の芯(設計)

[scope.md](scope.md) の v0.7 の試作の設計。定義は [calculation.md](calculation.md)、用語は [glossary.md](glossary.md)。コードは `wwcore/`、開発用のテストは `tests/test_wwcore.py`、独立の計算は `tests/wwcore_oracle.py`。今の版の画面からは使っていない。

## 入口

`evaluate(Board)` が、役職率・勝率・行動ごとの勝率・行動ごとの決着の確率・枝を返す。`read_roles(Board)` は役職率だけを返す。`read_board(Board)` は、未来を計算せずに分かるもの(役職率、段階、列の枝、決着の確率)を返す。Board は、配役・ルール・戦略と、公開の記録(盤面更新の列、処刑、襲撃)でできている。どの Board も、記録を初めから読むだけで単独で計算できる。

## 役職率の式

世界 w は、役職の割り当てと、占い師の記憶(これまでの占い先と、まだ1列目を過ぎていない昨夜の結果)。Board の重みは、次を順に掛けて正規化する。

1. **最初の重み(COグループ方式)**: 1日目の最初の列の CO から、CO可能性に合う狼の位置を等確率にし、その中で残りの配置を等確率にする。
2. **初日の占い**: 「あり」は自分以外から均等、「ランダム白」は自分以外の人間から均等、「なし」は何もしない。
3. **CO**: 本物か、CO可能性の範囲の狼でなければ 0。それ以外は 1(自由な CO は起こりやすさを読まない)。
4. **報告** R(A が T を c と報告): A が名乗った役職なら、記憶(霊能なら処刑)と合うときだけ 1。A が偽なら、`E[R] = (A が真の重みのうち、R が真の結果と合う重み) / (A が真の重み)` を掛ける。合う重みが 0 なら A は偽と確定するので 1 を掛ける。同じ列の報告は、列の前の重みで E を測るので、順番によらない。
   - A の真率は報告で動かない(真の側は合う割合に、偽の側は同じ割合になる)。
5. **約束**: 対抗飽和が前の列までに起きていれば、生きている本物は CO 済みでなければ 0。その日の1列目は、昨夜の結果が黒なのに CO・黒の開示がなければ 0。空の列(更新なし)も同じ。
6. **処刑**: 掛けるものはない。決着する世界を除く。
7. **夜**: 噛みは候補の人数分の1(自噛みなしなら生きている人間の数)を掛け、決着する世界を除く。占い師が生きていれば、占い先は自分以外の夜の始めに生きていた人から均等(以前と同じ人も含む)。

## 勝率の式

世界ごとの村の勝率 `outcome(b, w)` を、後ろの Board から順に決める。

- **昼の更新**: w から、約束と想定で列を作る。本物の報告は記憶のとおり。偽の報告は、ここで読み方と別に `fake_report` の絞り込みで選ぶ。
- **処刑**: 候補 x ごとに `Σ rate_b(w) · outcome(w, x 処刑)` を比べ、最大の人から等確率。
- **噛み**: 狼は仲間の位置だけを知る。同じ位置の世界の中で `Σ rate_b(w) · outcome(w, y 噛み)` が最小(狼の勝率が最大)の人から等確率。占いは同じ夜に想定の絞り込みで選ぶ。
- **Board の勝率**: `Σ rate_b(w) · outcome(b, w)`。

処刑と噛みの選び方は、その Board の役職率で決まる。`outcome` は世界ごとに持ち、どう来たかによらない。これが「Board ごとに解く」の実装で、ゲーム全体の均衡は計算しない。

行動ごとの決着の確率は、その Board の役職率で、その行動の直後に村・狼が勝つ世界の割合(噛みは、その人を噛める世界で正規化する)。子の Board は決着しなかった世界だけを読むので、画面では親の行動の側に決着の確率を出す。すべての世界で決着する行動の子は、Board として計算しない。

行動ごとの勝率は、その行動を1つに決めた場合の値。処刑は `Σ rate_b(w) · outcome(w, x 処刑)`。噛みは、その人を噛める世界だけで正規化する。

## 一致グループ

Board の記録の中で、2人を入れ替えても記録が変わらないなら、その2人は同じ立場。この関係は同値関係なので、プレイヤーの分割(グループ)になる。

**状態はグループごとの人数で持つ**: 役職 × 占い師の記憶(未占い、占い済み、昨夜の結果)の種類ごとの人数。1つの状態の重みは、その人数に合う割り当て全部の合計。

**同値の理由**: 配役の候補の重みも、行動の決め方も、公開の記録と役職だけで決まり、プレイヤーの名前を使わない。なので記録が変わらない入れ替えで、重みも `outcome` も変わらない。

| 操作 | 内容 |
|---|---|
| 切り出し | 記録に名前が出る人を、グループから1人ずつ取り出す。種類 k が c 人いるグループ(n 人)なら、確率 c/n で k。 |
| まとめ | 次の Board で同じ立場の人を、人数の和にまとめる。重みと `outcome` は同じ立場の中で変わらないので、足すだけでよい。 |
| 名前の付け替え | 記録が同じになるよう番号を振り直して、Board を使い回す。振り方が違って別の Board のままでも、遅くなるだけで値は変わらない。 |
| 代表の列 | グループ内の名前の付け替えで同じになる列は、1つの列にして確率を足す。状態はその付け替えで変わらないので、子の状態も同じ。 |

処刑や噛みの候補は、グループの代表だけ計算する。同率なら、人数の分だけ確率を配る。

## v0.7 で決めたこと(定義にない細部)

下は [calculation.md](calculation.md) に書いていなかったところで、試作のために決めた。画面で見られるようになってから、ケースごとに確かめて、必要なら直す(ユーザー 2026-11-03)。

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 配役 | 占い師・霊能は各1人まで | v0.7 の範囲で足りる。複数にすると記憶の持ち方が変わる |
| COグループの合法性 | 配役と CO可能性だけで見る。約束は次の項目で条件付ける | 約束には期限があり、最初の列ではまだ守る時間が残っている |
| スナップショットの範囲 | 1日目の**最初の列**の CO だけ。後の CO は条件付け | 「盤面更新の順番も公開情報」。旧 co-group-model の「後の CO で配り直さない」と同じ |
| 占い位置の「未確定」 | 公開の役職率で狼率が 0 でも 1 でもない人 | 順序「未確定 > 未占い」に意味があるのは、公開の値のとき(本人の視点なら未確定は未占いに含まれる) |
| 占い位置の「片白」 | 白の報告がちょうど1つで、黒の報告がない人 | 一般的な意味のまま |
| 読むときの占い先 | 以前と同じ人も含めて均等 | 「ルールの範囲で均等」 |
| 偽の報告の候補 | 夜の始めに生きていた、自分以外で、まだ報告していない人 × 白黒。残らなければ報告済みも含める | 今の版と同じ |
| 破綻しない報告 | 今の Board に、報告者が真で、昨夜の結果がその対象・色の世界が残っている報告(霊能は処刑先の色) | 今の版の `noncontradictory` と同じ。候補がなければ飛ばす |
| CO 前の結果 | CO したときの黒以外は開示しない。CO 後に得た結果だけ開示する | calculation.md の「CO より前の結果は含めない」 |
| 自動の更新がない盤面 | どの世界でも更新が起きないなら、同じ Board のまま閉じる | calculation.md の「1つの Board にまとめる」 |
| 手動の記録の処刑 | 空の列なしに処刑が書かれたら、空の列があったものとして読む | 昼は更新なしで閉じるから |

## 自由な CO と約束の読み

書いてある読み方(自由な CO は範囲だけを見る)のままにする(ユーザー 2026-11-03「たぶんあってる」)。CO可能性が「狼陣営: すべて」なら、BoardC で霊能 CO した人が狼である世界が読みに残る。

- CO可能性が「なし」のとき: BoardC で X の狼率は 1。子の平均は 2/7 で親と合う。
- CO可能性が「すべて」のとき: BoardC で X の狼率は **1/3**。枝の確率(8/35、27/35)と BoardE(2/27)は変わらないが、子の平均は 8/35 × 1/3 + 27/35 × 2/27 = 2/15 で、親の 2/7 と合わない。

理由は、枝は想定で作る(狼の自由な CO は自動では起こらない)のに、読みでは狼の CO を掛け算 1 で許すから。`tests/test_wwcore.py` の `test_board_c_when_wolves_may_claim` が、この値を記録している。

## 答え合わせ

`tests/wwcore_oracle.py` は、グループも切り出しも使わず、すべての役職の割り当てを1人ずつ数える別の実装。Board の使い回しは、記録に出た順に名前を振り直すだけにしている。`wwcore` と共有しているのは入力の Board だけ。

- 配役6種 × 設定9種 × 公開の記録の組み合わせで、役職率・勝率・行動ごとの勝率が分数で完全に一致する。
- 自動の枝をたどって、途中の Board を cold で計算し直しても一致する。
- 7人のケースが一致する([../PERFORMANCE.md](../PERFORMANCE.md))。
- 名前付きの結果: 7/15、2/7、12/35、8/35、27/35、2/27、占いの例の 1/2、旧 co-group-model の表(2/9、2/9、8/21、1/2)。

同じ人が同じ理解で書いているので、定義そのものの読み違いはこの照合では見つからない。定義の確認は、名前付きの結果と上の「v0.7 で決めたこと」のレビューで行う。
