# 計算の定義(案)

作り直す計算の芯の定義の下書き(2026-10-30 ユーザーと詰めた)。用語は [glossary.md](glossary.md)、ゲームのルールは [rules.md](rules.md)。決めた経緯は [../USER_NOTES.md](../USER_NOTES.md) と Git の履歴にある。「暫定」と書いたものは、実機テストで確かめながら見直す。

## 1. 重み付けの考え方

- 確率は、戦略が決める「起こり得る/起こり得ない」(1 と 0)と、区別する理由のない候補を等確率にすることだけで作る。人の感覚による重み付け(「この人は狂人っぽい」など)は入れない。
  - 確率論の呼び名: 等確率にする考え方は「理由不十分の原則」(無差別の原理)、場合の数で確率を出すのは「古典的確率」(ラプラスの定義)。人の感覚の重みは「主観確率」。
  - 将来は、人の感覚による重み付けもできる厳密計算に広げたい(ユーザー)。
  - 戦略に確率を書く設定(例: 「初日に占いを騙る確率 xx%」)も、分数で厳密に計算できる。将来の応用として足せる。
- 等確率にする単位: 何を等確率とみなすかで答えが変わる。初期値は **COグループ方式**(確定 2026-10-30)。騙れる別役職を持つ役職の位置の組み合わせ(誰が真か)を先に等確率にし、その中で残る配役を等確率にする(`../archive/20261029/co-group-model.md`)。ほかの単位(配役の1つ1つを等確率にする、など)は、余裕ができたらおまけで実装する。

## 2. 役職率(戦略から読める情報)

戦略はすべて共有されていて、全員が知っている。なので、戦略から読める情報も役職率に入れる(確定 2026-10-30)。

- **読み方(暫定 2026-10-30)**: 配役の候補ごとに、戦略に従ったときにその公開情報が起こる確率を掛ける(厳密なベイズの更新)。
- **偽の報告と対象の選び方は、真と同じ分布にする(暫定)**。「真と同じ分布」は、公開情報から見て「その人が真なら、その対象でその結果が出る確率」で測る。こうすると、白黒の結果だけでは真率が動かない。
  - 例: 占い CO が A と B(真率 50%/50%)。A が、内訳「市民2・人狼1」のグループの C を占って「黒」と報告した。

    | 読み方 | A の真率 |
    |---|---|
    | 起こり得るかだけ(起こりやすさを掛けない) | 1/4 |
    | 起こりやすさまで読む、偽は白黒を 1/2 | 2/5 |
    | 起こりやすさまで読む、偽は真と同じ分布(この例では黒 1/3) | 1/2 |

  - 以前に直した問題(2日目に CO した A と、1日目の夜の死体 D が真の候補): A が真の候補には「その占い先を選ぶ確率 × 結果が本当にそうか(1 か 0)」、D が真の候補(A は偽)には「真と同じ選び方でその占い先を選ぶ確率 × 真と同じ分布でその結果を出す確率」が掛かる。両方に同じものが掛かるので、報告だけでは真率は動かない。以前は片側にだけ掛けていたために、A の真率が不当に下がった。襲撃の確率は、D が占い師かどうかで変わらない(狼は占い師を知らない)。
- **手動更新でも自動更新でも同じに読む**(ユーザー 2026-10-30)。Board は公開情報と戦略だけで決まるので、同じ Board なら、どう作られたかに関係なく役職率は同じ。
  - CO は、騙れる役職の範囲で起こり得るかだけを見る。騙るタイミングは読まない。どの役職が騙ったかの重みは、等確率にする単位(COグループ方式)に従う。
- 起こり得る候補がなくなったら、盤面が戦略と矛盾していると表示する(未計算と同じく、値で代わりにしない)。
- **Tree の親子**:
  - 手動更新で作った子の Board は、分岐の確率 0% の新しい Board として扱う。親の勝率は、自動更新の枝だけから作る(ユーザーの記憶。今の実装と合っているかは未確認)。
  - 厳密なベイズなので、親の勝率は「子の勝率を分岐の確率で平均したもの」と基本的に一致する。役職率と分岐の確率を別々に持たなくてよい(今のコードの複雑さの一因が消える。[../design-review-20261030.md](../design-review-20261030.md))。
  - 例外: 自動更新を生む戦略のうち読まない項目(騙るタイミングなど)があると、その分だけずれる。仕様として受け入れる。
- 今の結果(7人のケースの 89/224 など)と値が変わってよい(ユーザー 2026-10-30)。

## 3. 戦略

- 戦略は Board ごとに持ち、すべて共有。個人戦略という概念はない(確定 2026-10-30)。
- 各役職は、その人が知っていることだけで行動を決める(今の人狼の襲撃と同じ)。狂人の PP の例は [rules.md](rules.md)。

### 項目の種類

1つの項目は、次のどれか1つだけを持つ(確定 2026-10-30)。

| 種類 | 何を決めるか | 例 |
|---|---|---|
| 既定開示 | 自動更新で生まれる公開情報(CO、報告、投票、宣言) | CO のタイミング、CO 後の結果の開示、騙るタイミング |
| 既定行動 | 秘密の行動の枝(襲撃、護衛、占い) | 占い位置、護衛位置、襲撃位置 |
| 盤面評価 | 役職率の読み方 | 騙れる役職 |

```
霊能 > CO のタイミング(既定開示): 対抗飽和時 > 黒結果時
霊能 > CO 後の結果の開示(既定開示): すべて
人狼 > 霊能騙り > 騙るタイミング(既定開示): 初日に1人
```

- **戦略はすべて読む**(2026-11-01)。真偽の読み方を選ぶ項目は作らない。既定開示に従わなかった人は、その役職の候補から除く(CO がないことからの読みも含む)。
  - 2026-11-01 に、読み方を選ぶ案を2つ検討してやめた。順序付きの「真偽判定」の段と、戦略の項目に [約束](読む)と [想定](枝を作るだけで読まない)を付ける案。どちらも、読まない項目があると、親の勝率と「子の勝率を分岐の確率で平均したもの」がずれる(下の例)。
  - 「黒結果時」がなかったときの勝率と比べたいときは、戦略の on/off を切り替えた Board どうしを比べる。
  - 将来の例(パン屋): 「死亡ログの前日以外の死体は偽」のような、ルールに則った条件は戦略ではない。配役の候補ごとに、公開ログをルールどおりに再現できるかを確かめる基盤の仕事(道連れ・聖職・巫女が重なる場合なども、配役ごとに成り立つかで判断する)。
- **「更新なし」の Board**(ユーザーの案 2026-11-01): 既定開示で更新が起こり得る盤面更新では、「更新の前」の Board から、更新があった Board と、「更新なし」が確定した Board に分かれる。「更新なし」は公開情報なので、役職率が変わってよい。
  - 例: 市民4・霊能1・人狼2 で全員潜伏。1日目に X を処刑し(霊能の処刑前の CO はないものとする)、夜に Y が噛まれた。霊能の CO のタイミングは「黒結果時」。
    - 翌日の更新の前(BoardB): X が狼の確率は 2/7(噛みは X が狼かどうかで確率が変わらないので、処刑の時と同じ)。
    - 霊能が CO した Board(BoardC): 確率 2/7 × 4/5 = 8/35。X は狼で確定。
    - 「更新なし」の Board(BoardE): 確率 27/35。X が狼の確率は 2/27。
    - 子の平均は 8/35 + 27/35 × 2/27 = 2/7 で、BoardB と一致する。BoardE で 2/7 のまま読むと、平均は 22/49 になってずれる(配役の候補を全部数えて確かめた)。
    - 「X が狼なのに霊能が CO しなかった」Board は、BoardE と公開情報が同じなので別に作らない。BoardE の中で、その配役の候補の確率が 0 になるだけ。
  - 更新が起こり得る配役の候補が1つもない盤面更新では、更新の前と「更新なし」の役職率が同じなので、1つの Board にまとめる。Board が増えるのは、黒結果時のように更新が起こり得るときだけ。
- **盤面更新の順番も公開情報**(ユーザー 2026-11-01)。ほかのプレイヤーの開示を確認する前か後かで、情報の意味が変わることがあるため。当分は作り込まないが、将来の拡張の基盤として、Board の公開情報は盤面更新の列(1回の更新に同時の開示をまとめたもの)として持つ。
  - なので、手動更新を1回にまとめるか、2回に分けるかで役職率が変わってよい。公開情報が違うから。
  - CO のタイミングの「時」は、きっかけの直後の盤面更新まで。例えば対抗飽和時なら、対抗が飽和した直後の盤面更新に含まれなければ偽。夜に結果を得たなら、翌日の最初の盤面更新まで。
  - 「前」は直前。例えば処刑前なら、潜伏したまま処刑された人は、その役職の真の候補から外れる。
- **順序付きの絞り込み**: 項目を順序付きで持ち、候補が1人になるまで順に絞り込む。最後は等確率(または最大化)で選ぶ。条件に合う候補がいなければ、その段は飛ばす。例(仮): 「占い位置: 未占い > 未確定の位置 > 潜伏 > 等確率」。多くの項目の既定値をこの形にし、最大化は確かめたいときに切り替える。今の UI にもある(`static/strategy.js` の `ordered`)。

### 騙り

- 騙れる役職(盤面評価): 役職ごとに、騙ってよい役職。「すべて」は人狼 CO・狂人 CO も含む。v1 の既定は、人狼と狂人が「すべて」、村陣営は「なし」。
- 騙るタイミング(既定開示): 騙る役職ごとに持つ。人狼のように情報を共有する役職は人数も指定する。

  ```
  人狼 > 占い騙り > 騙るタイミング: 初日に1人
  人狼 > 霊能騙り > 騙るタイミング: 初日に1人
  狂人 > 占い騙り > 騙るタイミング: なし
  狂人 > 霊能騙り > 騙るタイミング: なし
  ```

  - 「初日に1人」なら、どの人狼が騙るかは等確率。
  - 狂人は人狼を知らないので、人狼と狂人が同じ日に同じ役職を騙ることがある(占い CO が3人になる場合も含む)。
- 初日の CO は、戦略で自動更新せず、ユーザーが手動更新で入れる。騙るタイミングは、2日目以降の自動更新に使う。
- 真の役職の CO のタイミング(v1、2026-11-01): 「対抗飽和時」(その役職の CO の数が配役の数に達したら CO。今の版の「定員到達」)と、占い・霊能の「黒結果時」だけにする。「黒結果時」は、基盤が広げられるかを確かめる用。ユーザーの案には「処刑前」もある。今の版の「対抗が出たら」「X日に CO」「黒を X 人見つけたら CO」は、ひとまず外す。

## 4. 最大化

- 最大化: 行動の候補から、勝率が最大のものを選ぶ。同率の候補は等確率。
- **最大化どうし(v1)**: 例えば狩人の護衛と狼の襲撃が両方とも最大化なら、ナッシュ均衡で決める(確定 2026-10-30)。護衛は村の勝率、襲撃は狼の勝率の最大化を目指す。
  - v1 は陣営が2つのゼロ和なので、ナッシュ均衡は「相手が最善で応じると仮定して、お互いに最善を選ぶ」(ミニマックス)と同じになり、勝率の値は1つに決まる。保証勝率(マックスミン)とも同じ値。
  - 候補を確率で混ぜて選ぶ(混合)ことがある。確率は線形計画で、厳密な分数として求められる。連続護衛ありなら、狼はどこを噛んでも護衛される可能性がある。
  - 均衡の戦略は1つに決まらないことがある(値は1つ)。表示する戦略の選び方を決める必要がある。
  - 狩人は狼を知らず、狼は狩人を知らない。「その人が知っていることが同じ状況」ごとの戦略どうしの均衡になる。解き方の候補: ゲーム全体の均衡(きれいだが重い)/夜ごとの均衡(軽いが、全体の均衡とずれることがある)。
  - 狩人と占い師を同時に最大化にすると、知っていることが違う村の2人が協力する形になり、さらに難しい。v1 で許すかは v1 の範囲で決める。
- **片方だけ最大化**: もう片方は決め打ちの戦略で固定し、最大化する側はそれに対して最善を選ぶ(今の仕組み)。例: 護衛を「噛まれたときに最も勝率が落ちる位置」で決め打ちし、狼が最大化する。決め打ちの護衛が1人に決まると、狼はそこを避ける。
- **公開される行動の最大化**(CO のタイミングなど): 行動が役職率を変え、役職率が勝率を変え、勝率が行動を変える循環がある。v1 ならゲーム全体のナッシュ均衡として定義できるが、ゲーム全体を一度に解く必要があって重い。CO のタイミングの最大化は非推奨にする方向。
- **陣営が3つ以上(v2 以降、未決定)**: ナッシュ均衡は必ず存在するが、複数あって勝率の値も違うことがあり、3人以上では確率が無理数になることもある。対処の候補:
  - 保証勝率(マックスミン): 値は1つで、分数で求められる。相手を悲観的に見積もった値。選択肢の1つとして採用してもよい(ユーザー)。
  - 先に決める側を決める(シュタッケルベルク): 先に決める側は確率を決め、相手はその確率を知って応じる。どちらを先にするかが仮定になる。
  - 均衡の選び方の規則を決める(例: 村の勝率が最大の均衡)。重い。

  v1 の時点で、「最大化どうしをどう解くか」を差し替えられる形にしておく。

## 5. 基盤と保留(v0.7〜v0.8、方針 2026-11-01)

当面は、v1 に広げられる基盤を v0.7〜v0.8 で作る(ユーザー 2026-11-01)。基盤になる要件を先に詰め、枝葉は保留にする。最初は、今の版と同じ狂人抜きの配役で作り直す。

### 基盤(先に詰める)

- Board(公開情報)
- 配役の候補と重み(分数で厳密に)
- 戦略の項目の種類(既定開示・既定行動・盤面評価)と、順序付きの絞り込み
- ベイズの読み(役職率)
- 昼・夜の段: 配役の候補ごとに、確率付きの枝(決着を含む)を返す。戦略の項目は、配役の候補ごとに行動(公開情報を含む)の分布を返し、段はそれを枝にして読む
- 決着判定
- 最大化の解き方を差し替えられる形(4. 最大化)
- Tree

### 保留(枝葉)と差し替え口

何が基盤に関わるかは想定しきれないので、保留にした項目ごとに、どの差し替え口に乗るかを書いておく。どの口にも乗らないものが出たら、基盤の見落としとして見直す。

| 保留にした項目 | 差し替え口 |
|---|---|
| PP の判定([rules.md](rules.md) の「投票と PP」) | 昼の処刑の段 |
| RPP | 昼の処刑の段(同票の処理) |
| 投票・指定・グレラン(v2 以降で設計し直す) | 昼の処刑の段 |
| 村の騙り(PP 防止を含む) | 戦略の項目(既定開示・盤面評価) |
| CO タイミングの整理(騙りをまとめる案) | 戦略の項目と UI |
| 真の役職の CO タイミングの細部 | 戦略の項目(既定開示) |
