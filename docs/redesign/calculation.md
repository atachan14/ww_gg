# 計算の定義(案)

作り直す計算の芯の定義の下書き(2026-10-30 ユーザーと詰めた)。用語は [glossary.md](glossary.md)、ゲームのルールは [rules.md](rules.md)。決めた経緯は [../USER_NOTES.md](../USER_NOTES.md) と Git の履歴にある。「暫定」と書いたものは、実機テストで確かめながら見直す。

## 1. 重み付けの考え方

- 確率は、戦略が決める「起こり得る/起こり得ない」(1 と 0)と、区別する理由のない候補を等確率にすることだけで作る。人の感覚による重み付け(「この人は狂人っぽい」など)は入れない。
  - 確率論の呼び名: 等確率にする考え方は「理由不十分の原則」(無差別の原理)、場合の数で確率を出すのは「古典的確率」(ラプラスの定義)。人の感覚の重みは「主観確率」。
  - 将来は、人の感覚による重み付けもできる厳密計算に広げたい(ユーザー)。
  - 戦略に確率を書く設定(例: 「初日に占いを騙る確率 xx%」)も、分数で厳密に計算できる。将来の応用として足せる。
- 等確率にする単位: 何を等確率とみなすかで答えが変わる。初期値は **COグループ方式**(確定 2026-10-30)。騙れる別役職を持つ役職の位置の組み合わせ(誰が真か)を先に等確率にし、その中で残る配役を等確率にする(`../archive/20261029/co-group-model.md`)。ほかの単位(配役の1つ1つを等確率にする、など)は、余裕ができたらおまけで実装する。

## 2. 役職率

戦略はすべて共有されていて、全員が知っている。役職率は、公開情報と戦略だけで決まる。同じ Board なら、手動更新か自動更新かに関係なく役職率は同じ(ユーザー 2026-10-30)。

### 読むもの(方針 2026-11-02)

1. **ルール**: 配役と GameRule(自噛み、連続護衛など)。配役の候補ごとに、公開ログをルールどおりに再現できるかを確かめる。パン屋の「死亡ログの前日以外の死体は偽」や、黒猫・聖職・巫女が重なる場合も、戦略ではなくここで扱う。
2. **CO可能性**(下の「3. 戦略」): 誰がどの役職を名乗れるか。
3. **約束**(下の「3. 戦略」): その役職の人だけを縛る義務。守らなかった人は、その役職の候補から除く。CO がないことからの読みも含む。
4. **秘密の行動からは何も読まない。** 噛み・護衛・占い先は、ルールの範囲で均等に選んだものとみなして読む。想定(狼の勝率の最大化など)で何を選んでいても、読み方は変えない。「誰を噛んだから誰が狼」のような読みは勝手読みなので入れない(ユーザー 2026-11-02)。
5. **偽の報告は、真と同じ分布で読む。** 白か黒かだけでは、真偽は動かない。

想定(下の「3. 戦略」)は、未来の枝を作ることにだけ使い、役職率には使わない。

- 4 と 5 は、どちらも「見えない選び方からは何も読まない」という考え方。0 と 1 で絞るだけ(起こり得るかだけ)にすると、かえって読みすぎる。
  - 噛みの例(配役の候補を全部数えて確かめた): 市民4・霊能1・人狼2 で全員潜伏。1日目に X を処刑し、夜に Y が噛まれた。

    | 読み方 | X が狼 | 生きている5人の1人あたり |
    |---|---|---|
    | 噛みの前 | 2/7 | 2/7(6人) |
    | 噛み先は均等とみなす | 2/7 | 12/35 |
    | Y が狼でないことで絞るだけ | 1/3 | 1/3 |

    狼は必ず人間を噛むので、Y が人間だったことは当たり前で、ほかの人の手がかりにならない(モンティ・ホール問題で、司会者が必ずヤギの扉を開けるのと同じ)。噛みは「人間が1人減った」だけで、生きている人の狼の数の見込み(12/7)は変わらない。絞るだけにすると、Y を「たまたま人間だと分かった人」として扱ってしまい、X が狼の確率まで上がる。
  - 占いの例: 占い CO が A と B(真率 50%/50%)。A が、内訳「市民2・人狼1」のグループの C を占って「黒」と報告した。

    | 読み方 | A の真率 |
    |---|---|
    | 起こり得るかだけ | 1/4 |
    | 偽は白黒を 1/2 | 2/5 |
    | 偽は真と同じ分布(この例では黒 1/3) | 1/2 |

    「真と同じ分布」は、公開情報から見て「その人が真なら、その対象でその結果が出る確率」で測る。以前、片側にだけ掛けていたために、A の真率が不当に下がる問題があった(2日目に CO した A と、1日目の夜の死体 D が真の候補のとき)。
- 起こり得る候補がなくなったら、盤面が戦略と矛盾していると表示する(未計算と同じく、値で代わりにしない)。

### 「更新なし」の Board(ユーザーの案 2026-11-01)

約束で更新が起こり得る盤面更新では、「更新の前」の Board から、更新があった Board と、「更新なし」が確定した Board に分かれる。「更新なし」は公開情報なので、役職率が変わってよい。

- 例: 上の噛みの例の翌日。霊能の約束は「CO: 黒取得直後」、噛みの想定は均等(処刑前の CO はないものとする)。
  - 翌日の更新の前(BoardB): X が狼の確率は 2/7。
  - 霊能が CO した Board(BoardC): 確率 2/7 × 4/5 = 8/35。X は狼で確定。
  - 「更新なし」の Board(BoardE): 確率 27/35。X が狼の確率は 2/27。
  - 子の平均は 8/35 + 27/35 × 2/27 = 2/7 で、BoardB と一致する。BoardE で 2/7 のまま読むと、平均は 22/49 になってずれる(配役の候補を全部数えて確かめた)。
  - 「X が狼なのに霊能が CO しなかった」Board は、BoardE と公開情報が同じなので別に作らない。BoardE の中で、その配役の候補の確率が 0 になるだけ。
- 約束で更新が起こり得る配役の候補が1つもない盤面更新では、更新の前と「更新なし」の役職率が同じなので、1つの Board にまとめる。
- 想定だけで起こる更新(結果開示の「取得直後にすべて」など)は、どの配役の候補でも同じように起こるので、「更新なし」は自動では起こらない(手動でだけ作る)。

### 盤面更新の順番も公開情報(ユーザー 2026-11-01)

ほかのプレイヤーの開示を確認する前か後かで、情報の意味が変わることがあるため。当分は作り込まないが、将来の拡張の基盤として、Board の公開情報は盤面更新の列(1回の更新に同時の開示をまとめたもの)として持つ。手動更新を1回にまとめるか、2回に分けるかで役職率が変わってよい(公開情報が違うから)。

### Tree の親子

- 手動更新で作った子の Board は、分岐の確率 0% の新しい Board として扱う。親の勝率は、自動更新の枝だけから作る(ユーザーの記憶。今の実装と合っているかは未確認)。
- 秘密の行動の想定が「均等」なら、親の勝率は「子の勝率を分岐の確率で平均したもの」と一致する。
- 秘密の行動の想定が均等でないとき(既定の「噛み位置: 狼の勝率が最大」など)は、その分だけずれる。仕様として受け入れる。役職率は「秘密の行動から何も読まない読み手」の値で、未来は想定どおりに進むと見込んだもの、という意味になる。
  - Board の勝率は、配役の候補ごとに「その Board の役職率 × 想定で未来を進めた結末」を足したもの。未来の村の判断(処刑先など)には、その先の Board の役職率を使う。
- 公開の行動では、ずれは起こらない。秘密の情報を条件にした公開の行動は約束にしか置けず、約束は読むから。
- 今の結果(7人のケースの 89/224 など)と値が変わってよい(ユーザー 2026-10-30)。

### 検討してやめた案(2026-11-01〜02)

- 順序付きの「真偽判定」の段で読み方を選ぶ案。
- 戦略をすべて読む案(ベイズ)。手動で想定から外れると、偽や矛盾になる。噛み考察が入る。
- [想定] を読まない案で、公開の行動の想定に秘密の情報の条件(黒取得直後)を置けるもの。BoardE のずれ(22/49)が出る。
- 想定も読み、想定で起こり得ない盤面なら項目ごとに約束に戻る案。説明しづらい。
- 手動で作った盤面(実盤面)は約束だけ、自動で作った盤面(想定盤面)は想定で読む案。同じ公開情報なのに数字が変わるのがわかりづらい。

## 3. 戦略

- 戦略は Board ごとに持ち、すべて共有。個人戦略という概念はない(確定 2026-10-30)。
- 各役職は、その人が知っていることだけで行動を決める(今の人狼の襲撃と同じ)。

### 構成(方針 2026-11-02)

戦略は、CO可能性の表と、約束と想定でできている。2026-10-30 の「既定開示・既定行動・盤面評価」の3種類は、これに置き換えた(既定開示と既定行動は想定、盤面評価は CO可能性と約束にあたる)。

| 部分 | 何を決めるか | 役職率 | 自動更新の枝 |
|---|---|---|---|
| CO可能性 | 誰がどの役職を名乗れるか(範囲だけ) | 読む(反すると矛盾) | — |
| 約束 | その役職の人だけを縛る義務(CO、結果開示) | 読む(守らなかった人は、その役職ではない) | 作る(想定が継承する) |
| 想定 | 全員がこう動くと見込む行動 | 読まない | 作る |

```
CO可能性: 狼陣営 すべて / 村陣営 なし
占い
  約束 > CO: 対抗飽和直後 | 黒取得直後
  約束 > 結果開示: 黒取得直後に黒対象と黒結果
  想定 > CO: (約束の継承)
  想定 > 結果開示: (約束の継承) | 取得直後にすべて
  想定 > 占い位置: 未確定 > 未占い > 潜伏 > 片白 > 均等化
人狼
  想定 > 噛み位置: 狼の勝率が最大 > 均等化
```

- **CO可能性**: 1枚の表(行が名乗る側、列が名乗る役職)で持つ。条件(「PP 時」など)は表に書かず、約束や想定の CO に書く。v1 は村陣営が「なし」なのが普通なので、普段は「狼陣営: すべて / 村陣営: なし」の1行だけを見せ、表は開いたときだけ出す。「騙れる役職」(2026-10-30)を言い換えた。
- **約束**: その役職の人だけを縛る、最低限の義務。偽は守らなくてよい。
  - 秘密の情報を条件にした公開の行動(黒取得直後の CO・結果開示)は、約束にしか置けない。
  - 狼の騙りの義務(例: 初日に1人)も約束になる。v1 の既定は「なし」。初日の CO はユーザーが手動更新で入れる。義務にすると、初日の CO に人狼が1人ずついることが確定する。
  - 約束にないタイミングの CO は自由。自動更新では作らず、手動でだけ入る。読むときは CO可能性の範囲かだけを見る。
- **想定**: 全員がこう動くと見込む行動。約束を継承する(自動の枝は約束を破らない)。
  - 公開の行動の想定には、公開の情報を条件にしたもの(CO 時、取得直後)だけを置ける。真も偽も同じように行うので、読まなくても役職率は変わらない。
  - 秘密の行動(占い位置、護衛位置、噛み位置、偽の報告の仕方)は、想定で枝を作る。役職率には、上の「何も読まない」読み方を使う。
- 利用者向けの説明: 「約束 = 真ならその役職が必ずすること(しなければ偽)」「想定 = 誰がやっても同じこと、未来を作るための見込み(しなくても偽にならない)」。UI では、約束にしか置けない選択肢を想定の欄に出さない。

### タイミングの言葉(2026-11-01〜02)

- **時**: 同じ盤面更新の中。例: 結果開示「CO時にすべて」。
- **直後**: きっかけの次の盤面更新まで。例えば対抗飽和直後なら、対抗が飽和した次の盤面更新に含まれなければ偽。夜に結果を得たなら、翌日の最初の盤面更新まで。
- **前**: 直前。処刑前なら、潜伏したまま処刑された人は真の候補から外れる。v1 では使わない(下)。
- 結果開示は CO を前提とするので、「取得直後にすべて」に CO より前の結果は含めない。

### 真の役職の CO と結果開示(v1、2026-11-01〜02)

- CO の約束は「対抗飽和直後」(その役職の CO の数が配役の数に達したら。今の版の「定員到達」)と、占い・霊能の「黒取得直後」。「黒取得直後」は、基盤が広げられるかを確かめる用。今の版の「対抗が出たら」「X日に CO」「黒を X 人見つけたら CO」は、ひとまず外す。
- 結果開示の約束は「黒取得直後に黒対象と黒結果」。開示がなければ、約束によって、CO している生存者の誰も黒を取っていない(白)ことが確定する。占い先や結果を伏せても偽にはならない。
- 昼の最初の Board は期限内なので、黒を取った候補も白を取った候補も含む。次の盤面更新で「更新なし」なら、黒を取った人はいないと確定する。
- 「処刑前」は v2 以降(ユーザー 2026-11-02)。暫定の処刑先を決めてから CO・結果開示を確かめる進行(昼開始 → 盤面更新 → 指定 → 盤面更新 → 回避ならやり直し)が要り、v1 の配役では大事でないため。v1 の昼は、昼開始 → 盤面更新を義務がなくなるまで繰り返す(ある更新が次の更新の義務を生むことがある)→「更新なし」で閉じる → 処刑。
- 名前(2026-11-02): 画面は「結果開示」、コードは `disclosure`(今のコードと同じ)。略語(RD など)は作らない。「結果」だけだと、結果の取得と紛らわしい。

### 順序付きの絞り込み

項目を順序付きで持ち、候補が1人になるまで順に絞り込む。段ごとに、対象が0人ならその段は飛ばし、1人なら確定、2人以上ならそこまで絞って次へ。最後は等確率(または最大化)で選ぶ。多くの項目の既定値をこの形にし、最大化は確かめたいときに切り替える。今の UI にもある(`static/strategy.js` の `ordered`)。

### 騙り

- 狂人は人狼を知らないので、人狼と狂人が同じ日に同じ役職を騙ることがある(占い CO が3人になる場合も含む)。
- どの人狼が騙るかは等確率。

## 4. 最大化

- 最大化: 行動の候補から、勝率が最大のものを選ぶ。同率の候補は等確率。v1 では、当面は最大化なしで進める(既定値は順序付きの絞り込み)。

### 最大化できる項目(2026-11-02)

- **秘密の行動(占い・護衛・噛み)と、処刑だけ。**
- **約束は最大化しない。** 約束は「真なら必ずすること」で、勝率を見て選ぶものではない。
  - CO のタイミングの最大化(将来やりたい、ユーザー 2026-11-02)は、v1 ではやらない。潜伏している人の CO は約束なので、「公開盤面で CO したほうが村の勝率が高いなら CO する」という約束なら書ける。ただ、約束は読むので、CO しなかった Board の役職率が「CO が得だった配役の候補」を除いて決まり、CO が得かどうかはその役職率から出した勝率で決まる、という循環が起きる。釣り合う点を探す必要があって重い。v2 以降で考える。
- **公開の行動の想定**(結果開示など)は、将来「公開盤面での村の勝率の最大化」までなら置ける。公開の情報だけで決まるので、真でも偽でも同じ行動になり、読まなくてもずれない(偽は真を演じる、という仮定。偽の報告を真と同じ分布で読むのと同じ考え方)。その人の秘密の情報を使う最大化は、真と偽で行動が分かれるので置けない。

### 順番の最大化と、同時の最大化

- **順番**(昼の処刑 → 夜の噛みなど): 後ろから解く(ミニマックス)。均衡は要らない。
- **同時**(同じ夜の護衛と噛み、占いと噛みなど): ナッシュ均衡で決める(確定 2026-10-30)。護衛は村の勝率、襲撃は狼の勝率の最大化を目指す。
  - v1 は陣営が2つのゼロ和なので、ナッシュ均衡は「相手が最善で応じると仮定して、お互いに最善を選ぶ」(ミニマックス)と同じになり、勝率の値は1つに決まる。保証勝率(マックスミン)とも同じ値。
  - 候補を確率で混ぜて選ぶ(混合)ことがある。確率は線形計画で、厳密な分数として求められる。連続護衛ありなら、狼はどこを噛んでも護衛される可能性がある。
  - 均衡の戦略は1つに決まらないことがある(値は1つ)。表示する戦略の選び方を決める必要がある。
  - 狩人は狼を知らず、狼は狩人を知らない。「その人が知っていることが同じ状況」ごとの戦略どうしの均衡になる。

### Board ごとに解く(2026-11-02)

- 各 Board の最大化は、**その Board の勝率**(その Board の役職率で出したもの)を最大にする。後ろの Board から順に解き、前の Board は、後ろの Board の均衡で進んだ結末を使う。
  - 連ガなしのように、前の夜の秘密の行動が次の夜に効く場合も同じ。前の夜の護衛先は、役職率の上では「ルールの範囲で均等」として扱う。
- **ゲーム全体の均衡は使わない。** ゲーム全体で解くと、後ろの夜の判断に、前の夜の戦略で実際に進んだ確率が効く。これは秘密の行動から読むこと(噛み考察・護衛考察)と同じなので、方針(「秘密の行動からは何も読まない」)と合わない。
  - 例(配役の候補を全部数えて確かめた): 市民3・狩人1・人狼1 の5人、1日目の夜、狼は均等に噛み、狩人の想定は「プレイヤー1 を守る(自分ならほかを均等に)」。平和な朝になったとき、プレイヤー1 が狼の確率は、Board の役職率では 1/5、想定で実際に進んだ確率では 0(噛まれて守られたのはほぼプレイヤー1 なので)。ゲーム全体で解くと後者を使うことになる。
- Board ごとに解くので、軽い。値の意味は「各 Board で決まった読み方をする村と狼」のモデルでの均衡で、噛みから推理する本当に賢い村の均衡とは違う。
- 狩人と占い師を同時に最大化すると、知っていることが違う村の2人が協力する形になり、さらに難しい。v1 で許すかは v1 の範囲で決める。
- **公開盤面の判断**(処刑など)は、公開の役職率で最大化する(今の処刑先の計算と同じ)。

### 陣営が3つ以上(v2 以降、未決定)

ナッシュ均衡は必ず存在するが、複数あって勝率の値も違うことがあり、3人以上では確率が無理数になることもある。対処の候補:

- 保証勝率(マックスミン): 値は1つで、分数で求められる。相手を悲観的に見積もった値。選択肢の1つとして採用してもよい(ユーザー)。
- 先に決める側を決める(シュタッケルベルク): 先に決める側は確率を決め、相手はその確率を知って応じる。どちらを先にするかが仮定になる。
- 均衡の選び方の規則を決める(例: 村の勝率が最大の均衡)。重い。

v1 の時点で、「最大化どうしをどう解くか」を差し替えられる形にしておく。

## 5. 基盤と保留(v0.7〜v0.8、方針 2026-11-01)

当面は、v1 に広げられる基盤を v0.7〜v0.8 で作る(ユーザー 2026-11-01)。基盤になる要件を先に詰め、枝葉は保留にする。最初は、今の版と同じ狂人抜きの配役で作り直す。v0.7・v0.8 で作る範囲は [scope.md](scope.md)。

### 基盤(先に詰める)

- Board(公開情報)
- 配役の候補と重み(分数で厳密に)

- 最大化の解き方を差し替えられる形(4. 最大化)
- Tree
