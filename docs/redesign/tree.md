# 盤面の編集と Tree(案)

作り直す盤面の編集と GameTree の要件の下書き(2026-11-02 ユーザーと詰めた)。用語は [glossary.md](glossary.md)、計算は [calculation.md](calculation.md)。今の版の仕様は `docs/spec/screens.md` と、Help の「BoardLogと保存」(`templates/help_specs.html`)。

## どの Board も、それだけで計算できる

- 役職率は、その Board の公開情報と戦略だけで決まる(手動更新か自動更新かに関係しない)。勝率は、その Board の役職率と、その先の結末で決まる([calculation.md](calculation.md) の「2. 役職率」「4. 最大化」)。
- 過去の秘密(狼が前に噛んだ相手、狩人の前の護衛先、潜伏している占い師の結果など)は、秘密の行動からは何も読まない方針なので、公開情報と矛盾しない範囲で均等に起こったものとして扱う。
- なので、途中の盤面を手で編集しても、どうやってそこに来たかに関係なく計算できる。2026-10-30 の全体レビュー([../design-review-20261030.md](../design-review-20261030.md))の質問3の「(c) 任意の盤面を、独立した出発点として計算する」が、そのまま成り立つ。今のコードで繰り返し問題になっていた「過去の他人の秘密が盤面だけでは決まらない」は、ここで解ける。

## 決めたこと(2026-11-02)

| 項目 | 決めたこと |
|---|---|
| 手動更新の置き場所 | 過去の盤面を手動で編集したら、元の枝とその先は残し、新しい枝を**兄弟**として足す。今の版の「確定した変更は子孫を退役させる」から変える。Tree で比べやすくするため |
| 行動の候補の枝 | 今の版の表示のまま(手動更新の枝は分岐の確率 0% として表示する、など) |
| 盤面更新の列 | 今の版の表示のまま(Phase の列と、盤面更新の列)。「更新の前」と「更新なし」の Board も、この列に並ぶ |
| 戦略の変更 | 手動更新として扱う(新しい Board になる)。BoardLog にも残す。子の Board は戦略を引き継ぐ |
| Tree の展開 | 表示は、開いたところだけ出す。勝率に必要な計算は別に行う |
| 履歴の保存 | ブラウザ内(IndexedDB)だけに保存し、サーバーには保存しない(v0.6 の Preview と同じ)。下の理由 |
| 視点の表示 | v0.7・v0.8 では対応しない。v1 で出すかは保留 |

- 行動の候補の枝と盤面更新の列の細かい表示は、実装するときに今の Tree を確かめて書き起こす。
- v0.8 の `/core` の Tree は、左から右に子を並べる簡単な形。Phase の列をそろえる今の版の表示は、まだ持ち込んでいない。手動更新は Current の子として足す(過去の Board を Current にして足せば、元の枝の兄弟になる)。子の勝率は、その Board を開いたときに計算する。
- 履歴をブラウザ内だけにする理由(ユーザーが「おすすめで」と任せた):
  - Vercel の関数は状態を持たないので、サーバーに保存するにはデータベースが要り、費用と運用が増える。
  - 盤面はユーザー個人の検討なので、サーバーに置かないほうが扱いが簡単。
  - v0.6 の Preview で、ブラウザ内の保存は動いている(`archive/20261029/browser-history-prototype-2026-10-27.md`)。
  - 別の端末に移す、人に見せる、などが必要になったら、ファイルへの書き出しと読み込みを足す。
- 視点の表示を保留にしても、基盤は変わらない。狼の噛みや狩人の護衛を決めるのに、「その人が知っていることが同じ状況」ごとの状態は元々使う。視点の表示は、それを画面に出すかどうか。
