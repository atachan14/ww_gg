# モデルA構造整理と対応範囲の再監査

## 整理した境界

1. 夜の対象固定・取得・死亡・朝への遷移は`action_flow`と明示的policy。公開観測更新と対象固定行の条件付けを分離し、後者は生存狼数ごとの従来事前比率を維持する。
2. 朝の報告生成・枝統合・継続評価は共通flow。今回、random/max同率報告の同一公開ベクトル統合を`merge_report_outcomes`へ集約した。最初の枝の狼数確定値を再利用せず、統合後の分布から推定する。混合狼数回帰を追加。
3. 取得は`acquire_laws`、私的報告の尤度移送は`observer_report_weights`。公開分布・実際の枝重み・閲覧者の条件付き分布は別物として保持する。
4. 公開モデルA facadeがOverview/Table/今日中/累積の継続値を返す。独立した初期配役比較もAへ接続し、そこで明示されている占い能力なしの範囲をStrategyで指定する。旧計算器へのフォールバックなし。
5. 共通の公開取得履歴を`public_observed_prior`、分布射影を`belief_projection`へ分離。Aの本番経路は旧占い評価器からこれらをimportしない。公開snapshot/prior cacheは公開情報のみ。viewer/秘密はrequest内のpayoff側に置く。完全値だけcacheしPendingを保存しない。
6. 呼出監査により、主画面・私的視点・初期配役比較から旧評価ループの呼出を除いた。旧exact/reports/占い/狼評価器は移行前の独立fixtureと参照テストに利用されるため保持する。共通Board・報告生成関数も同じファイルにあり、ファイル丸ごとの削除はしない。使用中の参照exportを「未使用」として削除しない。

追加能力のため、死亡前取得・死亡resolver・観測更新・朝公開・情報所有者・キャッシュ依存の接続箇所は既存の`information-ownership-cache-and-extension.md`に整理済み。現在の圧縮は能力なし狩人・潜伏役が未来に影響しない範囲専用で、生存占いCO/allには適用しない。狩人/GJ追加時は高速経路の条件を再審査する。

## 性能範囲と残り

`benchmark_model_a.py`と`model-a-root-benchmark.json`に、旧v0.4相当の9人10配役/CO/戦略を**占い能力なしと明示して**比較した結果を保存。全10ケースで完全な9行と今日中値が既定250000work/20秒内に返り、0.145〜10.489秒。root snapshotの測定であり全履歴・全設定の一般性能保証ではない。新しい占い全公開を省略する隠れた高速化ではない。

追加した7人・狼2/霊媒2/占い1・占いCO1/霊媒CO2・将来allは7.902秒でwork予算超過、数値/行は返さずPending。この既存入力を扱う混合能力の性能改善が次の優先開発要件。最適化は非圧縮Aとの一致、公開同率処理、秘密非漏洩を先に検証する。予算を上げるだけ、旧モデルへ戻す、能力結果を省略して数値を見せる代用は採用しない。

未実装の狩人能力、潜伏/none占い本人の将来能力比較、複数偽占いの共同法則、役騙り/結果騙り/ギドラは引き続き未対応として明示する。これらを今回の構造整理の完了扱いにはしない。
