# 物理分岐・情報集合の段階的整理

開始基準: HELP実装 `83de806`、構造監査 `97d0ed4`、計算実装 `eb8116d`。
ユーザー承認に基づく構造整理。model Aの公開更新、情報集合内の政策、未知の途中履歴の扱いは維持する。

## 第一段階: 物理Boardの明示的な継承

共通フローの位置引数payloadを `ActionInputs` / `ContinuationInputs` として名前付けした。
元のタプル入力を受ける共通処理との互換性は残し、公開状態と物理Boardを明示して運ぶ。
`InformationSetActionPolicy.project` は `outcome.board` を継続データへ保存し、
昼・朝の評価はそのBoardを `solve(..., physical=...)` へ渡す。

`physical_board` は入口でだけ公開Boardを土台に初期化できる。継続に物理Boardがあれば
その枝を土台にし、役職質量は本人の分岐測度から更新する。生存者・日・昼夜・死亡履歴が
公開観測と食い違う場合はエラーとし、公開盤面で置き換えて辻褄を合わせない。
公開されたCO・報告等の事実は枝へ反映する。既存のsolver用役職縮約はこの段階では維持。
狩人登録範囲は既存どおりその縮約を迂回する。

GJの物理成功Boardも、公開信念を土台にせず、入力された物理Boardと生成した本人記録から作る。
既存キャッシュは公開事実と本人の仮説測度をキーに持つ。新しい物理入力も同じ公開事実点で
あることを検証するため、この段階で別の不可視事実を同じキーへ紛れ込ませない。

検証: 公開の狩人候補が残るGJと物理成功世界を分離、複数夜の両本人記録、
次solverへの物理Boardの同一オブジェクト受渡し、キャッシュ有無の一致、
事実が食い違う入力の拒否。既存の候補採点はmodel Aの公開側から始める経路を維持している。
公開候補採点をすべて根からの物理分岐へ置き換えたという主張ではない。

## 続く段階

1. 狼の初期仲間と本人記録から情報集合を抽出し、集約・条件付けの重複を共通化する。
2. 最終評価と当日終了評価、各視点が同じ共通フローを使い、生成記録を捨てないようにする。
3. 役職縮約・キャッシュと、評価のための主観的な候補分岐／実際の継続を整理する。

途中Boardだけから未知の他者履歴を配分する新しい基準モデルは実装しない。
根から持つ物理情報と、公開方針の採点に使う主観分布を混同しない。
