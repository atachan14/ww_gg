## Why the dependency cut is exact

All accepted future selectors are already fixed. Execution is uniform over the
alive roster. The wolf's legal uniform set uses only its own initial roster.
The guardian's uniform set uses its own role and immediately preceding action,
with GameRules controlling repeat permission. No selector reads a latent scan
result or an inactive medium result. Those unobserved scan chance kernels sum
to one in every physical world, including scans before the seer's death.

Consequently expectation is linear in the original P measure. The code backs up
fixed legal choices through physical_hypothesis_outcomes, which uses the SAME
exact action and guarded-night resolver as the unshortened flow. There is no
per-world optimization. S/M masks remain in physical inputs; only scalar cache
equality can ignore their inactive labels. Cache keys keep full wolf/hunter
masks, alive roster, phase, rules, strategy and the relevant previous guard.
No-repeat source history must be ready in every public world. Completed values
alone enter the bounded cache. All source and private records remain available.

The controlled seer table validates its OWN known history and legal candidates
first. Only in this same fixed/no-report scope is the calculated continuation
value invariant to a new unread scan. Other policies keep the complete controlled
scan observer path. This does not create an optimal CO/report policy.
