入力から再帰まで

  1. app.replay → prepare_public_prior：公開入力から役職と公開取得記録を準備。
  2. condition_private：私有視点だけの追加条件。
  3. score_day_targets / wolf_policy：公開の処刑方針、狼情報集合別の襲撃方針。
  4. resolve_action：夜の能力取得を死亡前に行う。
  5. guarded_outcomes：均等護衛、襲撃との一致、両者の記録、物理枝の質量。
  6. project / morning_value / solve：公開更新と本人測度を運び、勝者判定・朝・次の昼夜へ。

公開sの再投入箇所

scalar(b, s, past)          → solve(..., private=s)
score_day_targets(...)     → act(..., private=s)
wolf_policy(...)           → group = condition(s, wolf_mask, history)
uncached_act(..., private) → physical = replace_worlds(b, private.public_roles)

実際の枝のGuardContext.privateは再帰へ残ります。一方、公開候補の仮想採点は公開sから分岐を作り直す経路です。この二つを混同しないでください。

キャッシュとPending

政策キーは公開状態・狼マスク・履歴、値のキーには本人分布と観測者も含みます。random襲撃のスカラーキーでは無関係な履歴を周辺化できますが、記録本体は保持します。予算超過や未対応を0%として保存しません。
